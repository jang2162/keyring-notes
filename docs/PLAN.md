# Obsidian·SiYuan 대체 노트 앱 개발 계획서

Oct 5, 2026 · @병현

노트 앱과 그 운영·관리 환경을 하나의 서비스로 처음부터 만든다. 마크다운 파일을 원본으로 셀프호스팅 서버에 두고, 사람은 웹에서 위젯과 함께 편집하며, 에이전트는 토픽별 권한 토큰으로만 접근한다.

## 배경

두 앱 모두 요구사항의 일부만 채우고, 핵심인 에이전트 권한은 둘 다 플러그인에 기대야 한다.

| 요구사항 | Obsidian | SiYuan |
| --- | --- | --- |
| 마크다운 원본 | 순수 .md 파일 | 내부는 블록 JSON, 마크다운은 가져오기·내보내기 |
| 문서 내 위젯 | 플러그인(Dataview, Bases 등) | 기본 지원 |
| 셀프호스팅·원격 원본 관리 | 서버 개념 없음, Sync나 Git으로 보완 | Docker 서버 가능 |
| 토픽별 에이전트 권한 | 없음, OS 레벨에서 직접 구성 | 커뮤니티 플러그인(Sisyphus) 계층 |

그래서 기존 앱에 기대지 않고, 노트 앱과 이를 설치·운영·관리하는 환경까지 한 서비스로 처음부터 설계한다.

## 목표와 범위

1인 사용자를 위한 개인용 앱으로 시작하고, MVP는 "Obsidian·SiYuan을 끄고 이것만 써도 되는가"를 기준으로 자른다. LLM Wiki(원본 자료 → 에이전트가 관리하는 위키 → 스키마) 운영을 기본 사용 방식으로 지원한다.

**MVP에 포함**

- 서버에 저장된 마크다운 파일을 웹에서 열람·편집
- 위키링크, 백링크, 전체 검색
- 기본 위젯 3종: 쿼리 목록, 할 일, 표·차트
- 토픽별 에이전트 토큰과 MCP 서버
- 폴더 단위 권한과 추가 전용(append-only) 권한
- 원본 자료 수집: 파일 업로드, 웹 클리퍼, 마크다운 변환
- 여러 문서를 한 커밋으로 묶는 일괄 쓰기
- index·log 자동 생성
- 변경 이력과 롤백
- 관리 콘솔: 설치·업데이트, 에이전트 토큰과 토픽 권한, 백업·복원, 서버 상태
- Obsidian 볼트 가져오기

**MVP 이후**

- 에이전트 변경 검토 대기열 (diff 확인 후 승인)
- 출처 연결: 위키 페이지 ↔ 원본 자료 양방향 링크
- 구조적 정리(lint) 도구와 정기 작업 스케줄러, 새 원본 이벤트 알림
- 그래프 뷰
- 임베딩 기반 의미 검색
- 모바일 최적화와 오프라인 편집
- SiYuan 데이터 가져오기 도구
- 위젯 플러그인 API
- 다중 사용자, 실시간 공동 편집

**범위 밖**

- 퍼블리시·웹 공개 기능

## 아키텍처

웹 앱과 에이전트는 입구만 다르고, 같은 권한 미들웨어를 거쳐 같은 원본에 닿는다.

```
 [웹 앱 (사람)]          [에이전트 (MCP 클라이언트)]
        │ 로그인 세션              │ 에이전트 토큰
        ▼                          ▼
 ┌──────────────── API 계층: REST · MCP ────────────────┐
 └──────────────────────────┬───────────────────────────┘
                            ▼
 ┌──────── 권한 미들웨어: 토큰 × 폴더, 이력 기록 ────────┐
 └──────────────────────────┬───────────────────────────┘
                            ▼
 ┌──── 저장소: 마크다운 파일 · Git 이력 · SQLite 인덱스 ──┐
 └──────────────────────────────────────────────────────┘
```

권한 검사를 한 계층에 모아서, 에이전트가 파일이나 인덱스에 직접 닿는 경로를 없앤다. 권한을 건너뛰는 별도 도구도 두지 않는다.

## 데이터·권한 모델

토픽은 최상위 폴더이고, 권한은 "토큰 × 폴더" 표 하나로 정의한다. LLM Wiki로 쓰는 토픽은 원본·위키·스키마 세 층으로 나눈다. 파일은 다른 에디터에서 열어도 그대로 읽히는 마크다운을 유지한다.

**저장 구조**

- `vault/<토픽>/raw/`: 원본 자료. 수집한 PDF·이미지 원본과 그 마크다운 변환본. 에이전트는 추가만 할 수 있다.
- `vault/<토픽>/wiki/`: 에이전트가 관리하는 위키 페이지. `index.md`와 `log.md`는 서버가 자동 생성한다.
- `vault/<토픽>/SCHEMA.md`: 위키 구조와 작업 규칙(수집·질의·정리 절차). 사람만 수정한다.
- 일반 노트 토픽은 세 층 구분 없이 써도 된다.
- `vault/.history/`: Git 저장소. 커밋마다 작성자를 기록해 이력과 롤백에 쓴다.
- `index.db`: SQLite 인덱스(검색, 백링크, 위젯 쿼리용). 언제든 파일에서 다시 만들 수 있는 캐시다.

**위젯 문법**

위젯은 `widget` 언어 이름을 붙인 코드 블록으로 쓴다. 이 앱에서는 위젯으로 그려지고, 다른 에디터에서는 평범한 코드 블록으로 보여 파일이 깨지지 않는다. 블록 안 내용 예시:

```yaml
type: query
from: 업무/프로젝트A
where: status != done
show: [title, due]
sort: due
```

**폴더별 에이전트 권한 (예시)**

| 토큰 | 업무/raw | 업무/wiki | 업무/SCHEMA.md | 에이전트 작업함 | 개인·재무 |
| --- | --- | --- | --- | --- | --- |
| wiki-work (위키 관리) | 추가만 | 쓰기·삭제 | 읽기 | 숨김 | 숨김 |
| openclaw-work (업무 보조) | 읽기 | 읽기 | 읽기 | 쓰기·삭제 | 숨김 |
| openclaw-personal | 숨김 | 숨김 | 숨김 | 쓰기·삭제 | 숨김 |

같은 문서에 여러 규칙이 걸리면 가장 구체적인 경로의 권한을 적용한다.

숨김 토픽은 목록·검색·백링크 결과에서도 빠진다. 에이전트가 숨김 문서를 링크한 문서를 읽어도 링크 대상의 제목과 내용은 돌려주지 않는다.

## 기술 스택 (초안)

서버와 웹을 TypeScript 하나로 맞춰 1인 개발 부담을 줄인다. 확정 전 1단계 프로토타입에서 검증한다.

| 영역 | 후보 | 선택 이유 |
| --- | --- | --- |
| 서버 | Node.js 또는 Bun + Hono | 가볍고, 웹과 같은 언어 |
| 저장·이력 | 파일 시스템 + Git (isomorphic-git 또는 git CLI) | 원본이 파일이라 백업·이전이 단순 |
| 인덱스 | SQLite + FTS5 | 서버 하나로 충분, 한국어 검색은 토크나이저 검증 필요 |
| 에이전트 연동 | MCP TypeScript SDK | OpenClaw 등 MCP 클라이언트와 바로 연결 |
| 웹 에디터 | CodeMirror 6 (원문 편집 + 실시간 미리보기) | 마크다운 원문이 그대로 보존됨 |
| 위젯 렌더링 | React 또는 Svelte 컴포넌트 | 위젯 타입별 컴포넌트로 확장 |
| 인증 | 사용자 로그인(패스키 또는 비밀번호) + 에이전트별 API 토큰 | 사람과 에이전트를 분리 |
| 배포 | Docker Compose, VPN(Tailscale 등) 또는 리버스 프록시 + HTTPS | 앞 계획서의 서버 구성 재사용 |

1단계에서 고른 것: Node.js 22 + Hono, git CLI(`--git-dir vault/.history`), CodeMirror 6, React, markdown-it + DOMPurify.

### 1단계 메모

- 해시 기반 충돌 감지(F8), 작성자 기록, 문서 단위 롤백(F7)은 웹 편집에도 바로 필요해서 1단계에 넣었다. 웹 에디터는 충돌 시 덮어쓰지 않고 "사본으로 저장 / 서버 버전 불러오기"만 제공한다.
- 아직 인증이 없어 모든 웹 변경은 `KEYRING_AUTHOR_NAME` 작성자로 기록되고, 서버는 기본적으로 `127.0.0.1`에만 바인드한다.
- 미리보기는 위키링크(`[[문서#제목|별칭]]`)와 이미지 임베드(`![[img.png|300]]`)를 Obsidian의 최단 경로 규칙으로 해석한다. `widget` 코드 블록은 자리 표시만 하고 3단계에서 렌더링한다.
- 점으로 시작하는 폴더(`.obsidian`, `.history` 등)는 API에서 접근할 수 없고, 볼트 밖을 가리키는 심볼릭 링크는 따라가지 않는다.

### 2단계 메모

- 권한 계층은 `ScopedVault` 하나다. REST와 MCP 모두 이것만 거치며, 파일·이력에 직접 닿는 다른 경로는 없다.
- 권한 단계: 숨김 < 읽기 < 추가만 < 쓰기 < 삭제. 계획서 표의 "쓰기·삭제"는 `delete`로 준다. 규칙이 없는 경로는 숨김.
- 추가 전용(`append`)은 "새 문서 만들기"와 "기존 내용 뒤에 붙이기"만 허용한다. 전체 쓰기라도 새 내용이 기존 내용으로 시작하면 덧붙이기로 본다. 이동은 원래 위치에 `delete`가 필요하다.
- 숨김 경로에 대한 읽기는 "없는 문서"와 같은 404, 쓰기는 존재 여부와 상관없이 같은 403을 낸다. 충돌(409) 응답으로 존재가 드러나지 않도록 권한을 먼저 검사한다. 개요의 링크 해석은 보이는 문서 안에서만 하며, 이동 커밋 메시지에 숨김 경로가 있으면 가린다.
- 일괄 쓰기는 가상의 상태 위에서 모든 연산의 권한·충돌을 먼저 검사하고, 통과해야 디스크에 쓴다. 쓰기·커밋 중 오류가 나면 원래 바이트로 되돌리고 스테이징도 비운다.
- 에이전트만 있으면 권한이 의미가 없어서(토큰 없이 사람인 척 접근 가능) 소유자 로그인(F9 일부)을 앞당겼다. 비밀번호는 scrypt, 세션은 HMAC 서명 쿠키(HttpOnly, SameSite=Strict, 30일), 비밀번호를 바꾸면 모든 세션이 끊긴다. 패스키는 이후.
- 토큰·권한은 관리 콘솔(5단계) 전까지 CLI(`npm run keyring -- agent ...`)로 관리한다. 설정 파일은 볼트 밖에 두어 Git 이력에 섞이지 않게 했다.
- 검색은 아직 파일 전체를 훑는 단순 구현이다. 3단계에서 SQLite FTS로 바꿔도 권한 필터는 `ScopedVault`에 남긴다.

### 3단계 메모

- 인덱스는 Node 내장 `node:sqlite`(SQLite 3.50)를 써서 네이티브 빌드 의존성을 없앴다. 볼트의 `.keyring/index.db`에 두고 Git에서는 뺀다. 시작할 때 mtime·크기가 바뀐 파일만 다시 읽고, 서버를 통한 변경은 커밋 직후(다음 쓰기보다 먼저) 반영한다.
- **한국어 검색 토크나이저 검증 결과**: FTS5 `unicode61`은 "기준금리를"을 한 덩어리로 보아 "금리"로 찾지 못한다. `trigram` 토크나이저는 조사가 붙어도 부분 일치로 찾지만 3글자 미만은 찾지 못한다. 그래서 3글자 이상은 FTS(trigram, bm25 순위), 1~2글자는 LIKE로 거르는 방식으로 합쳤다. 개인 볼트 규모에서는 LIKE 전체 훑기도 충분히 빠르다(15개 문서 기준 시작 동기화 36ms).
- 권한 필터는 여전히 `ScopedVault` 한 곳이다. 인덱스는 권한을 모르며, 검색·백링크·태그·위젯·할 일 결과를 모두 여기서 거른다. 백링크는 볼트 전체 기준으로 링크를 해석한 뒤 출처 문서를 권한으로 거른다.
- 위젯 YAML은 서버가 해석·실행한다(`server/src/query.ts`). 같은 엔진을 MCP `query` 도구로도 쓴다. 위젯 문법은 계획서 예시(`type/from/where/show/sort`)를 그대로 따르고 `limit`, `status`, `chart/x/y/agg/data`, `title`을 더했다.
- 할 일 위젯에서 체크하면 원본 문서를 해시 확인 후 바로 저장한다(작성자 기록, 충돌 시 거부). 미리보기 안의 체크박스는 편집 중인 초안만 바꾼다.
- 차트는 단일 계열 막대·선만 지원한다(여러 계열·이중 축은 범위 밖). 계열 색은 밝은 면 `#3b6fd8`, 어두운 면 `#5b8def`로 명도 대역·대비 검사를 통과한 값을 쓰고, 호버 툴팁과 표 보기를 제공한다.
- 남은 점: 서버를 거치지 않은 외부 편집은 재시작 전까지 인덱스·이력에 반영되지 않는다(파일 감시는 이후). 어두운 테마에서 에디터 구문 강조 일부 색(코드 블록 언어 이름 등)이 어둡다.

### 4단계 메모

- **수집**: URL·웹 클리퍼는 Readability(본문 추출) + Turndown(GFM 표 포함)으로, PDF는 unpdf(pdf.js)로 쪽별 텍스트를 뽑는다. 원본 파일은 `raw/assets/`에 함께 남긴다. 스캔 PDF(이미지)는 텍스트가 나오지 않는다(OCR은 이후). 웹 클리퍼는 북마클릿이 현재 페이지 HTML과 선택 영역을 앱 창으로 보내는 방식이라 로그인이 필요한 페이지도 된다. 페이지 제목 끝의 사이트 이름(`| 경제신문`)은 뗀다.
- **SSRF**: 에이전트도 `ingest_url`로 서버가 URL을 가져오게 할 수 있어서, 사설·루프백·링크 로컬 주소는 리다이렉트마다 다시 검사해 막는다(`KEYRING_FETCH_ALLOW_PRIVATE=1`로 해제). 크기 20MB·시간 20초 제한.
- **SCHEMA.md**: "사람만 수정"을 서버가 강제한다. 에이전트 규칙이 무엇이든 `<토픽>/SCHEMA.md`는 읽기까지만. 토픽 만들기도 소유자만.
- **index·log**: 디스크에는 소유자용을 쓰고(다른 에디터에서 보이게), 에이전트에게는 요청할 때 그 에이전트가 볼 수 있는 문서만으로 다시 만든다. 그래서 Git·검색 인덱스에서 뺐다(검색·백링크로 숨김 원본 이름이 새지 않게). log는 Git 이력이 원본이라 에이전트가 고쳐 쓸 수 없다. index의 "미반영 원본"이 수집 작업의 할 일 목록이 된다.
- **시험 운영(2026-10-05)**: 실제 LLM 에이전트 대신, 에이전트 역할 스크립트가 wiki-work 토큰과 MCP만으로 SCHEMA.md 절차를 따라 한 바퀴 돌았다. 이 환경은 외부 웹 접근이 막혀 있어, 자료는 로컬 테스트 사이트의 기사 3건(금리·환율·물가)과 PDF 1건을 썼다.
  - 수집: 에이전트가 `ingest_url`로 기사 1건을 직접 수집 → index의 미반영 원본 4건을 개요·절 단위로 읽고 → 위키 페이지 5개(개념·기관·사건·지표)를 `batch_write` 한 커밋으로 작성 → 미반영 0건.
  - 질의: 목차·검색으로 두 페이지의 필요한 절만(840자) 읽고 답을 쓴 뒤, 답을 "질의" 페이지로 남김.
  - 정리: `query` 위젯으로 sources 없는 페이지, `backlinks`로 고아 페이지(방금 만든 질의 페이지)를 찾아 링크로 연결.
  - 같은 세션에서 원본 덮어쓰기·삭제, SCHEMA 수정, index.md 직접 쓰기, 다른 토픽 읽기가 모두 막힘을 확인.
  - 시험 중 찾아 고친 것: 서버 재시작 때마다 index·log가 커밋됐다가 빠지는 쓸데없는 커밋 2개가 생기던 문제(위키 토픽을 볼트 시작 커밋보다 먼저 찾도록 순서 변경), `list_topics`가 일부만 보이는 토픽을 "hidden"으로 보여 주던 문제("partial"로).

### 5단계 메모

- **설치**: 비밀번호가 없으면 서버가 일회용 설정 코드를 로그에만 찍고, 웹 첫 화면에서 그 코드로 비밀번호를 정한다(도커에서 CLI 없이 시작). 비밀번호가 생기면 이 경로는 닫힌다. CLI(`keyring passwd`)도 그대로 쓸 수 있다.
- **백업**: 볼트의 원본은 모두 Git에 있으므로 `git bundle --all` 하나가 문서·첨부·전체 이력을 담는다. 복원 전 자동 백업과 이전 HEAD ref를 남겨 복원도 되돌릴 수 있다. 자동 백업은 바뀐 것이 있을 때만, 개수 제한은 자동 백업에만.
- **업데이트**: 앱이 스스로 이미지를 바꾸지는 않는다(도커 소켓을 컨테이너에 주지 않기 위해). 관리 콘솔은 최신 릴리스 확인과 명령 안내만 하고, 이미지는 v* 태그마다 GitHub Actions가 GHCR에 올린다.
- **원격 접속**: 앱 포트는 127.0.0.1에만 열고, Caddy(https 프로필, 자동 인증서) 또는 VPN 뒤에 둔다. 허용 호스트 검사(DNS 리바인딩), CSP·프레임 금지 등 보안 헤더, 프록시 뒤 HTTPS면 Secure 쿠키.
- **검증(이 환경)**: 실제 `docker build`(기반 이미지는 mirror.gcr.io, Debian 저장소가 막혀 있어 git이 든 node:22-bookworm으로 대체) → 컨테이너 실행·헬스체크·웹 첫 설치·CLI·재시작 후 유지. compose https 프로필 + Caddy 자체 CA(`CADDY_TLS=internal`)로 호스트의 비루프백 주소에서 접속해 인증서 검증, HTTP→HTTPS, 앱 포트 직접 접속 차단, 다른 Host 421, Secure 쿠키, HTTPS 너머 MCP 쓰기, 관리 콘솔(에이전트·백업·복원)을 확인했다.
  - 시험 중 찾아 고친 것: compose가 설정 안 된 변수를 빈 문자열로 넘겨 `KEYRING_ALLOWED_HOSTS=""`가 "검사 안 함"이 되던 문제(빈 값은 미설정으로 처리).
  - 확인하지 못한 것: 실제 도메인의 Let's Encrypt 발급, GHCR 이미지 게시 워크플로(첫 v* 태그 때 처음 돈다), Debian slim 기반 이미지의 apt 설치(이 환경에서 Debian 저장소 차단), 업데이트 확인(외부 접속 차단 — 실패를 안내로 보여 주는 것까지만 확인).

### 6단계 메모

- **변경 검토 대기열(W5)**: 설정의 `reviewPaths` 아래에 에이전트가 쓰면 일괄 쓰기를 dry run으로 끝까지 검사(권한·충돌·추가 전용)한 뒤 제안으로 저장(`.keyring/proposals/`, Git 밖)한다. 승인은 저장해 둔 연산을 같은 baseHash로 적용하므로 그 사이 바뀐 문서는 충돌로 거부되고 사람 수정이 덮이지 않는다. 사람의 쓰기는 대상이 아니다. 결정 기록은 30일 보관.
- **출처 연결(W6)**: 프런트매터 `sources`를 본문 링크와 다른 종류로 색인한다. 본문 백링크와 "출처로 인용한 페이지"를 나눠 보여 주고, 위키 목차의 반영 판정·정리 점검이 같은 데이터를 쓴다. URL 출처는 볼트 문서가 아니라 뺀다.
- **정리(W7)**: 위키 페이지 규칙(출처·고아·오래됨·필수 프런트매터)은 위키 토픽의 `wiki/`에만 적용하고, 깨진 링크는 모든 문서에. 에이전트에게 숨김 대상으로 가는 링크는 "없거나 볼 수 없음"으로 함께 보여 존재가 드러나지 않는다.
- **웹훅·스케줄러(W8)**: 이벤트는 커밋 직후 `git show --name-status HEAD`로 만들어 수집·에이전트 쓰기·승인 어느 경로든 같은 `raw.added`가 나간다. HMAC 서명, 5xx·연결 실패만 재시도. 정기 작업은 "에이전트를 깨우는" 용도로, 서버가 직접 LLM을 부르지는 않는다(에이전트는 웹훅을 받아 MCP로 일한다). 시험 중 고친 것: 스케줄러가 판단한 시각과 실행 기록 시각이 달라 같은 분에 두 번 돌 수 있던 문제.
- **그래프(W9)**: d3-force + 캔버스. 색은 dataviz 범주 팔레트 중 모든 쌍 검증을 통과하는 앞 3색만(산점도처럼 모든 점이 이웃), 나머지는 "기타" 회색, 범례·호버 툴팁·제목 라벨로 색에만 기대지 않는다.
- **의미 검색(W9)**: 공급자를 정하지 않고 OpenAI 호환 `/embeddings`를 받는다(로컬 Ollama 가능). 벡터는 같은 SQLite 파일의 별도 테이블(검색 인덱스를 다시 만들어도 남음), 정규화해 내적으로 전수 비교. 이 환경에서는 외부 모델에 닿을 수 없어 동의어 묶음을 같은 차원으로 보내는 가짜 임베딩 서버로 파이프라인·증분 갱신·권한 필터를 검증했다. 실제 모델의 검색 품질은 확인하지 못했다.
- **PWA·오프라인(F13)**: 서비스 워커는 화면(index·assets)만 캐시하고 `/api`는 건드리지 않는다. 문서·트리·오프라인 저장분은 IndexedDB. 다시 연결되면 처음 편집을 시작한 baseHash로 보내 충돌이면 "오프라인 충돌 사본"을 만든다(덮어쓰기 금지 원칙 유지). 로그아웃하면 이 기기의 사본을 지운다. 빌드마다 서비스 워커 캐시 이름이 바뀐다.
- **위젯 플러그인**: 플러그인은 볼트 밖 폴더의 ES 모듈이고 API·에이전트로는 쓸 수 없다(브라우저에서 소유자 권한으로 돌기 때문). 쿼리는 서버가 같은 엔진·권한으로 실행하고 플러그인은 그리기만 한다.

### 7단계 계획·메모

- **목표**: 앱은 서버 없이 설치하자마자 쓸 수 있어야 한다. 서버 연결은 선택이며 언제 켜고 꺼도 기기의 문서는 그대로다.
- **플랫폼**: Tauri 2 하나로 데스크톱과 iOS·Android를 낸다. 기존 React·CodeMirror 화면을 그대로 WebView에 올리고, 파일 접근은 공식 fs·dialog 플러그인만 쓴다(Rust 코드는 플러그인 등록뿐). 브라우저에서도 `?local`로 같은 로컬 엔진을 IndexedDB 위에서 돌릴 수 있다(시험·서버 없는 PWA용).
- **로컬 볼트**: 원본은 기기 폴더의 마크다운 파일(데스크톱은 사용자가 고른 폴더, 모바일은 앱 문서 폴더). 앱 메타데이터는 볼트 안 `.keyring-app/`(점 폴더라 서버·Obsidian 모두 무시): 이력 스냅샷(내용 해시로 저장해 중복 없음)·변경 기록(journal)·동기화 기준점. 서버 연결 정보(주소·기기 토큰)는 볼트가 아니라 앱 설정에 둔다.
- **색인**: 기기에서는 SQLite 대신 메모리 색인(시작할 때 전체를 읽음). 개인 볼트 수천 문서까지는 충분하며, 느려지면 캐시를 붙인다. 분석 함수는 서버와 같은 코어를 써서 검색 외 결과(태그·백링크·위젯·위키 목차)가 서버와 같다.
- **동기화 규약**: 문서마다 "마지막으로 맞춘 서버 해시"(기준점 B)를 기억하고 로컬 L·서버 S와 3방향 비교한다.
  - 한쪽만 바뀜 → 그쪽을 반영(서버로 보낼 때는 baseHash=B라 그 사이 바뀌었으면 409로 멈춘다).
  - 양쪽 다 바뀜 → 원래 경로는 서버 버전, 내 변경은 "동기화 충돌 사본"으로 새 문서. 한쪽이 지웠고 다른 쪽이 고쳤으면 고친 쪽을 살린다.
  - 마크다운은 양방향, 첨부(이미지·PDF)는 서버 → 기기만. 서버가 만드는 위키 index·log는 동기화하지 않고 기기에서 따로 만든다.
- **인증**: 앱은 쿠키 대신 기기 토큰(`kd_`)을 쓴다. 비밀번호로 한 번 발급받고 관리 콘솔에서 기기별로 끊을 수 있다. 기기 토큰은 소유자 권한으로 문서를 다루지만 관리 콘솔(백업·토큰·비밀번호)은 못 쓴다. 커밋 작성자는 `소유자 (기기 이름)`. 앱의 출처가 달라 `/api`는 Authorization 헤더로 온 요청에만 CORS를 연다(쿠키 세션 응답은 다른 출처에 보이지 않음).
- **에이전트**: 지금처럼 서버에만 붙는다. 기기에서 쓴 내용은 동기화된 뒤 에이전트가 볼 수 있다.
- **확인·입력 창**: macOS·iOS WebView는 `window.confirm/prompt`를 막을 수 있어 앱에서도 쓰는 화면(편집·동기화)은 앱 안 대화상자를 쓴다. 관리 콘솔·수집·검토처럼 서버 웹 화면에만 있는 곳은 그대로.
- **빌드 구조**: core는 `keyring-source` 조건으로 개발·테스트 때 TypeScript 원본을, 서버 배포(Docker) 때 `dist`를 쓴다. 앱은 web 빌드 결과를 그대로 싣는다.
- **검증(이 환경)**:
  - 자동 테스트: 코어 16개(로컬 볼트·동기화), 서버 118개(새로 4개: 기기 토큰·CORS·동기화 목록, 실제 서버 API를 거친 앱 ↔ 서버 동기화 포함).
  - 브라우저 로컬 모드(Playwright, 서버와 다른 출처): 로그인 없이 쓰기·위젯·검색·새로고침 후 유지, 잘못된 비밀번호 거부, 연결 후 받음·보냄, 서버 커밋 작성자 `me (기기)`, 양쪽 수정 → 충돌 사본, 오프라인 저장 후 동기화 실패 안내 → 다시 연결되면 전송.
  - 실제 데스크톱 앱(Linux .deb 4.4MB, WebKitGTK를 tauri-driver로 조작): 앱 안 대화상자로 새 문서, 실제 폴더(`~/Documents/Keyring Notes`)에 파일·`.keyring-app` 생성, 다른 편집기로 고친 파일을 창 복귀 때 반영, `asset:` 이미지 표시, 이력, 서버 동기화, 재시작 후 유지.
  - Docker 이미지(코어 dist 포함) 빌드·실행·기기 등록.
  - 시험 중 고친 것: core 패키지 조건 이름(`source`)이 다른 패키지와 겹쳐 `keyring-source`로, `generate_context!`에 필요한 serde_json 누락, DOMPurify가 `asset:`·`blob:` 이미지 주소를 지우던 문제, XDG 문서 폴더가 없는 Linux에서 홈으로 폴백.
  - 확인하지 못한 것: Windows·macOS 앱 빌드와 실행, iOS·Android 빌드(SDK 없음)와 실제 기기, 큰 볼트(수천 문서)에서 시작 시간, macOS·iOS WebView에서 플러그인 HTTP·파일 권한 동작.
- **범위 밖**: 실시간 공동 편집(CRDT), 기기 간 직접 동기화, 첨부 업로드 동기화, 모바일 백그라운드 동기화(앱을 열 때·저장할 때 동기화).

### 저장소 확장: S3

- **결정**: 원본(마크다운·Git)은 서버 디스크에 두고 S3는 원격 백업과 큰 첨부 보관에만 쓴다. Git 작업 트리·SQLite 인덱스·일괄 쓰기 원자성이 모두 로컬 파일 시스템을 전제로 하기 때문이다(S3 마운트는 rename·잠금·fsync가 없어 Git이 깨진다).
- **원격 백업**: 기존 .tar.gz 백업을 그대로 `backups/`에 올린다. 실패는 로컬 백업을 막지 않는다. 자동 백업만 개수 제한.
- **큰 첨부**: Git LFS 방식. 커밋 직전 훅(`Vault.beforeCommit`)에서 기준 크기 이상 첨부를 `blobs/<sha256>`로 올리고 Git 제외 목록에 넣은 뒤 목록 파일(`.keyring-blobs.json`)을 같은 커밋에 넣는다. 일괄 쓰기·수집·서버 밖 변경·시작 커밋 모두 같은 길을 지난다. 업로드 실패는 "대기"로 두고 재시도해 쓰기를 막지 않는다.
- **검증**: SigV4는 AWS 문서 예제 서명으로, 클라이언트는 서명을 다시 계산하는 시험용 S3로 자동 테스트(11개). 소스로 빌드한 실제 MinIO로 한글·공백 키, 수집한 첨부의 S3 보관과 Git 제외, 원격 백업, 서버 디스크를 통째로 잃은 뒤 S3만으로 문서·이력·설정·첨부를 바이트 단위까지 되살리는 것을 확인했다. AWS S3·R2 실제 계정으로는 확인하지 못했다.
- **하지 않은 것**: 로컬 사본을 지우고 필요할 때 받기(디스크 절약), 과거 첨부 버전 보기 화면, 쓰이지 않는 S3 객체 정리.

### 충돌 처리: 3방향 병합

- 다른 노트 앱 조사: 사본 만들기(Dropbox·Joplin·Evernote), 3방향 자동 병합(Obsidian Sync·Logseq·git), CRDT(Notion·Anytype·AFFiNE). 마크다운 파일이 원본인 구조에는 두 번째가 맞다.
- `merge3`(core): 줄 단위 diff3. 겹치거나 맞닿은 변경은 충돌(git과 같은 기준), 양쪽이 같게 고친 것은 하나로. 충돌이면 문서에 표시를 넣지 않고 기존처럼 사본을 만든다(덮어쓰기 금지 원칙 유지).
- 적용: 앱 동기화(기준점 내용은 기기 이력 스냅샷에서, 양쪽이 이미 같아 기준점이 된 문서도 스냅샷을 남김), 웹 저장 409(편집 시작 버전 = 기준), 오프라인 저장 대기열(대기할 때 기준 내용을 함께 저장). 저장하는 동안 더 입력한 내용도 한 번 더 합친다.
- 에이전트 쓰기에는 적용하지 않는다(409를 받고 다시 읽는 규약 유지).
- 검증: 병합 단위 테스트 8개, 동기화 3개, 실제 서버 API 동기화 1개, 브라우저 E2E(다른 줄 → 자동 병합, 같은 줄 → 충돌 안내, 오프라인 저장 → 재연결 때 병합, 사본 없음).

### 8단계 메모

- **링크 자동 갱신(1)**: 링크마다 이동 전 경로 목록으로 해석한 대상 R0와 이동 후 목록으로 해석한 R1을 구해, 기대 대상(`moves.get(R0) ?? R0`)과 R1이 다를 때만 고친다. 그래서 이동한 문서를 가리키던 링크와, 이동한 문서가 더 얕은 같은 이름이 되어 다른 링크를 가로채는 경우가 한 규칙으로 처리된다. R0가 없거나(원래 깨진 링크) 기대 대상이 이동 후에 없으면 그대로 둔다.
  - 순수 함수(`core/links.ts`의 `rewriteLinks`·`chainMoves`)를 서버 `Vault.batch`와 앱 `LocalVault.move`가 같이 쓴다. 고치는 곳: 본문 위키링크·임베드, 프런트매터 sources/source의 `[[…]]`와 경로 값(목록·인라인·흐름 목록), 상대 경로 마크다운 링크(문서 폴더 기준, 실제 파일에 닿을 때만, 이동한 문서 자신은 새 위치 기준). 코드 블록·인라인 코드 안은 그대로. 이동한 이름(인코딩 형태 포함)이 본문에 없으면 건너뛰는 빠른 거르기.
  - 서버: 잠금 안 계획 단계에서 모든 연산을 가상 상태에 적용한 뒤 계산하고, 같은 일괄 쓰기의 연쇄 이동(A→B→C)은 합친다. 커밋 제목은 그대로 `이동: a → b`(ScopedVault.history가 이 모양으로 숨김 경로를 가린다), 고친 문서는 본문에 `링크 갱신: <경로>` 줄로. 자동 생성 문서(위키 index·log)는 건너뛴다.
  - 권한: 에이전트는 볼 수 있는 경로로만 해석하고 고친 링크를 늘 전체 경로로 쓴다(짧은 이름이 되는지로 숨김 문서가 드러나지 않게). 고칠 문서마다 `guard("modify")`를 지나야 하고, 안 되면 조용히 건너뛴다. **`BatchResult.files`는 실제로 바뀐 파일만** 넣도록 바꿨다(예전에는 읽기만 한 slot도 들어가, 찾느라 읽은 숨김 경로가 응답으로 샐 수 있었다). 응답에 `linksUpdated`·`linkCount`.
  - 검토 대기열: 링크 갱신이 검토 대상 경로에 닿을 수 있으므로, 검토 경로가 설정돼 있으면 에이전트 이동은 먼저 dry run해 바뀌는 문서까지 보고 검토 여부를 정한다. 제안에는 링크 갱신을 켰는지와 미리보기에서 고친 문서를 저장하고, 승인 때는 그 문서로만 제한해(그 에이전트가 볼 수 있는 경로로 해석) 승인 시점 내용으로 다시 계산한다. 그 사이 생긴 숨김 문서가 끼어들지 않는다. 예전 제안(필드 없음)은 링크를 고치지 않는다. 검토 대상이 아니면 dry run에서 본 문서로만 적용한다.
  - 기본 켬, REST `updateLinks`·MCP `update_links`로 끈다. 웹은 이동 뒤 "링크 N곳을 고쳤습니다(다른 문서 M개)".
  - 주석 `%%…%%` 안의 링크도 고친다(보이지 않을 뿐 원문이므로 어긋나지 않게 두는 편이 낫다).
- **여러 마크다운 형식(2)**: 렌더링 지원으로만 다룬다(마이그레이션 기능 아님). markdown-it 규칙은 동기로 자리만 만들고(`markdown.ts`), 수식·다이어그램·문서 임베드는 그린 뒤 채운다(`enhance.ts`).
  - 콜아웃(종류별 7가지 색 묶음, `+`/`-` 접기는 `<details>`), 하이라이트·각주는 markdown-it 공식 플러그인, 수식 규칙은 직접(`$` 바로 뒤가 공백이거나 닫는 `$` 뒤가 숫자면 수식이 아님 — 금액), 블록 ID(`^id` 표시는 숨기고 `data-block`, `^id`만 있는 줄은 앞 블록), 제목에 `data-heading` — `[[문서#제목]]`·`[[문서#^id]]`·상대 링크 `#제목`으로 열면 그 위치로 스크롤하고 잠깐 표시. 각주 링크는 주소의 `#/문서`를 건드리지 않고 스크롤.
  - KaTeX·Mermaid는 npm 패키지를 번들해 처음 쓸 때만 동적 import(Mermaid 조각 수 MB). 서비스 워커는 빌드 때 지연 자산 목록(js·css·woff2)을 넣어 활성화 뒤 뒤에서 받아 둔다(데이터 절약 모드면 안 받음) — 설치된 PWA는 처음 연 뒤 오프라인에서도 수식·다이어그램이 보인다. 같은 원문은 결과를 기억해 입력마다 다시 그려도 깜빡이지 않는다.
  - 보안: CSP는 넓히지 않았다(KaTeX 글꼴·CSS는 같은 출처 번들, 인라인 style은 이미 허용, 시험에서 위반 없음). 본문 정화 설정은 그대로, 그린 결과는 따로 정화: KaTeX는 HTML+MathML 프로필(`trust: false`로 `\href` 등 막음), Mermaid는 `securityLevel: "strict"` + 라벨을 SVG 글자로(`htmlLabels: false`) 그려 SVG 프로필로 정화.
  - 문서 임베드: 문단에 임베드만 있을 때 내용을 끼워 넣는다. 기존 API(`api.read`, 로컬이면 기기 볼트)로 읽어 권한 계층을 그대로 지나고, 없거나 읽을 수 없으면 끊어진 링크. 깊이 3, 순환이면 링크로만. 임베드 안의 위젯·할 일 체크는 원본 문서에서(누르면 열린 문서의 줄이 바뀌므로 막음). 각주 id는 임베드 깊이별로 앞붙임.
  - 주석: 미리보기에서 숨기고, `analyze`·`wikilinkTargets`도 주석 안의 링크·태그·할 일을 세지 않는다(Obsidian과 같은 쪽, 보이지 않는 링크가 백링크·그래프에 나오지 않게). 줄 수는 그대로라 할 일 줄 번호가 맞는다. 검색(FTS)은 원문 그대로 색인한다.
- **검증**: core 42개(링크 갱신 13·주석 1 추가), 서버 134개(이동 링크 5 추가: 한 커밋·옵션 끔·연쇄 이동과 files·에이전트 숨김/읽기 전용 제외·검토 제안과 승인 범위). 브라우저(서버 모드, 밝은·어두운 테마, 390px 폭): 모든 형식 렌더링, CSP·콘솔 오류 없음, 페이지 가로 넘침 없음(넓은 수식은 그 안에서 스크롤), 각주·블록·상대 링크 이동. 웹에서 이동 → "링크 4곳" → 임베드·링크 그대로 살아 있음. 로컬 모드(`?local`, 서버에서 동기화로 받아 옴)에서도 같은 렌더링과 이동.
- **시험 중 고친 것**: DOMPurify(SAFE_FOR_XML)가 `-->`가 든 속성을 지워 Mermaid 원문(`A --> B`)이 사라지던 문제(원문을 퍼센트 인코딩해 넣음), 빠른 거르기가 괄호를 인코딩한 이름(`a%20%281%29.md`)을 놓치던 문제.
- **확인하지 못한 것**: Safari·Firefox, 데스크톱·모바일 앱(WebKit) 안의 KaTeX·Mermaid, 설치된 PWA가 실제로 오프라인에서 Mermaid를 그리는지(뒤에서 받아 두는 코드만 확인), 아주 큰 볼트에서 이동 시간, Mermaid 일부 다이어그램(마인드맵 등)이 SVG 글자 라벨로 잘 그려지는지.

## 리스크 및 대응

가장 큰 리스크는 개발 범위가 끝없이 커지는 것이다. 매 단계 끝에 MVP 범위를 넘는 작업이 섞였는지 점검한다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 범위 확대 (에디터·위젯 욕심) | 완성 지연, 중단 | MVP 목록 고정, 그 외 요청은 이후 목록으로만 |
| 에디터 완성도가 기존 앱보다 낮음 | 사용 지속 어려움 | WYSIWYG 대신 원문 편집 + 미리보기로 시작, 검증된 에디터 라이브러리 사용 |
| 사람과 에이전트의 동시 수정 | 내용 유실 | 해시 기반 충돌 감지, 덮어쓰기 대신 거부 후 재시도, Git 이력 |
| 에이전트 요약의 왜곡이 위키에 누적 | 잘못된 지식이 퍼짐 | 원본은 추가 전용으로 보존, 출처 연결, 변경 검토 대기열 |
| 일괄 쓰기가 중간에 실패 | 위키가 반쯤 고쳐진 상태로 남음 | 하나의 커밋으로 묶고 실패 시 전체 취소 |
| 권한 구현 실수 (검색·백링크로 숨김 내용 노출) | 개인 정보 유출 | 권한 필터를 인덱스 조회 계층 한 곳에서 적용, 숨김 토픽 노출 테스트 자동화 |
| 원본 자료 용량 증가 (PDF·이미지) | 저장·백업 비용 증가 | 토픽별 용량 한도, 첨부 파일 백업 주기 분리 |
| 서버 외부 노출 | 원본 유출·변조 | VPN 또는 리버스 프록시 + HTTPS, 강력한 인증, 의존성 보안 업데이트 |
| 1인 유지보수 부담 | 장기 방치 | 원본은 순수 마크다운으로 유지해 이식성 보장, 백업·업데이트는 관리 콘솔로 자동화 |
