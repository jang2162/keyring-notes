# 백업과 복원

백업을 만들고 복원하고, 볼트를 다른 서버로 옮기고, S3 호환 저장소에 사본을 둡니다.

서버를 운영하는 분을 위한 문서입니다.

## 백업 만들고 내려받기

설정 → **백업·복원**을 여세요(소유자만).

- **지금 백업**으로 백업을 만듭니다. 목록의 백업은 무엇이든 내려받을 수 있습니다.
- 자동 백업은 간격(기본 24시간)이 지났고 마지막 자동 백업 뒤 바뀐 것이 있을 때 만듭니다. 남길 개수(기본 14)를 넘으면 자동 백업만 지웁니다.
- 백업에 설정(비밀번호·토큰 해시, 권한 표)을 넣을지 고르세요.

백업은 모든 노트와 첨부의 전체 Git 이력을 담은 `.tar.gz` 파일 하나입니다. 형식은 [참조](../reference.md#백업-파일-형식)에 있습니다. 백업 직전에 서버 밖에서 생긴 변경도 커밋해서 넣습니다.

서버에서 자동 백업을 끄려면 `KEYRING_BACKUP_SCHEDULER=0` 을 정하세요.

## 백업 복원하기

목록의 백업에서 **복원**을 고르세요. 설정 복원은 고를 때만 합니다.

복원은 볼트를 바꾸기 전에 지금 상태를 `pre-restore` 백업으로 남기고, 지금 Git HEAD 를 `refs/keyring/before-restore-<시각>` 에 보관합니다. 그래서 복원도 되돌릴 수 있습니다. 복원이나 올리기가 도는 동안에는 설정을 닫을 수 없습니다.

## 다른 서버로 옮기기

1. 옛 서버에서 백업을 내려받으세요.
2. 새 서버의 설정 → **백업·복원**에서 그 백업을 올리세요.
3. **복원**을 고르세요. 설정도 복원하면 비밀번호와 에이전트까지 그대로 옮겨집니다.

## S3 호환 저장소에 백업 두기

원본은 계속 서버 디스크(볼트 폴더와 Git)에 있습니다. S3 호환 저장소(AWS S3, Cloudflare R2, MinIO, Backblaze B2 등)는 두 가지를 더합니다. Docker 로 설정하는 방법은 [Docker 로 배포하기](deploy-with-docker.md#s3-저장소-고르기선택)에, 모든 키는 [설정값](../configuration.md)에 있습니다.

버킷은 공개하지 않습니다. 첨부는 지금처럼 서버가 권한을 확인한 뒤 내줍니다.

### 원격 백업

`KEYRING_S3_BUCKET` 과 키를 정하면 바로 켜집니다.

- 백업마다 `<접두사>backups/` 에도 올립니다(**S3에도 올리기**, 기본 켬).
- S3 의 자동 백업은 따로 정한 개수만 남깁니다(**S3에 남길 자동 백업**, 기본 30).
- 올리기가 실패해도 로컬 백업은 만들어지고 관리 콘솔에 경고가 뜹니다.

서버를 잃으면 같은 S3 설정으로 새 서버를 띄우세요. 설정 → **백업·복원**의 S3 원격 백업 목록에서 백업을 가져와 복원하세요.

### 큰 첨부를 S3 에 두기

`KEYRING_S3_BLOBS=1` 이면 기준 크기(`KEYRING_S3_BLOB_MIN_KB`, 기본 256KB) 이상의 첨부(마크다운이 아닌 파일)를 내용 해시로 `<접두사>blobs/` 에 올리고 Git 에서는 뺍니다. Git 에는 경로→해시 목록 `.keyring-blobs.json` 만 남습니다. Git LFS 와 같은 방식입니다. 파일은 볼트 폴더에 그대로 있으므로 앱, API, 동기화, 다른 편집기는 차이가 없고, Git 이력과 백업이 작아집니다.

- 켜는 순간 이미 Git 에 있던 큰 첨부도 이력에서 빠집니다. 과거 커밋 안의 사본은 남습니다.
- 올리기가 실패해도 쓰기는 되고, 그 파일은 올리기를 기다리며 5분마다 다시 올립니다. 기다리는 첨부는 백업에 들어가지 않고, 관리 콘솔이 경고합니다.
- 복원은 그 백업의 목록대로 S3 에서 첨부를 받아 오고, 그 뒤에 생긴 첨부는 지웁니다.
- S3 객체는 내용 해시가 이름이라 덮어쓰지 않고, 과거 백업이 가리킬 수 있어서 지우지도 않습니다. 버킷에 버전 관리나 수명 주기 규칙을 걸면 `blobs/` 는 빼세요.
- 첨부의 이력은 노트 이력 화면이 아니라 `.keyring-blobs.json` 의 Git 이력에 있습니다.

### 올리기 전에 암호화하기

`KEYRING_S3_ENCRYPTION_KEY` 를 정하면 백업과 첨부를 서버에서 AES-256-GCM 으로 암호화한 뒤 올립니다. 저장소 운영자나 유출된 접근 키를 가진 사람은 내용을 읽을 수 없습니다.

- 키는 긴 무작위 문자열을 쓰세요. 예: `openssl rand -base64 32` 의 결과.
- 키는 scrypt 로 늘려 씁니다. 솔트와 키 확인 값은 `<접두사>encryption.json` 에 두며, 비밀이 아닙니다.
- 다른 키로 띄우면 로그에 알리고 올리기를 멈춥니다. 다른 키로 올린 데이터가 섞이지 않게 하려는 것입니다.
- 첨부는 내용 해시 대신 HMAC 이름으로 `<접두사>blobs-enc/` 에 올려, 해시를 맞춰 보고 어떤 파일을 가졌는지 알 수 없게 합니다. 크기, 올린 시각, 백업 이름은 가리지 않습니다.
- 암호화를 켜기 전에 올린 백업과 첨부도 그대로 읽습니다. 받은 첨부는 내용 해시를 확인합니다.
- 서버 디스크의 로컬 백업은 암호화하지 않습니다. 디스크 암호화는 운영체제에 맡기세요.

> [!WARNING]
> 키를 잃으면 암호화한 백업과 첨부는 복구할 수 없습니다. 비밀번호 관리자처럼 서버 밖에 따로 두세요. 키 바꾸기는 지원하지 않습니다.
