## 사용자가 고르지 않은 결정

코디네이터나 워커가 정했다. 바꿀 때는 해당 코드와 `docs/ops/ux.md`·사용자 문서를 함께 고친다.

- **권한 규칙은 대소문자까지 접어 엄한 쪽으로 판정한다**(코디네이터). 제한하는 규칙은 철자가 달라도 적용되고, 다른 철자로는 권한이 넓어지지 않는다. 대가: 대소문자를 가리는 볼륨에서 `secret/` 과 `Secret/` 을 따로 두면 숨김 규칙이 둘 다 숨긴다. 처음 지시(「정규화만 맞추고 대소문자는 디스크를 따른다」)는 만들기만 따로 막는 꼴이 되어, 다른 주체가 먼저 만든 폴더로 새는 것이 2회차 리뷰에서 재현됐다.
- **디스크와 대소문자가 다른 경로는 없는 경로다**(코디네이터). 대소문자를 가리지 않는 볼륨에서도 Linux 와 같은 답을 낸다.
- **빈 프런트매터(`---` 바로 뒤 `---`)는 프런트매터로 읽는다**(코디네이터). 그래서 내용이 그 두 줄뿐인 새 노트는 닫을 때 빈 노트로 지워진다.
- **초안을 덮거나 버리는 조작은 저장 안 한 것이 남으면 하지 않는다**(워커). 노드·워크스페이스 삭제도 든다. 자동 저장을 끈 사람에게 대신 저장해 주지 않는다.
- **서버에 닿지 않은 로그아웃은 이 기기의 것을 지우지 않는다**(워커). 대가: 연결 없이 이 기기의 사본만 지우는 길이 없다.
- **서버가 거절한 오프라인 저장은 대기열에 남긴다**(워커). 502·503·504 는 거절이 아니라 연결 없음으로 본다.
- **그리지 못한 노트의 대체 화면**은 안내, 원문, 다시 시도 단추다(코디네이터). 편집 모드로 바꾸는 단추는 두지 않았다.
- **web 테스트에 jsdom 을 개발 의존성으로 들였다**(코디네이터). DOM 이 필요한 시험 파일만 그 환경으로 돈다.
- **CI 는 Node 22·24 두 벌**이고 `main` 커밋마다 결과를 남긴다(코디네이터). pull request 에서만 앞선 실행을 취소한다.

## 확인하지 못한 것

- **Linux.** 권한 수정은 macOS(APFS)에서만 실측했다. 볼륨 성질에 달린 테스트 4개는 대소문자를 가리는 볼륨에서 건너뛴다. Linux Node 22 컨테이너에서 테스트 전체가 통과한 것은 `ops-deps-ci` 시점의 트리다.
- **CI 워크플로의 실제 실행.** push 해야 돈다. 처음 돌 때 볼 것: `jdx/mise-action` 이 `MISE_NODE_VERSION` 을 받는가(안 받으면 「런타임 확인」 단계에서 멈춘다).
- **`unpdf` 1.9.1 로 올린 뒤의 Docker 이미지 빌드.** 1.8.1 때는 빌드·기동·이미지 안 PDF 수집을 확인했다.
- **데스크톱·모바일 앱(WKWebView)과 Firefox·Safari.** 화면 확인은 Chromium 이다(PDF 보기만 WebKit 도).
- 데스크톱 앱에서 디스크 쓰기 실패가 저장 실패로 보이는지(코드와 순수 테스트만).

## 이월 — 이번 수정에서 남은 것

화면 쪽은 `docs/ops/ux.md` 의 「그리지 못하는 노트가 앱 전체를 내리던 것」·「저장 안 한 글이 묻지 않고 사라지던 경로」·「색인·링크 고치기가 멈추던 입력, 프런트매터 판정 한 벌」 절의 「남은 것」에 있다. 그 밖:

- **`@napi-rs/canvas` 의 고지.** `docs/guides/development.md` 「의존성과 라이선스 고지」에 빈자리로 적었다. 고지를 채우거나 Docker 설치에서 선택적 의존성을 뺀다.
- **남은 감사 5건.** `nanoid` 4.0.2 넷(번들에 실리지 않는다)과 `katex` 0.16(낮음, mermaid 12 로 올려야 함께 풀린다).
- **릴리스 워크플로에 테스트가 없다.** 태그를 찍기 전에는 검증할 수 없어 고치지 않았다.
- **소유자가 규칙의 철자로 폴더를 못 만들 때의 오류 글.** 다른 대소문자의 폴더가 먼저 있으면 「No such note」가 나온다. core 에 새 오류 코드가 필요하다. 대소문자만 바꾸는 이름 바꾸기도 같은 글이다.
- **노트의 원시 HTML `<form>`·`<style>`·`style` 속성**이 정화를 지나 남는다(스크립트는 돌지 않는다). 데스크톱 앱 CSP 에 `form-action` 이 없다.
- **부하에서 흔들리는 테스트.** 5초 제한과 CodeMirror 파서 예산에 기대는 것들(`docs/guides/development.md` 「검사」). CI 러너에서 가끔 떨어질 수 있다.

## 이월 — 점검에서 나왔지만 재현하지 않은 것

코드 읽기로만 나온 주장이다. **재현부터 한다.** 「확인함」은 감사 에이전트가 코드 경로를 끝까지 따라갔다는 뜻이고 실행으로 본 것이 아니다.

**서버**

- 로그인 지연이 동시 요청에 무력하다 — 지연을 요청이 들어온 순간의 실패 횟수로 정하고 `scryptSync` 로 검사한다. 실패 횟수가 전역이라 소유자도 막힌다. `/api/auth/device` 의 CORS 가 `*` 다.
- 백업 파일에 세션 서명 키(`sessionSecret`)가 들어 있다 — 암호화 없이 쓰는 버킷을 읽을 수 있으면 소유자 세션을 만들 수 있다.
- 백업 복원이 번들 내용을 믿는다 — 첨부 목록(`.keyring-blobs.json`)의 경로를 검증하지 않고, 번들이 `.history/` 아래 경로를 추적하면 저장소 설정을 덮을 수 있다(추정).
- 수집(ingest)의 권한 검사가 맨 끝이라 숨긴 토픽의 존재가 드러나고, 권한 없는 토큰이 서버에 URL 을 받게 한다.
- 토픽으로 좁힌 웹훅에 그 토픽 밖 경로가 실려 나간다.
- `/mcp` 에 본문 크기 제한이 없고, 검색 SQL 에 상한이 없고, 검토 제안이 개수 제한 없이 쌓인다.
- 로그아웃이 세션을 폐기하지 않는다(상태 없는 서명 쿠키).
- 백링크·위키 목차의 링크 해석이 숨김 경로까지 넣어 계산된다(이름 충돌로 존재가 드러난다).
- `/api/plugins`·`/api/semantic/status` 가 권한 계층을 거치지 않는다.
- `void backups.prune()` 의 거부를 받는 곳이 없다.

**core·동기화·앱**

- UTF-8 이 아닌 `.md` 가 기기 동기화 두 번 만에 서버에서 U+FFFD 로 덮인다 — 기기가 받은 내용을 매니페스트 해시와 대조하지 않는다.
- 대소문자·정규화만 다른 두 경로를 한 번에 받으면 한쪽이 덮이고 다른 쪽이 지워진다(`LocalVault.applySync`).
- S3 첨부 보관을 켠 서버에서 복원 직후 `afterRestore` 가 되살린 추적 첨부를 지운다.
- 서버·기기 모두 제자리 쓰기라 프로세스가 죽으면 반쯤 쓰인 파일이 정상 변경으로 퍼진다. `sync.json` 이 깨지면 기준점이 조용히 빈다.
- 서버 밖에서 넣은 파일은 다음 흡수 전까지 지우기·옮기기가 실패한다(`git add --all -- <경로>` 가 128 로 끝난다).
- 받기 적용 단계에서 파일 하나가 실패하면 동기화 전체가 멈추고 기준점도 저장되지 않는다.
- 동기화 실행이 겹쳐 새 노트에 내용이 같은 충돌 사본이 생긴다.
- 기기 이력(journal·objects)에 상한도 정리도 없다.
- 남은 `index.lock` 을 처리하지 않아 서버가 재시작 루프에 빠진다.
- 앱 웹뷰 권한이 홈 전체 읽기·쓰기·삭제와 모든 URL 요청이고, 기기 토큰이 평문 localStorage 다.
- 복원 중 실패하면 반쯤 바뀐 상태로 남고 색인을 맞추지 않는다.
- 링크 해석이 링크마다 `LinkIndex` 를 새로 만든다(정리 점검·그래프·기기 백링크가 링크 수 × 파일 수).
- 실행 중인 서버는 외부 변경을 색인에 반영하지 않는다.
- 위젯의 `modified` 는 UTC 날짜, `today` 는 로컬 날짜다.
- 앱이 꺼진 동안 사라진 노트는 휴지통에 남지 않고 서버에서도 지워진다.
- 양쪽에서 갈린 첨부는 영구히 건너뛰고, 0바이트 첨부는 영구히 오류다.

**웹**

- 오프라인 큐 쓰기(IndexedDB)가 실패하면 「저장 중」에 멈춘다.
- 미리보기의 외부 링크가 같은 탭(앱에서는 웹뷰)에서 열린다.
- 키 입력마다 Workspace 전체가 다시 그려지고 트리에 가상화가 없다. 트리 행 계산이 형제 수의 제곱이다.
- 노드·워크스페이스 삭제가 파일을 하나씩 전부 읽어 메모리에 든다.
- `flush()` 가 진행 중인 저장을 기다리지 않는다.
- 임베드한 노트 안의 `keyring-widget` 이 빈 자리로 남는다.
- 진입 청크가 크고 화면 단위 분할이 없다(설정·관리·그래프·검토가 정적 import).
- 이미지 확장자 정규식이 세 종류로 갈려 있다(avif·ico).

## 최종 검증

병합 뒤 `main` 에서 돌렸다. 수치는 아래 명령의 출력이다.

```bash
pnpm install --frozen-lockfile
pnpm fmt:check && pnpm lint && pnpm typecheck
pnpm --filter @keyring-notes/core exec vitest run --maxWorkers=4
pnpm --filter @keyring-notes/server exec vitest run --maxWorkers=4
pnpm --filter @keyring-notes/web exec vitest run --maxWorkers=4
pnpm build
pnpm audit
```

- 설치·`fmt:check`·`lint`·`typecheck`·`build`: 종료 코드 0.
- 테스트: core 27 파일 492개, server 30 파일 367개, web 100 파일 1,213개 통과.
- web 은 첫 실행에서 1개가 떨어졌다 — `src/codeLanguages.test.ts` 「편집 화면 … py 블록을 Python 으로 읽는다」(`expected 'CodeText' to be 'def'`). 그때 부하 평균이 70 이었다. 그 파일 단독 3회와 전체 재실행(`--maxWorkers=3`)은 통과했다. 이번 배치가 건드리지 않은 파일이고, CodeMirror 파서의 시간 예산에 기대는 테스트다(「이월」의 부하에서 흔들리는 테스트).
- `pnpm audit`: 5건(높음 3, 중간 1, 낮음 1). 배치 전 38건.
