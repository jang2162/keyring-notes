# keyring-widget — 노트 안 상태 위젯 — 설계

Nov 9, 2026 · 기준 커밋 `cd8274b`

## 왜

노트 안에 작은 앱(D-day, 카운터, 그림판 같은 것)을 넣고, 그 상태가 노트 파일에 남게 하고 싶다(사용자). 나중에 마켓플레이스에서 제3자 위젯을 받아 쓸 수 있어야 하므로 실행 구조가 처음부터 제3자 코드를 견뎌야 한다. 요청과 앞선 결정은 `docs/ops/ux.md` 「5차 요청 (2026-11-09)」 의 「위젯」 줄과 「사용자 결정」 절.

지금 있는 ` ```widget `(YAML) 블록은 **서버가 볼트를 조회해 결과를 만드는 쿼리 위젯**이고, 미리보기에서만 그려지며(`web/src/markdown.ts` 의 `widget-slot`), `type: plugin` 은 `/plugins/<이름>.js` 를 앱 창 안에서 그대로 `import()` 한다(`web/src/Widget.tsx` 의 `PluginWidget`). 이번 위젯은 그와 성격이 다르다 — 자기 상태만 다루고, 편집 화면(Live Preview)에서 그 자리에서 고친다.

## 범위

| 항목 | 이번에 | 정한 사람 |
| --- | --- | --- |
| 블록 형식 ` ```keyring-widget ` + JSON | 만든다 | 사용자 |
| 위젯은 자기 상태만 읽고 쓴다(다른 노트·볼트 데이터 없음) | 그렇게 한다 | 사용자 |
| `display: block \| inline`, inline 은 「블록이지만 내용 폭만큼만 그린다」 | 그렇게 한다 | 사용자 |
| 수정 중 상태는 런타임에만, 적용할 때 파일에 쓴다 | 그렇게 한다 | 사용자 |
| 이벤트 API(위젯 안 상호작용으로 상태 변경) | 만든다 | 사용자 |
| 상태가 큰 위젯은 데이터 파일을 따로 두고 블록에는 경로만 | 그렇게 한다 | 코디네이터 제안·사용자 이의 없음 |
| 큰 위젯(Excalidraw 류)은 노트 안 그 자리에서 고친다(전체 화면 키우기 단추) | 그렇게 한다 | 사용자(①) |
| 실행: 앱 코드이고 인라인 기준을 지키면 인라인, 나머지는 iframe | 그렇게 한다 | 사용자(A안 + 기준) |
| 내장 위젯 D-day(인라인) | 만든다 | 코디네이터 |
| 내장 위젯 Excalidraw(iframe, 데이터 파일) | 만든다 — 2단계 | 코디네이터 |
| Live Preview·미리보기 둘 다에서 그리기 | 그렇게 한다 | 코디네이터 |

**하지 않는 것(non-goals)**

- 마켓플레이스·패키지 설치·제3자 위젯 받기. 별도 설계다. 이번에는 제3자 위젯이 들어올 **자리(iframe 호스트와 API)** 만 만들고, 그 자리를 앱 내장 위젯(Excalidraw)으로 검증한다.
- 위젯이 다른 노트·볼트·네트워크를 읽는 API.
- 기존 ` ```widget `(YAML 쿼리 위젯)의 형식 변경·옮기기. 그대로 둔다. 두 블록을 한 레지스트리로 합치는 것은 마켓플레이스 설계에서 다룬다.
- 문장 중간에 끼우는 인라인 문법.
- 블록을 지웠을 때 데이터 파일 자동 삭제. 파일은 첨부로 남는다(트리 「파일 N」 줄에서 지울 수 있다).
- 위젯 넣기 UI 의 화려함. 명령 팔레트 「위젯 넣기」 하나다. `/` 슬래시 명령은 저장소에 체계가 없어 만들지 않는다. — 코디네이터
- 위젯이 다른 노트를 여는 `open(path)` API. 위젯은 자기 상태만 다룬다(사용자) — 링크가 필요하면 노트 본문에 둔다. — 코디네이터

**실패로 보는 것(anti-goals)**

- 위젯을 한 번 누르거나 포커스가 오갈 때마다 파일이 바뀌는 것(저장·동기화·커밋 폭주). 파일은 「적용」 이나 상호작용 한 번에 한 번만 바뀐다.
- 위젯 안 변경이 본문 실행 취소와 따로 노는 것 — 인라인 위젯의 적용은 본문 `Mod+Z` 한 번으로 되돌아가야 한다.
- iframe 위젯이 앱 DOM·저장소·쿠키·다른 노트·네트워크에 닿는 것.
- 위젯 코드가 없거나 블록 JSON 이 깨졌을 때 노트 내용이 사라지거나 고칠 길이 없어지는 것 — 늘 원문 블록이 남고 원문으로 고칠 수 있어야 한다.
- 큰 데이터를 노트 본문 JSON 에 넣어 노트가 수백 KB 로 부푸는 것.
- 한글 입력(IME)이 위젯 입력칸에서 깨지는 것.

## 접근 방식

| 안 | 내용 | 대가 | 결정 |
| --- | --- | --- | --- |
| A | 기준을 지키는 앱 코드는 인라인(편집기 안 DOM), 나머지는 sandbox iframe + `postMessage`, 같은 API | API 연결이 둘 — 같은 위젯을 두 연결로 돌리는 시험으로 같음을 지킨다 | **골랐다** |
| B | 모든 위젯을 iframe | 위젯이 많은 노트가 무겁다. 높이·테마·포커스 아웃을 매번 iframe 너머로 | 작은 위젯에 비용이 과해 버림 |
| C | 모든 위젯을 앱 안(Web Component 등) | 제3자 코드가 앱 권한으로 돈다 — 지금 `PluginWidget` 의 문제 그대로 | 마켓플레이스와 맞지 않아 버림 |

### 인라인/iframe 기준 (사용자 승인)

위젯을 등록할 때 **정적으로** 정한다. 실행 중에 재서 바꾸지 않는다 — 같은 위젯이 상황마다 포커스·테마·실행 취소 동작을 바꾸면 안 된다.

1. **앱과 함께 빌드된 코드가 아니면 무조건 iframe.** 보안은 잴 수 있는 값이 아니라 출처로만 가른다(제3자, 파일로 설치한 위젯).
2. **앱 코드라도 다섯 가지를 모두 지킬 때만 인라인.** 하나라도 넘으면 iframe.
   - 처음 쓸 때 불러오는 코드가 압축(gzip) 약 50KB 이하 — **빌드 시험으로 막는다**
   - `window`·`document` 에 이벤트를 걸지 않고 전역 CSS 를 쓰지 않는다. 스타일은 자기 클래스 안, 색은 앱 테마 토큰 — 리뷰 점검
   - 자기 입력칸 안의 키만 받는다. 앱 단축키·편집기 키맵·IME 를 가로채지 않는다 — 리뷰 점검
   - 자기 실행 취소 기록이 없다. 모든 변경은 편집기 트랜잭션 — 리뷰 점검
   - DOM 수백 개 이하, 계속 도는 애니메이션·캔버스 루프 없음 — 리뷰 점검

위젯 정의에 `isolation: "inline" | "frame"` 을 적는다. 1번에 걸리면 앱이 `frame` 으로 강제한다. **리뷰 점검 넷은 정적으로 완전히 잡지 못한다** — 시험이 통과해도 이 넷은 보증되지 않는다.

적용: D-day → inline. Excalidraw → frame(크기·전역 이벤트·키보드·자체 실행 취소·캔버스 다섯 다 넘는다).

## 블록 형식

````markdown
```keyring-widget
{"widget": "keyring/dday@1", "display": "block", "editable": true, "state": {"targetDate": "2026-12-25", "label": "크리스마스"}}
```
````

| 키 | 뜻 | 정한 사람 |
| --- | --- | --- |
| `widget` | `<id>@<상태 판>`. id 는 범위 붙은 이름(내장은 `keyring/…`). 판은 상태 스키마 판(정수) | 사용자(위젯 id), 형식은 코디네이터 |
| `display` | `block`(본문 폭) \| `inline`(블록이지만 내용 폭만큼). 없으면 위젯 정의의 기본값 | 사용자 |
| `editable` | `false` 면 수정 모드에 들어가지 않고 상호작용으로도 상태를 바꾸지 않는다. 없으면 `true` | 사용자(「고정 상태값으로 수정여부」) |
| `state` | 위젯 상태. 위젯이 스키마를 정한다 | 사용자 |

- 엄격한 JSON(주석·끝 쉼표·따옴표 없는 키 없음). 파싱에 실패하거나 `widget` 이 없으면 원문 블록과 오류 한 줄을 그린다.
- 앱이 블록을 다시 쓸 때는 **예약 키 순서(`widget`·`display`·`editable`·`state`)와 2칸 들여쓴 여러 줄 JSON** 으로 쓴다(diff 를 읽을 수 있게). 단 블록 JSON 전체를 한 줄 꼴(`": "`·`", "` 띄움)로 썼을 때 80자(UTF-16 길이) 이하면 한 줄로 쓴다. 넘으면 예약 키마다 한 줄이고 `state` 값도 2칸 들여쓴 여러 줄로 펼친다 — 상태 필드 하나가 바뀌면 diff 에 그 줄만 보이게. 모르는 키는 지우지 않고 예약 키 뒤에 원래 순서로 둔다. 사람이 원문으로 쓴 모양은 앱이 그 블록을 다시 쓸 때까지 그대로 둔다. — 코디네이터
- 위젯 정의가 `migrate(state, fromVersion)` 을 주면, 블록의 판이 낮을 때 그린 화면에는 올린 상태를 쓰고, 파일은 다음 적용 때 새 판으로 쓴다(읽기만으로 파일을 바꾸지 않는다). 판이 위젯보다 높으면 원문과 「이 위젯의 새 판이 필요합니다」. 판이 낮은데 `migrate` 가 없으면 호환으로 보고 상태를 그대로 쓰며, 다음 적용 때 위젯 판으로 쓴다. — 코디네이터

### 데이터 파일(큰 상태)

````markdown
```keyring-widget
{"widget": "keyring/excalidraw@1", "display": "block", "state": {"file": "회의록/스케치-3f9a.excalidraw.json"}}
```
````

- 위젯 정의에 `dataFile: { ext: ".excalidraw.json" }` 를 적은 위젯만 데이터 파일을 쓴다.
- 처음 넣을 때 앱이 그 노트의 첨부 위치(공통 설정 「첨부 폴더」 규칙 그대로)에 `<위젯 이름>-<짧은 무작위>.<ext>` 를 만들고 `state.file` 에 적는다. 이름은 앱이 정한다.
- 위젯은 **그 블록의 `state.file` 하나만** 읽고 쓴다(`api.file`). 다른 경로·`..`·절대 경로는 앱이 거부한다. 블록을 원문으로 고쳐 `state.file` 을 바꾸면 그 파일을 쓴다(같은 그림을 두 노트에서 가리키는 것도 막지 않는다).
- 쓰기는 첨부 교체 규칙을 그대로 탄다: 서버는 `PUT /api/attachment?path=&baseHash=`, 기기 볼트는 해시 검사 교체, 동기화는 서버가 기준점 그대로일 때만 올림(`ux.md` 「첨부 삭제·교체 구현」). 해시가 다르면(다른 창·기기가 먼저 바꿈) 덮어쓰지 않는다. 위젯이 들고 있던 내용을 같은 첨부 폴더에 노트 동기화와 같은 「충돌 사본」 이름으로 올리고, 알림에 그 경로를 보인 뒤 원본을 다시 읽는다(블록은 원본을 계속 가리킨다) — 마지막 저장 뒤 그린 것을 잃지 않게. — 코디네이터
- 파일이 없으면(지워짐·아직 동기화 안 됨) 위젯은 「파일을 찾을 수 없습니다」 와 경로를 보이고, 새로 만들지 않는다.
- **`state.file` 은 첨부 링크로 친다** — 코디네이터. 경로는 볼트 기준(첨부 링크와 같은 정규형). core 의 링크 추출이 `keyring-widget` 블록의 `state.file` 을 읽어, 첨부를 옮기거나 이름을 바꾸면 블록의 경로도 고쳐지고(`rewriteLinks`·`updateLinks`), 첨부 삭제 확인창의 「가리키는 노트」(`linkingDocs`)와 깨진 링크 점검(`analysis.ts`)에 잡힌다. 링크로 치지 않으면 이름 바꾸기 한 번에 위젯이 조용히 파일을 잃는다. 경로 검사(「그 블록의 `state.file` 만」)는 이 정규형으로 한다. 이 일은 2단계에 든다.
- **쓰는 시점은 앱(호스트)이 정한다** — 코디네이터. 위젯은 바뀔 때마다 `api.file.write` 를 불러도 되고, 앱이 노트 자동 저장과 같은 규칙(멈춘 뒤 한 번, 설정의 자동 저장 간격)으로 모아 마지막 것만 쓴다. 포커스 아웃·탭 닫기·노트 바꾸기·창 숨김(`visibilitychange`)·앱 닫기 전에는 남은 쓰기를 비운다(flush). 자동 저장을 끈 설정이면 노트처럼 「저장하지 않은 그림」 표시를 두고 `Mod+S` 로 쓴다. 획마다 커밋·업로드가 생기지 않게 하는 것과 닫을 때 잃지 않는 것을 둘 다 지키려는 것이다.
- **이력 보기(읽기 전용)에서 데이터 파일 위젯은 그 판의 파일을 그리지 않는다** — 코디네이터. 지금 파일을 그리면 옛 노트에 지금 그림이 보여 속이므로, 위젯 자리에 「이력 보기에서는 그림을 보이지 않습니다」 와 경로만 둔다. 첨부의 옛 판은 첨부 이력으로 본다.

## 실행

### 공통 API (인라인·iframe 같음)

```ts
interface WidgetDefinition {
  id: string;                 // "keyring/dday"
  version: number;            // 상태 판
  isolation: "inline" | "frame";
  display: "block" | "inline"; // 기본값
  dataFile?: { ext: string };
  defaultState(): unknown;    // 「위젯 넣기」 때
  migrate?(state: unknown, from: number): unknown;
  title: Record<string, string>; // 언어별 이름(넣기 목록)
}

// 위젯 코드가 구현한다
render(el: HTMLElement, ctx: WidgetContext, api: WidgetApi): () => void  // 정리 함수

interface WidgetContext {
  state: unknown;      // 지금 보일 상태(수정 중이면 초안)
  editing: boolean;
  editable: boolean;
  display: "block" | "inline";
  lang: string;        // 화면 언어
  theme: Record<string, string>; // 앱 테마 토큰 값(--fg, --bg, --accent …)
  readOnly: boolean;   // 이력 보기 등
}

interface WidgetApi {
  setState(patch: object): void;   // 아래 「상태가 바뀌는 길」
  requestEdit(): void;             // 수정 모드 들어가기
  exitEdit(apply: boolean): void;  // 끝내기(적용 / 버리기)
  t(key: string, vars?: object): string; // 위젯이 가져온 메시지
  file?: { read(): Promise<{ bytes: Uint8Array; hash: string }>; write(bytes: Uint8Array, baseHash: string): Promise<{ hash: string }> };
  toggleFullscreen?(): void;       // display: block 위젯만
  onUpdate(cb: (ctx: WidgetContext) => void): void; // 상태·테마·언어가 바뀌면
}
```

`setState` 의 patch 는 얕은 병합이다. 위젯은 `state` 를 직접 바꾸지 않는다.

### 상태가 바뀌는 길 (사용자 결정 위에서 코디네이터가 정함)

- **보기 모드에서 상호작용**(예: 카운터 +1, 체크): `setState` 가 곧바로 블록을 한 번 다시 쓴다(트랜잭션 하나). `editable: false` 면 무시한다.
- **수정 모드**: `requestEdit()`(위젯이 부름, 보통 위젯을 누르거나 Enter) → `editing: true` 로 다시 그림. 이 동안 `setState` 는 메모리 초안만 바꾼다. 다음에 끝난다:
  - 위젯 밖으로 포커스가 나감(사용자: 「포커스 아웃되면 수정모드 종료」) → **적용**: 초안이 원래 상태와 다르면 블록을 한 번 다시 쓴다.
  - `Esc` → 초안 버림.
  - 위젯이 `exitEdit(true|false)`.
- 블록 다시 쓰기는 **늘 그 칸의 편집기 트랜잭션**이다(실행 취소 한 번, 자동 저장·같은 문서 다른 칸·동기화가 본문 경로 그대로). 미리보기도 숨은 편집기가 있다 — 미리보기의 할 일 체크가 `handle.current.toggleTask` 로 편집기 초안을 바꾸는 것(`DocPane.tsx`)과 같은 길을 쓴다. 편집기가 없는 이력 보기는 읽기 전용이라 쓰지 않는다. — 코디네이터(빌더 점검에서 고침: 처음 안의 `api.write` 직접 쓰기는 저장하지 않은 초안과 갈라진다)
- 수정 중에 바깥 변경(다른 칸·동기화)이 같은 블록을 바꾸면 초안은 유지하고 적용 때 바깥 변경 위에 쓴다 — 블록 하나가 위젯의 원자 단위다. 블록이 사라졌으면 초안을 버리고 알린다.
- 데이터 파일 쓰기는 블록과 따로다. 노트 실행 취소에 들어가지 않는다(파일 이력은 git). Excalidraw 의 실행 취소는 위젯 안 자체 기록이다 — 그래서 iframe 이다.

### 인라인

- Live Preview: `liveBlocks.ts` 의 블록 찾기에 `CodeBlock` 정보 문자열 `keyring-widget` 을 더하고, 커서가 블록 밖이면 위젯으로 그린다(mermaid 와 같은 자리). 커서가 블록 안에 들어오면 원문 — 다른 블록들과 같다. 위젯 머리에 「원문으로 편집」 을 둔다(표의 「원문으로 편집」 과 같은 방식).
- 미리보기: `markdown.ts` 의 fence 규칙에 `keyring-widget` 자리를 더한다(`widget-slot` 과 같은 방식, 다른 클래스).
- `display: inline` 은 `width: fit-content` 블록.

### iframe

- `sandbox="allow-scripts"`(same-origin 없음). 위젯 코드와 부트스트랩을 `srcdoc` 으로 넣는다. 네트워크는 iframe 안 CSP `default-src 'none'` + 필요한 `script-src`(해시 또는 nonce)로 막는다.
- 부트스트랩이 `postMessage` 로 API 를 잇는다. 메시지마다 위젯 인스턴스 id 를 붙이고, 앱은 **자기가 만든 iframe 의 `contentWindow` 에서 온 메시지만** 받는다.
- 높이: 부트스트랩의 `ResizeObserver` 가 높이를 보낸다. 앱이 상한을 둔다(전체 화면이 아니면 예: 화면 높이 80%).
- 포커스 아웃: iframe 이 포커스를 잃는 것(`blur` 를 앱 쪽 `document.activeElement` 로 판정) = 위젯 밖으로 나감.
- 테마·언어가 바뀌면 `onUpdate` 로 보낸다.
- 전체 화면: 앱이 그 iframe 을 화면 전체 겹침으로 옮긴다(다시 만들지 않는다 — 그리던 것을 잃지 않게). `Esc` 는 먼저 위젯에 가고, 위젯이 처리하지 않으면 전체 화면을 닫는다.

### 넣기·없을 때

- 명령 팔레트 「위젯 넣기」 → 등록된 위젯 목록 → 커서 자리에 `defaultState()` 로 블록(데이터 파일 위젯은 파일도 만든다).
- 등록되지 않은 `widget` id: 원문 블록 + 「위젯 `<id>` 를 찾을 수 없습니다」. 마켓플레이스가 생기면 여기에 「설치」 단추가 들어갈 자리다.

## 제약

- **CSP(사용자 결정)**: iframe 은 srcdoc + `sandbox="allow-scripts"` 이고, 서버 앱 페이지 CSP 와 데스크톱 앱 CSP 의 `script-src` 에 부트스트랩 해시와 `blob:` 을 더한다(부트스트랩이 위젯 코드를 iframe 안 blob 스크립트로 실행). 별도 `frame.html` 은 샌드박스 iframe 이 서비스 워커를 타지 않아 오프라인·기기 볼트에서 열리지 않고 데스크톱 앱에서는 앱 CSP 에 막혀 버렸다. 부트스트랩이 바뀌면 해시가 어긋나 실패하게 한다.
- **CSP 배경**: 데스크톱 앱(`app/src-tauri/tauri.conf.json` 의 `security.csp`)에 `frame-src` 가 없어 `default-src 'self'` 를 따른다. 서버가 거는 보안 헤더(`server/src/app.ts` 의 앱 페이지 헤더)도 함께 본다. srcdoc iframe 이 부모 CSP 를 물려받는 규칙 때문에 iframe 안 스크립트가 막힐 수 있다 — 구현에서 실제 엔진(Chromium·WebKit/Tauri)으로 재고 고른 방법을 문서에 적는다.
- 기기 볼트(`?local`)·데스크톱 앱·모바일에서 모두 돈다 — 내장 위젯은 앱 번들에 있으니 서버가 필요 없다.
- 화면 글은 `packages/core/src/messages/{en,ko}.json`. 위젯 이름·위젯 안 글도 같은 묶음(내장 위젯).
- 에이전트(MCP)는 블록을 JSON 원문으로 본다. 에이전트가 블록을 고치는 것은 막지 않는다.

## 단계

1. **런타임 + D-day**: 블록 파서·직렬화(순수 함수, core), 레지스트리, Live Preview·미리보기 인라인 호스트, 상태가 바뀌는 길 전부, 「위젯 넣기」, 없을 때·깨졌을 때, D-day 위젯, 빌드 크기 시험.
2. **iframe 호스트 + Excalidraw**: 부트스트랩·메시지 다리, CSP, 높이·포커스·테마·전체 화면, 데이터 파일 API, Excalidraw 위젯(처음 쓸 때만 불러옴). D-day 를 iframe 연결로도 돌리는 시험(두 연결이 같음을 지킨다).

## 구현자에게 맡기는 것

- D-day 의 모양과 상태 스키마(`targetDate`·`label` 은 예시 — 사용자 예시를 따르되 세부는 구현자). 지난 날짜 표시(D+N).
- 레지스트리의 파일 자리, 부트스트랩의 실제 메시지 형식.
- Excalidraw 번들을 iframe 에 싣는 방법(빌드 산출물, 크기, 처음 쓸 때만 받기)과 라이선스 고지(`docs/guides/development.md` 「의존성과 라이선스 고지」).
- 위젯 머리(「원문으로 편집」·전체 화면) 모양.

## 검증

- core 시험: 파서·직렬화(엄격 JSON, 예약 키 순서, 한 줄/여러 줄, 원문 보존, migrate, 판이 높을 때), 데이터 파일 경로 검사.

- 화면: Live Preview·미리보기·나란히 보기·같은 문서 두 칸, 한글 입력, 밝은·어두운, 390px·터치, `?local`, 데스크톱 앱(WebKit — iframe CSP 때문에 필수), iframe 이 앱 `document`·`localStorage`·`fetch` 에 닿지 못함.
