# 화면 분할: 두 칸에서 문서 편집 — 설계

Oct 12, 2026

`docs/ops/ux.md` 「8. 화면 분할」 의 남은 부분이다. 지금은 가운데 오른쪽에 **읽기 전용 "옆 칸"** 만 띄울 수 있다. 이 설계는 가운데를 **편집 가능한 두 칸**으로 나누고, 칸마다 자기 탭을 갖게 한다.

사용자가 질문 없이 설계만 요청해 **설계자의 판단으로 정한 것**이 많다. 그런 자리는 「(판단)」 으로 표시했다. 사용자가 명시한 것은 `ux.md` 의 8번 제안 네 줄뿐이다.

## 의도

두 문서를 나란히 두고 **둘 다 고치는** 일이 되게 한다. 한쪽을 보며 다른 쪽에 옮겨 쓰기, 데일리 노트를 열어 둔 채 본문 문서 고치기, 같은 문서의 앞뒤를 동시에 보기. 지금은 옆 칸이 읽기 전용이라 그때마다 탭을 오가야 한다.

## 목표

- 가운데를 **좌우 두 칸**으로 나눈다. 칸마다 **자기 탭 바·제목 칸·에디터·보기 모드**(편집·미리보기·나란히)를 가진다.
- 링크를 `Mod+클릭` 하면 **다른 칸**에서 연다(칸이 없으면 만든다). 탭은 칸 사이로 **끌어 옮기고**, 메뉴·명령으로도 옮긴다.
- **같은 문서를 두 칸에 열면 원본은 하나**다. 한쪽에서 치면 다른 쪽에 바로 보인다. 자동 저장·충돌·되돌리기는 문서 단위로 한 번만 돈다.
- 칸 경계를 끌어 크기를 바꾸고, 칸을 닫는다. 어느 칸이 **활성**인지가 상태 표시줄·오른쪽 패널·명령(저장·탭 닫기)의 대상을 정한다.
- 열린 칸·탭 배치는 지금 탭처럼 **워크스페이스 범위마다 이 기기에 기억**한다.
- 지금의 읽기 전용 "옆 칸"(`AsidePreview`)은 **없앤다.** 「같은 문서를 미리보기로 옆에 띄우기」는 둘째 칸을 **미리보기 모드**로 여는 것으로 대신한다(사용자 제안 세 번째 줄의 뜻을 이렇게 흡수한다 — 판단).

## 하지 않는 것

- 위아래 분할, 세 칸 이상, 칸 안의 칸. 좌우 두 칸만이다. (사용자 제안의 "필요하면 위아래"는 이번 범위 밖 — 판단)
- 좁은 화면(폭 800px 이하, 지금 `narrow` 판정)의 분할. 좁아지면 두 칸을 **하나로 합친다**(아래 「좁은 화면」).
- 두 칸의 스크롤 맞추기, 같은 문서 두 칸의 접힘 상태 동기화.
- 서버·코어·에이전트 API 변경. 전부 웹 화면 안의 일이다. `?local`(브라우저 로컬 볼트)·데스크톱·모바일 앱은 같은 웹 코드를 쓴다.

## 실패로 치는 것

- **같은 문서가 두 칸에서 서로 다른 초안을 가지는 것.** 한쪽이 다른 쪽을 덮어쓰면 글이 사라진다. 원본이 하나여야 한다.
- 같은 문서에 자동 저장 타이머가 둘 돌아 `409` 충돌을 스스로 만드는 것.
- 칸을 닫거나 좁은 화면으로 바뀔 때 저장 안 한 초안이 사라지는 것.
- 분할하지 않은 사람에게 지금 화면이 달라 보이는 것. 한 칸일 때는 지금과 같아야 한다.

## 지금 구조와 바꿀 것

지금 `Workspace.tsx` 는 **문서 하나**를 전제로 한 상태를 여럿 가진다 — `doc`(`OpenDoc`), `saveState`, `conflict`, `revision`, `commits`, `cursor`, `editorHandle`, `mode`. 탭은 `tabsByScope`(`keyring:tabs`, 범위 → 경로 배열)이고, 저장 안 한 탭의 내용은 `tabCache`(경로 → `OpenDoc`)에 남겨 둔다. 옆 칸은 `aside: string | null` 하나다.

바꾸는 것은 두 층이다.

### 열린 문서 저장소 (문서 단위)

`tabCache` 를 키워 **열린 문서 전부**의 원본으로 삼는다. 경로 → `{ doc: OpenDoc, saveState, conflict }`. 지금 `doc`·`saveState`·`conflict`·`tabCache` 네 상태를 이것 하나로 합친다.

- `OpenDoc` 의 모양(`saved`·`hash`·`draft`·`seq`·`generated`·`cachedOffline`·`virtual`)은 그대로다.
- **자동 저장은 문서마다 타이머 하나.** 초안이 바뀌면 그 경로의 타이머만 다시 건다. 창 포커스 이탈·탭 숨김 때는 **초안이 다른 문서 전부**를 저장한다(지금은 하나).
- `Mod+S` 는 활성 칸의 문서를 저장한다.
- 충돌(`conflict`)은 문서의 것이다. 같은 문서를 두 칸에 열었으면 **두 칸 모두**에 충돌 배너가 뜨고, 어느 쪽에서 풀어도 같이 풀린다.
- 이력 목록(`commits`)은 문서마다 둔다. 활성 칸의 문서만 불러오면 된다(지연 로드).
- 이동·이름 바꾸기·삭제가 오면 저장소의 키와 모든 칸의 탭을 함께 고친다(지금 `aside === from → setAside(to)` 와 탭 이름 바꾸기 처리를 일반화).

### 칸 배치 (화면 단위)

```ts
interface Pane {
  tabs: string[];        // 이 칸의 탭(문서 경로)
  active: string | null; // 이 칸에서 보고 있는 탭
  mode: ViewMode;        // 편집·미리보기·나란히 — 칸마다
}
interface Layout {
  panes: Pane[];         // 길이 1 또는 2. 왼쪽이 [0]
  focused: 0 | 1;        // 활성 칸
}
```

- 범위(워크스페이스 또는 `*`)마다 하나씩, 이 기기 `localStorage` 에 둔다. **키는 새로 `keyring:panes`** 로 하고, 처음 읽을 때 옛 `keyring:tabs`(경로 배열)가 있으면 `panes: [{ tabs, active: 마지막 문서, mode }]` 로 옮긴 뒤 옛 키를 지운다. (판단 — 모양이 달라져 같은 키를 덮어쓰면 옛 판으로 돌아갈 때 깨진다.)
- 칸의 탭이 모두 닫히면 **그 칸이 사라진다.** 두 칸이 모두 비면 지금처럼 홈이다. 왼쪽이 비고 오른쪽만 남으면 오른쪽이 왼쪽 자리로 온다.
- `revision`(과거 판 보기), `cursor`, `titleFocus`, `pendingAnchor`(열면서 갈 제목·블록)는 **칸의 것**이다 — 문서가 아니라 보는 자리에 붙는다.
- 오른쪽 패널(개요·연결·속성·이력)과 상태 표시줄(저장 상태·커서·글자 수)은 **활성 칸의 문서**를 따른다. 활성 칸은 클릭·포커스로 바뀐다.

### 같은 문서를 두 칸에

에디터(`Editor.tsx`, CodeMirror)는 칸마다 하나씩 뜬다. 같은 문서가 양쪽에 있으면 **한쪽의 변경(ChangeSet)을 다른 쪽 뷰에 그대로 전달**한다.

- 전달한 트랜잭션에 표식(annotation)을 붙여 되돌아오지 않게 한다.
- 받는 쪽은 `addToHistory: false` 로 받아, 그 칸의 되돌리기(`Mod+Z`)는 **그 칸에서 친 것만** 되돌린다. CodeMirror 의 이력은 사이에 끼어든 변경을 거쳐 위치를 다시 맞춰 주므로 두 칸이 번갈아 쳐도 안전하다.
- 저장소의 `draft` 는 어느 쪽이 쳤든 한 값이다. 자동 저장은 문서 타이머 하나만 돈다.
- 다시 읽어 와 내용을 통째로 바꾸는 경우(충돌 해결, 되돌리기, 서버 변경 반영)는 지금처럼 `seq` 를 올려 **두 에디터를 모두** 다시 만든다.
- 접힘 상태(`foldKey`, 경로별·이 기기)는 두 뷰가 같은 키를 쓰고 마지막에 바뀐 쪽이 남는다. 받아들이는 한계다(「하지 않는 것」).

### 링크·명령·단축키

| 하는 일 | 지금 | 바뀐 뒤 |
| --- | --- | --- |
| 링크 클릭 | 같은 탭에서 열기 | **그 칸**에서 열기(지금과 같음) |
| 링크 `Mod+클릭` | 옆 칸 읽기 전용 | **다른 칸**에 새 탭으로 열기. 칸이 없으면 만든다 |
| `cmd.asideOpen` / `cmd.asideClose` (`Mod+\`) | 옆 칸 열기·닫기 | **「분할 열기·닫기」**로 이름을 바꾼다. 열기는 지금 문서를 다른 칸에도 연다(같은 문서 두 칸). 닫기는 다른 칸의 탭을 활성 칸으로 옮기고 칸을 없앤다 — 초안은 문서 저장소에 있으니 사라지지 않는다 |
| 새 명령 「탭을 다른 칸으로」 | 없음 | 활성 탭을 다른 칸으로 옮긴다. 칸이 없으면 만든다 |
| 새 명령 「다른 칸으로 포커스」 | 없음 | 활성 칸을 바꾼다 |
| 탭 오른쪽 클릭 메뉴 | 닫기 등 | 「다른 칸으로 옮기기」 추가 |
| 탭 끌기 | 없음 | 다른 칸의 탭 바에 놓으면 옮긴다 |

새 명령의 키는 `shortcuts.ts` 의 지금 명령과 겹치지 않는 것으로 **구현자가 고른다**(웹은 브라우저가 가져가는 키를 피해 대체 키를 둔다 — 지금 규칙). 명령 팔레트·툴팁·설정의 단축키 표에 자동으로 들어가야 하므로 `shortcuts.ts` 의 명령 목록에 등록한다.

### 크기·경계

- 두 칸 사이 경계를 끌어 비율을 바꾼다. 두 번 누르면 50%, 키보드 `←`·`→` 로도 움직인다(왼쪽·오른쪽 패널 경계와 같은 동작). 비율은 이 기기 `prefs` 에 기억한다(`keyring:prefs`, 기기마다 설정 — `ux.md` 「27. 화면 설정 동기화」 의 "기기마다" 쪽).
- 칸 하나의 최소 폭은 **280px**(지금 `.aside-pane` 의 `min-width`). 가운데 폭이 560px 보다 작으면 분할을 열 수 없고, 열려 있던 것은 합친다.

### 좁은 화면

`narrow`(폭 800px 이하)로 바뀌면 둘째 칸의 탭을 **첫째 칸 뒤에 이어 붙이고** 칸을 하나로 만든다. 활성 문서는 그대로 활성. 좁은 화면에서 「다른 칸에서 열기」·`Mod+클릭` 은 **새 탭 열기**로 동작한다. 다시 넓어져도 자동으로 다시 나누지 않는다(판단 — 어느 탭이 어느 칸이었는지 기억하는 가치가 복잡도보다 작다).

지금 좁은 화면의 `.aside-pane { position: fixed }` 규칙은 옆 칸과 함께 없어진다.

## 화면 글

- 새 키는 `packages/core/src/messages/{en,ko}.json` 에(키 정렬, 들여쓰기 1칸). 영어가 기준.
- `aside.*`·`cmd.aside*` 키는 쓰는 곳이 없어지면 지운다. 「분할 열기·닫기」·「탭을 다른 칸으로」·「다른 칸으로 포커스」·「다른 칸으로 옮기기」·칸 라벨(`aria-label`) 이 새로 필요하다.

## 구현자에게 맡기는 것

- 문서 저장소·칸 배치의 자료구조를 어디에 둘지(`Workspace.tsx` 안의 훅인지 별 모듈인지). 단, **칸 배치 연산은 순수 함수로 뺀다** — 열기·닫기·옮기기·합치기·옛 키 옮김. `web/src/stored.test.ts` 와 같은 vitest 로 검증할 수 있어야 한다.
- 두 에디터 사이 ChangeSet 전달의 구체(annotation 이름, 전달 지점이 `Editor` 안인지 밖인지).
- 탭 끌기의 시각 피드백(트리의 끌어 옮기기와 같은 결을 따른다).
- 새 명령의 기본 키.

## 검증

전부 구현자가 워크트리 안에서 한다. 보고에는 **실행 개수**를 적는다.

- `pnpm test`, `pnpm typecheck`, `pnpm build` 가 루트에서 통과. 칸 배치 순수 함수의 단위 테스트가 들어 있어야 한다(열기·닫기·옮기기·빈 칸 제거·좁은 화면 합치기·`keyring:tabs` → `keyring:panes` 옮김).
- 시험 서버(임시 `KEYRING_DATA`, 워크트리 전용 포트)와 `?local` 에서 브라우저로:
  - 한 칸일 때 지금 화면과 같다(탭·제목·상태 표시줄·오른쪽 패널).
  - 링크 `Mod+클릭` → 오른쪽 칸에 새 탭. 양쪽에서 각각 고치면 **각각** 자동 저장되고 상태 표시줄은 활성 칸을 따른다.
  - 같은 문서를 두 칸에 열고 한쪽에서 치면 다른 쪽에 바로 보인다. 저장은 한 번 돈다(네트워크 요청 1건). 되돌리기는 그 칸에서 친 것만 되돌린다.
  - 다른 기기(둘째 브라우저)에서 같은 문서를 고쳐 충돌을 내면 두 칸 모두에 배너가 뜨고, 한쪽에서 풀면 같이 풀린다.
  - 탭을 끌어 다른 칸으로, 메뉴로 다른 칸으로. 마지막 탭을 옮기면 빈 칸이 사라진다.
  - 둘째 칸의 마지막 탭을 닫으면 칸이 사라지고, 첫째 칸의 탭을 모두 닫으면 둘째 칸이 왼쪽으로 온다.
  - 경계 끌기·두 번 누르기·키보드. 새로고침 뒤 칸·탭·비율이 돌아온다.
  - 창을 800px 이하로 좁히면 한 칸으로 합쳐지고 초안이 남아 있다.
  - 어두운 테마, 390px 폭에서 가로 넘침이 없다.
- 끝나면 `docs/ops/ux.md` 「8. 화면 분할」 의 구현 현황 행을 "됨"으로 고치고 "옆 칸" 설명을 걷는다.
