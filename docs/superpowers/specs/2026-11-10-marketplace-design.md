# 마켓플레이스 — 위젯·테마·언어 받기 — 설계

Nov 10, 2026 · 기준 커밋 `32a25dd`

## 왜

노트 위젯(`keyring-widget`)·화면 색 테마·언어를 앱에 들어 있는 것 말고도 받아 쓰고 싶다(사용자). **공식으로 운영하는 마켓플레이스를 하나 제공하고, 누구나 자기 개인 마켓플레이스를 더해 쓸 수 있는 구조**다 — Maven 의 중앙 저장소와 개인 저장소처럼(사용자). 요청은 `docs/ops/ux.md` 「5차 요청 (2026-11-09)」 의 「마켓플레이스」 줄, 처음 관리 제안은 같은 절 「정한 것」 의 「마켓플레이스」.

지금 앱에는 이렇게 있다.

- **위젯:** 내장 위젯(D-day 인라인, Excalidraw iframe)만 레지스트리에 있다. iframe 위젯은 코드를 글로 받을 수 있다(`FrameCode` 의 `text`) — 받은 위젯을 그 자리에 실을 수 있다. 등록되지 않은 위젯 블록은 원문과 「찾을 수 없습니다」 를 보인다. 설계 `docs/superpowers/specs/2026-11-09-keyring-widget-design.md`.
- **테마:** 「시스템·밝게·어둡게」 셋뿐이다(`web/src/prefs.ts` 의 `theme`, `html[data-theme]`). 색은 `web/src/styles.css` 의 CSS 변수(`--bg`·`--fg`·`--accent`…)다. 사용자 정의 테마 체계는 없다.
- **언어:** 비공식 언어팩을 파일로 불러와 이 기기(`localStorage` `keyring:langpacks`)에 둔다(`web/src/i18n.ts`, `ux.md` 「26. 다국어」).
- **보안 정책:** 앱 페이지 CSP 의 `connect-src` 는 `'self'` 다 — 화면이 다른 주소로 요청하지 못한다.

## 범위

| 항목 | 이번에 | 정한 사람 |
| --- | --- | --- |
| 공식 마켓플레이스 하나 + 사용자가 더하는 개인 마켓플레이스 | 만든다 | 사용자 |
| 제출 심사·서명 | 만들지 않는다 | 사용자 |
| 받을 수 있는 것: 위젯·테마·언어 | 셋 다 | 사용자 |
| 테마는 색 토큰만 바꾼다 | 그렇게 한다 | 사용자(①) |
| 받기: 서버 모드는 서버가 받아 캐시하고 화면은 서버에서, 서버 없는 데스크톱 앱은 네이티브 HTTP | 그렇게 한다 | 사용자(A) |
| 저장소는 정적 파일(`index.json` + 패키지 파일), 서버 백엔드 없음 | 그렇게 한다 | 코디네이터 제안·사용자 이의 없음 |
| sha256 확인과 볼트 잠금(모든 기기가 같은 판) | 그렇게 한다 | 코디네이터 — 서명이 아니라 같은 파일 보장 |
| 받은 위젯은 모두 iframe | 그렇게 한다 | 위젯 설계의 기준 |
| 패키지를 만드는 CLI(공식·개인 저장소 둘 다 쓰는 것) | 만든다 | 코디네이터 |

**하지 않는 것(non-goals)**

- 제출 심사, 서명·출처 보증, 평점·검색 순위·다운로드 수(사용자).
- 테마가 글꼴·간격·레이아웃·임의 CSS 를 바꾸는 것(사용자 ①).
- 받은 위젯을 인라인으로 돌리는 것. 앱과 함께 빌드된 코드가 아니면 iframe 이다(위젯 설계 「인라인/iframe 기준」).
- 기존 ` ```widget `(YAML 쿼리 위젯)과 `/plugins/<이름>.js` 플러그인을 마켓 패키지로 옮기는 것. 그대로 둔다.
- 저절로 업데이트. 새 판은 알리기만 한다.
- 공식 마켓플레이스에 무엇을 올릴지는 이 설계 밖이다. 형식·CLI·**마켓 서버를 띄우는 Docker 구성과 문서**는 만든다(아래 「마켓 서버와 배포」).

**실패로 보는 것(anti-goals)**

- 웹 화면의 CSP(`connect-src 'self'`)를 넓히는 것.
- 기기마다 다른 판이 깔려, 같은 노트의 위젯이 기기마다 다르게 그려지는 것.
- 받은 파일의 sha256 이 목록과 다른데 쓰는 것.
- 패키지를 지우거나 저장소를 빼서 노트 내용이 사라지거나 고칠 길이 없어지는 것 — 위젯 블록은 늘 원문으로 남는다.
- 테마가 앱을 읽을 수 없게 만드는 것(대비 깨짐)을 되돌릴 길이 없는 것 — 언제든 기본 테마로 돌아갈 수 있어야 한다.
- 오프라인이 된 뒤 이미 깐 위젯·테마·언어가 사라지는 것.

## 접근 방식

| 안 | 내용 | 대가 | 결정 |
| --- | --- | --- | --- |
| A | 서버 모드는 서버가 받아 sha256 확인·캐시하고 화면은 같은 출처에서 받는다. 서버 없는 데스크톱 앱은 네이티브 HTTP(`tauri-plugin-http`, CSP 밖)로 받는다 | 서버에 받기·캐시가 늘고, 서버에서 저장소로 나가는 연결이 필요하다 | **골랐다** |
| B | 기기마다 화면이 직접 받는다 | 웹 CSP `connect-src` 를 `https:` 로 넓혀야 한다, 기기마다 받는다, 저장소 CORS 에 기댄다 | 앱 전체 방어선이 약해져 버림 |
| C | 패키지 파일을 볼트에 넣어 동기화로 퍼뜨린다 | 볼트·Git 이력이 코드·바이너리로 부푼다, 마크다운이 아닌 파일은 서버 → 기기 한 방향 동기화 | 버림 |

## 저장소 형식

정적 파일로 어디에나(GitHub Pages·아무 웹 서버) 올린다. 저장소 주소 `<repo>` 아래:

```
<repo>/index.json
<repo>/packages/<scope>/<name>/<version>/<파일들>
```

`index.json`:

```json
{
  "format": 1,
  "name": "Keyring 공식",
  "packages": {
    "@keyring/pomodoro": {
      "type": "widget",
      "versions": {
        "1.2.0": {
          "engines": { "keyring": ">=0.13.0" },
          "files": [
            { "path": "keyring-package.json", "sha256": "…", "size": 812 },
            { "path": "frame.js", "sha256": "…", "size": 20480 }
          ]
        }
      }
    }
  }
}
```

- `index.json` 의 판마다 선택 필드 `name`(언어별)·`description`(언어별)·`author`·`license` 를 둘 수 있다 — `pkg index` 가 매니페스트에서 옮겨 쓴다. 둘러보기 표시용일 뿐이고, 설치 판정·적용은 sha256 을 확인한 매니페스트가 원본이다. 저장소마다 요청 하나로 둘러보기를 그린다. — 코디네이터
- 패키지는 묶음 파일(zip 등)이 아니라 **파일마다 sha256** 이다 — 정적 호스팅에 그대로 올리고, 받는 쪽이 압축을 풀 필요가 없다. — 코디네이터
- `id` 는 `@<scope>/<name>`(소문자·숫자·`-`). 위젯 블록의 `widget` 은 이 id 와 상태 판을 쓴다(`@keyring/pomodoro@1`). 내장 위젯의 `keyring/…` 와 겹치지 않게 범위 앞에 `@` 를 둔다.
- `version` 은 semver. `engines.keyring` 은 앱 판 범위 — 설치하는 기기(서버 모드면 서버, 서버가 곧 화면의 판)의 판과 맞지 않으면 설치하지 않는다. 잠금으로 이미 깔린 판이 **어떤 기기의 앱 판과 맞지 않으면 그 기기에서만** 위젯 자리에 원문과 「앱을 업데이트해야 이 위젯이 보입니다」, 테마·언어는 기본으로 보인다 — 잠금은 바꾸지 않는다(다른 기기의 판을 끌어내리지 않는다). — 코디네이터
- **범위 `@keyring` 은 공식 저장소에서만 받는다.** 다른 저장소의 `index.json` 에 `@keyring/…` 가 있으면 무시한다(개인 저장소가 공식 패키지를 같은 id 로 가리지 못하게). 그 밖의 id 가 여러 저장소에 있으면 설치 화면이 「다른 저장소에도 같은 id 가 있음」 을 보이고, 설치 뒤에는 잠금의 `repo` 가 고정한다(우선순위가 바뀌어도 다른 저장소로 넘어가지 않는다). — 코디네이터

### 매니페스트 `keyring-package.json`

| `type` | 필수 파일 | 내용 |
| --- | --- | --- |
| `widget` | `frame.js`, 선택 `frame.css`·`messages/<lang>.json` | 매니페스트 안 `widget`: `stateVersion`(상태 판, 정수 — 패키지 `version` 과 다르다)·`display`·`dataFile`·`defaultState`(JSON 값). `isolation` 은 늘 `frame` |
| `theme` | — | 매니페스트 안 `colors.light`·`colors.dark`: 토큰 → 색 값. 한쪽만 있어도 된다 |
| `language` | `messages.json` | 지금 언어팩 형식(`meta`·`messages`) 그대로 |

공통: `id`·`version`·`type`·`name`(언어별)·`description`·`author`·`license`·`engines`.

- **위젯 패키지의 파일은 `frame.js`·`frame.css`·메시지뿐이다(`format: 1`).** 그림·글꼴 같은 자산은 JS·CSS 안에 넣어(data URL·`ArrayBuffer` 글꼴) 온다 — 지금 iframe 호스트(`FrameCode` 의 `text` 꼴)와 iframe CSP 가 그대로 받는다. 자산 파일이 필요해지면 `format: 2` 로 넓힌다. — 코디네이터
- **받은 위젯의 `migrate` 는 iframe 안에서 돈다.** 블록의 상태 판이 낮으면 호스트는 옛 상태와 판을 `init` 에 그대로 넘기고, `frame.js` 가 등록한 `migrate` 로 올린 상태를 그 안에서 쓴다. 파일에는 다음 적용 때 새 판으로 쓴다(위젯 설계의 규칙 그대로). 인라인 내장 위젯의 동기 `migrate` 는 바꾸지 않는다. — 코디네이터

### 테마 토큰

- 테마가 바꿀 수 있는 것은 **앱이 정한 색 토큰 목록뿐**이다(예: `--bg`·`--bg-soft`·`--fg`·`--muted`·`--accent`·`--border`·`--hover`·`--active`·`--focus`·`--danger`·`--success`·…). 목록과 각 토큰의 뜻은 구현에서 `styles.css` 의 실제 변수를 보고 고정하고 사용자 문서에 싣는다. 크기·글꼴·간격 변수(`--fs-*`·`--font-*`·`--radius-*`·`--*-h`·`--*-w`)는 넣지 않는다.
- 값은 색만 받는다(`#rgb`·`#rrggbb`·`#rrggbbaa`·`rgb()`·`hsl()`·`oklch()` 의 엄격한 꼴). `url(`·`var(`·`;`·`}` 가 든 값은 거부한다 — CSS 주입을 막는다.
- 적용은 `html[data-theme]` 와 같은 자리에 토큰 값만 덮는다. 테마에 없는 토큰은 기본 테마 값.
- 화면 설정에서 테마를 「밝게·어둡게·시스템」 과 받은 테마 중에서 고르고, 받은 테마는 밝음·어두움 중 가진 쪽으로 그린다. 고르기는 지금 화면 설정 동기화(공통 → 이 기기에서만 다르게)를 따른다.
- 본문 글과 배경의 대비가 4.5:1 보다 낮으면 설치·고를 때 경고한다(막지는 않는다). 설정에 「기본 테마로 돌아가기」 가 늘 보인다.

## 설정과 잠금

공통 설정 파일 `keyring-settings.md`(프런트매터, 모든 기기가 양방향 동기화)에 둔다. — 코디네이터

```yaml
marketplace:
  repos:
    - url: https://market.keyring.example/   # 공식 — 기본값, 지울 수 있음
    - url: https://me.github.io/my-widgets/
  packages:
    "@keyring/pomodoro": { version: 1.2.0, repo: https://market.keyring.example/, sha256: { keyring-package.json: …, frame.js: … } }
```

- 저장소 목록은 순서가 우선순위다. 같은 id 가 여러 저장소에 있으면 위의 것. 설치하면 잠금에 받은 저장소를 적어, 이후엔 그 저장소에서만 받는다.
- 잠금(`packages`)이 모든 기기에서 같은 판·같은 파일(sha256)을 고정한다. 기기는 잠금에 있는데 캐시에 없는 패키지를 받아 온다.
- 공식 저장소 주소는 앱 판에 박힌 기본값 **`https://keyring-notes-marketplace.develma.com/`** 이다(사용자). 첫 실행에 `repos` 가 없으면 공식 하나로 시작한다. 공식 주소도 `https:` 다 — `http:` 는 운영자 환경 변수 없이는 받지 않으므로, TLS 는 마켓 서버 앞의 리버스 프록시가 붙인다.
- **잠금이 원천이다.** 설치 화면을 거치지 않고 들어온 항목(사람이 파일을 고침, 다른 기기에서 동기화로 옴)도 서버·기기가 받는다 — 잠금이 바뀌는 것을 볼 때마다 캐시와 맞춘다(없는 것은 받고 빠진 것은 지운다). 항목의 `repo` 가 `repos` 에 없어도 그 주소에서 받는다(잠금이 기록이다). sha256 이 다르면 쓰지 않고 오류로 보인다. — 코디네이터
- **공통 설정 병합에서 `marketplace.packages` 의 항목 하나(`id` 아래 통째)를 잎 하나로 합친다.** 지금 병합(`packages/core/src/settingsMerge.ts`)은 잎 값마다 3방향이라 두 기기가 동시에 업데이트하면 한쪽 `version` 과 다른 쪽 `sha256` 이 섞일 수 있다. 같은 항목을 두 쪽이 다르게 바꿨으면 판이 높은 쪽을 고르고, 「이 기기에서만 다르게」 로 남기지 않는다(`marketplace` 는 기기별 덮어쓰기가 없다). — 코디네이터
- **한 기기에서 제거하고 다른 기기에서 업데이트한 것이 겹치면 업데이트가 이긴다**(다시 깔린다) — 사용자. 제거가 이기면 그 위젯을 쓰던 블록이 다른 기기에서 갑자기 「찾을 수 없음」 이 된다. 원하지 않으면 다시 지우면 된다.

## 받기와 캐시 (사용자 결정 A)

- **서버 모드**: 서버가 `<KEYRING_DATA>/packages/<id>/<version>/` 에 받아 둔다. 받을 때 파일마다 sha256 을 잰다 — 다르면 버리고 오류. 화면은 서버 API 로 목록·설치·제거를 하고, 파일은 서버의 같은 출처 주소에서 받는다. 저장소 목록(`index.json`)도 서버가 받아 준다(캐시, 짧은 유효 시간).
- **서버 없는 데스크톱 앱(기기 볼트)**: 네이티브 HTTP 로 직접 받아 앱 데이터 폴더에 같은 구조로 둔다.
- **기기 볼트 + 서버 동기화**: 잠금은 동기화로 오고, 파일은 서버에서 받는다(서버 캐시를 쓴다).
- **화면 쪽 캐시**: 받은 파일은 기기에 남겨(서비스 워커 캐시 또는 앱 데이터) 오프라인에서도 쓴다.
- 서버에서 저장소로 나가는 요청은 `https:` 만, 크기 상한(패키지 하나·파일 하나), 시간 제한. **`http:`·사설 IP 는 서버 운영자 설정(환경 변수)으로 켤 때만**(개인 저장소를 집 안에 둘 때). 볼트의 공통 설정에 두지 않는다 — 볼트를 고칠 수 있는 기기나 사람이 서버를 내부망으로 보내는 통로가 되지 않게. — 코디네이터
- 데스크톱 앱의 네이티브 받기도 같은 규칙이다: `https:` 만, `http:`·사설 IP 는 그 기기의 설정(이 기기에서만, 동기화되지 않음)으로 켤 때만. 앱의 HTTP 권한(capabilities)도 마켓 받기에 필요한 만큼으로 좁히는지 구현에서 본다. — 코디네이터
- **모드별로 누가 받는가** — 코디네이터:

  | 모드 | 받는 쪽 |
  | --- | --- |
  | 서버 모드(웹·모바일·데스크톱 앱이 서버 화면) | 서버(소유자 로그인) |
  | 데스크톱 앱 기기 볼트 + 서버 동기화 | 서버에 받게 하고 동기화와 같은 인증으로 서버 캐시에서 가져온다. 서버가 실패(저장소에 닿지 못함·사설 IP 거부 등)하면 앱의 네이티브 받기로 대신한다 |
  | 데스크톱 앱 기기 볼트(서버 없음) | 앱의 네이티브 받기 |
  | 브라우저 기기 볼트(`?local`·설치한 PWA) + 서버 동기화 | 서버 캐시(동기화와 같은 인증) |
  | 브라우저 기기 볼트, 동기화 없음 | 받지 않는다 — 마켓 화면에 「서버 동기화를 연결하거나 데스크톱 앱에서 받을 수 있습니다」. 이미 캐시에 있는 것은 쓴다 |

## 설치·제거·업데이트 화면

- 설정 → **마켓플레이스**: 저장소 목록(더하기·빼기·순서), 패키지 둘러보기(종류별, 이름·설명·작성자·라이선스·판), 설치·제거, 「새 판 있음」 과 업데이트.
- **위젯 설치 때 알림**: 「이 위젯은 격리되어 앱·노트에 닿지 못하지만, 외부와 통신할 수 있습니다(WebRTC)」 — iframe 안 WebRTC 는 CSP 로 막지 못한다(위젯 2단계의 알려진 한계).
- **등록되지 않은 위젯 블록**: 「위젯 `<id>` 를 찾을 수 없습니다」 옆에 「설치」 — 저장소 목록에서 그 id 를 찾으면 설치 화면으로.
- 제거하면 잠금에서 빼고 캐시를 지운다. 그 위젯을 쓰는 블록은 원문과 「설치」 로 돌아간다. 고른 테마·언어가 지워지면 기본으로 돌아간다.
- 위젯 패키지의 상태 판이 올라갔으면 위젯 설계의 `migrate` 규칙을 따른다(매니페스트가 iframe 쪽 `migrate` 를 준다).

## 패키지 CLI

공식과 개인 저장소 둘 다 쓴다. — 코디네이터

- `pnpm keyring pkg check <폴더>`: 매니페스트·필수 파일·테마 색 값·언어 키 검사.
- `pnpm keyring pkg index <저장소 폴더>`: `packages/` 를 훑어 sha256·크기를 재고 `index.json` 을 다시 만든다(멱등).
- 위젯 `frame.js` 를 만드는 빌드는 작성자 몫이다. 사용자 문서에 최소 예(위젯 런타임 API 와 `keyringWidgetRegister`)를 둔다.
- **CLI 를 쓰는 길: 이 저장소를 클론해서, 또는 배포 Docker 이미지 안에서**(`docker compose exec … pnpm keyring pkg …`). npm 에 따로 배포하지 않는다. 대신 `index.json`·매니페스트 형식을 사용자 문서에 전부 실어, CLI 없이 손이나 다른 도구로도 저장소를 만들 수 있게 한다. — 코디네이터

## 마켓 서버와 배포 (사용자 요청)

마켓 구성 방법을 문서로 남기고, 프로젝트 배포 지침(`docs/guides/deploy-docker.md`, `docs/guides/deploy-komodo.md`, komodo 스택 지침)에 따라 Docker 로 띄울 수 있게 한다.

- **마켓 서버 이미지**: 패키지 폴더를 받아 `index.json` 을 만들고(`pkg index`, 멱등) 정적 파일로 내주는 컨테이너 하나. 이 저장소의 코드로 빌드한다(`pull_policy: build`, 레지스트리에 게시하지 않는다). 내줄 때 `index.json` 은 짧은 캐시, 패키지 파일은 판마다 바뀌지 않으므로 긴 캐시. 패키지 폴더가 바뀌면 다시 만든다(시작 때와 바뀜 감지 또는 주기). 정적 서버를 무엇으로 할지(앱 서버 CLI 의 `pkg serve` 또는 작은 정적 서버)는 구현자 몫 — 앱 이미지·툴체인을 늘리지 않는 쪽.
- **compose**: 이 저장소에 마켓용 compose 파일을 따로 둔다(앱의 `docker-compose.yml` 과 섞지 않는다). 리버스 프록시·TLS 는 넣지 않는다(배포 지침 「저장소가 갖는 것과 갖지 않는 것」) — 운영자가 서버의 override 로 프록시 네트워크에 붙인다. `container_name` 을 쓰지 않는다.
- **공식 패키지의 자리**: 이 저장소 `marketplace/packages/<scope>/<name>/<version>/`. 이미지가 그것을 싣는다. 공식 마켓은 이 저장소로 만든 Stack 을 재배포해 갱신한다. — 코디네이터. 2026-11-11 사용자 결정으로 별도 저장소로 옮김: 마켓 서버 구성은 keyring-notes-marketplace 가 갖고, 공식 패키지는 어느 저장소에도 두지 않고 서버에서 따로 관리한다.
- **개인 마켓**: 같은 이미지에 자기 패키지 폴더를 마운트해 덮는다. 또는 `pkg index` 로 만든 폴더를 아무 정적 호스팅에나 올린다.
- **문서**:
  - 사용자 문서 `docs/manual/{en,ko}/how-to/` 에 「내 마켓플레이스 운영하기」 — 패키지 폴더 구성, `pkg check`·`pkg index`, Docker 로 띄우기, 프록시·TLS 를 붙이는 법(https 가 필요한 이유), 앱에서 저장소를 더하기. 「패키지 만들기」 — 매니페스트·종류별 파일·위젯 `frame.js` 최소 예·테마 토큰 표·언어 형식. 설정 표(`configuration.md`)에 마켓 서버 환경 변수.
  - 개발 문서 `docs/guides/` 에 공식 마켓 배포 — Komodo Stack 설정 표(서버별 값은 적지 않는다), 갱신 절차.

## 제약

- 웹 CSP 는 그대로다(`connect-src 'self'`).
- 받은 위젯은 위젯 설계의 iframe 규칙(출처 검사·자기 탐색 차단·데이터 파일 하나만)을 그대로 탄다.
- 화면 글은 `packages/core/src/messages/{en,ko}.json`, 사용자 문서는 `docs/manual/{en,ko}/` 같은 커밋. 서버 API 를 바꾸면 `reference.md`·llms.txt(`docs/guideline/web/00-llms-txt.md`).
- 기존 비공식 언어팩(이 기기 `localStorage`)은 계속 불러올 수 있다. 마켓에서 받은 언어는 잠금을 따라 모든 기기에 깔린다.

## 단계

1. **형식과 서버 받기**: 저장소 형식·매니페스트 검사(core), 패키지 CLI, 공통 설정의 `marketplace`, 서버 받기·sha256·캐시·API, 데스크톱 앱 네이티브 받기.
2. **언어와 테마**: 언어 패키지 설치·적용, 테마 토큰 체계·검사·적용·대비 경고·기본으로 돌아가기, 설정의 마켓플레이스 화면.
3. **위젯**: 받은 위젯을 레지스트리에 iframe 으로, 「설치」 단추, WebRTC 알림, 제거·업데이트.

## 구현자에게 맡기는 것

- 테마 토큰의 정확한 목록과 이름(위 원칙 안에서).
- 서버 API 경로·캐시 유효 시간·크기 상한 값.
- 화면 쪽 오프라인 캐시 방법(서비스 워커·IndexedDB·앱 데이터).
- 마켓플레이스 화면 모양.
- 공식 저장소 주소의 기본값(설정 상수 하나로).

## 검증

- core 시험: 매니페스트·`index.json` 검사, id·semver·engines, 테마 색 값 검사(주입 거부), sha256 대조, 잠금 직렬화.
- server 시험: 받기·sha256 불일치 거부·캐시·크기 상한·`https:` 만·사설 IP 거부·API 권한(소유자만 설치·제거).
- web 시험: 테마 적용·기본으로 돌아가기, 언어 패키지 적용, 위젯 「설치」 흐름, 제거 뒤 블록 원문.
- 화면: 서버 모드(웹)·기기 볼트(데스크톱 앱)·오프라인에서 이미 깐 것, 두 기기에서 같은 판, 밝은·어두운 테마 패키지, 390px.
