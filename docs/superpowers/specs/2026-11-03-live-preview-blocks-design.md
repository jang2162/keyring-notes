# Live Preview 에서 원문으로 남던 요소 그리기 + 표 편집기 — 설계

Nov 3, 2026 · 기준 커밋 `8b22590`

## 왜

편집 화면(Live Preview)이 기본 편집 화면인데, 구분선·인용·목록 글머리·할 일·코드 블록·표·줄 안 `![](이미지)`·HTML 블록은 마크다운 기호째로 보이고 미리보기(`Ctrl/Cmd+E`)로 넘어가야 그려진다. 사용자는 편집 중에도 완성된 모양을 보고 싶어 한다(요청: 「Live Preview 에서 지원 안하는 요소들 지원 하도록 해줘」). 표는 그리는 데서 그치지 않고 **그려진 표에서 바로 고치는 표 편집기**로 만든다(사용자).

지금 이것들이 원문인 것은 결정이 아니라 남은 한계다 — `docs/ops/ux.md` 「2차 남은 것·알려진 한계」 의 「Live Preview는 표·목록 글머리·HTML은 원문 그대로다」, 사용자 문서 `docs/manual/{en,ko}/how-to/edit-notes.md` 「Live Preview」 의 「코드 블록과 표는 원문으로 보입니다」.

## 범위

| 항목 | 이번에 | 정한 사람 |
| --- | --- | --- |
| 1. 구분선 `---`·`***`·`___` | 가로줄로 그린다 | 사용자(요청) |
| 2. 인용 `>`(콜아웃이 아닌 것) | 왼쪽 막대로, `>` 숨김 | 사용자(요청) |
| 3. 목록 글머리 `-`·`*`·`+` | 점(•)으로 | 사용자(요청) |
| 4. 할 일 `- [ ]`·`- [x]` | 누를 수 있는 체크박스 | 사용자(요청) |
| 5. 코드 블록 | 펜스 줄을 숨기고 상자로, 안쪽 코드는 그 자리에서 고침 | 사용자(요청), 방식은 코디네이터 제안·사용자 이의 없음 |
| 6. 표 | **표 편집기** — 칸마다 편집기(아래), 열 정렬, 행·열 끌어 옮기기, sort | 사용자 |
| 7. 줄 안 `![글](주소)` | 그림으로 | 사용자(요청) |
| 8. HTML 블록 | 그린 결과로 | 사용자(요청) |
| 9. 코드 블록 언어별 색 | 미리보기에도 칠하고, 편집 화면과 같은 테마 색으로 | 사용자(요청), 방식은 코디네이터 |

**하지 않는 것(non-goals)**

- 새 표 만들기 명령(「표 넣기」), 표 붙여넣기 변환(엑셀·CSV → 마크다운 표). 사용자가 묻지 않았다. 표는 지금처럼 원문으로 쳐서 만들고, 형식이 맞으면 그 순간부터 편집기로 그려진다.
- 콜아웃·인용·목록 **안의** 표. 이것들은 지금처럼 그 바깥 블록의 위젯(콜아웃)이나 원문으로 보인다. 표 편집기는 줄 맨 앞에서 시작하는(문서 최상위) GFM 표만 다룬다.
- 칸을 합치기(colspan), 칸 안 여러 줄 문단. GFM 표에 없다.
- 줄 안 HTML(`<span>` 등)을 그리기. 블록 HTML 만 그린다.
- 번호 목록의 번호 꾸미기. 번호는 글자 그대로 둔다.
- 미리보기(`markdown.ts` 의 `renderMarkdown`) 동작 변경. 미리보기는 이미 다 그린다.

**실패로 보는 것(anti-goals)**

- **한글 입력(IME)이 깨지는 것** — 칸 편집기에서 조합 중 글자가 사라지거나 두 번 들어가거나, 조합 중에 다른 칸으로 튀는 것.
- **표를 고쳤는데 고치지 않은 줄까지 파일에서 바뀌는 것.** 칸 글을 고치면 그 칸만, 행을 넣거나 지우거나 옮기면 그 행 줄만 바뀌어야 한다(열 작업은 성질상 모든 행 줄이 바뀐다). 표 전체를 다시 써 `|` 사이 공백을 맞추지 않는다 — 저장마다 Git 이력에 표 전체가 바뀐 것으로 남기 때문이다(사용자 동의).
- 실행 취소가 표와 본문에서 따로 노는 것. 칸 안에서 친 것도 `Ctrl/Cmd+Z` 한 줄기로 되돌아가야 하고, 본문에서 친 것과 순서가 섞이지 않아야 한다.
- 같은 문서를 연 다른 칸(`mirror.ts`)·다른 기기 합치기로 문서가 바뀌었을 때 표가 옛 내용을 보이거나, 편집 중인 칸의 커서를 잃는 것.
- 큰 표(수백 칸)에서 타이핑이 눈에 띄게 느려지는 것.
- 읽기 전용 편집기(생성된 노트, 이력 보기, 워크스페이스 문서 — `DocPane.tsx` 의 `readOnly`)에서 표·체크박스로 파일이 바뀌는 것.

## 지금 코드

- 편집기: `web/src/Editor.tsx`. CodeMirror 6, `markdown({ base: markdownLanguage })`(lezer 마크다운 + GFM: `Table`·`Task`·`Strikethrough`), `history()`, `autocompletion({ override: [wikilinkSource(...)] })`, 키맵 `Mod-b`/`Mod-i`/`Mod-k`/`Mod-Shift-h`/`Mod-Enter`(할 일 토글 `toggleTaskLine`). Live Preview 는 `liveSlot` Compartment 로 `livePreview(getCtx)` 를 켜고 끈다.
- 기호 숨기기: `web/src/livePreview.ts` 의 `build` — 커서가 없는 줄(`activeLines`)에서 `HeaderMark`·`EmphasisMark`·`StrikethroughMark`·인라인 `CodeMark`·링크 기호를 숨기고, 위키링크·`==하이라이트==` 를 글자로 찾아 꾸민다. `FencedCode`·`CodeBlock`·`HTMLBlock`·`Table` 안은 건너뛴다.
- 블록 그리기: `web/src/liveBlocks.ts`. `findBlocks` 가 콜아웃·`$$`·Mermaid·여러 줄 주석·임베드만 있는 줄을 찾고, `buildBlocks` 가 **블록의 어느 줄에도 커서가 없을 때** `Decoration.replace({ block: true })` 로 `BlockWidget` 을 놓는다. 위젯은 미리보기 렌더러(`renderMarkdown` + `enhance`)로 그리고, 누르면 커서를 블록 처음에 두어 원문을 보인다(`mousedown`). 위젯 안의 할 일 체크는 `disabled`.
- 줄 안: `buildInline` 이 `![[이미지]]`(줄에 다른 글이 있을 때)·`$…$`·주석·블록 ID·각주를 장식한다. **`![글](주소)` 는 줄 안에서 처리하지 않는다**(혼자 있는 줄만 `findBlocks` 의 `image`).
- 코드 고정폭: `livePreview.ts` 의 `codeFont`(`codePlugin`) — Live Preview 와 따로 늘 켜져 코드 줄·인라인 코드에 고정폭 클래스를 단다.
- 칸 미러링: `web/src/mirror.ts` — 같은 문서를 연 다른 칸의 `ChangeSet` 을 `mirrored` 표식과 `addToHistory: false` 로 받아 넣는다. `Editor.tsx` 의 `updateListener` 가 이 칸에서 생긴 변경만 내보낸다(`outgoingChanges`).
- 프런트매터: `livePreview.ts` 의 `foldField` 가 맨 앞 `---…---` 를 한 줄로 접는다. 구분선 처리는 여기와 겹치면 안 된다.
- 시험: vitest(`web/src/livePreview.test.ts` — `EditorState` 단위). 브라우저 시험은 사람이 시험 서버로 본다(`docs/guides/development.md`).

## 접근 방식

### 나머지 7가지(1–5, 7, 8)

기존 틀에 얹는다. 고를 것이 없었다.

- 기호 숨기기(구분선 제외 줄 단위 장식): `livePreview.ts` 의 `build` 에 노드를 더한다 — `QuoteMark`, `ListMark`, `TaskMarker`, `CodeMark`(펜스).
- 블록 위젯: `liveBlocks.ts` 의 `findBlocks` 에 `HTMLBlock` 을 더한다(`BlockWidget`, 미리보기 렌더러 그대로).
- 줄 안: `buildInline` 에 `![글](주소)` 를 더한다(`InlineImage` 재사용).

### 표 편집기 — 고른 방식과 버린 방식

| 방식 | 내용 | 대가 | 결과 |
| --- | --- | --- | --- |
| A. 그린 표 + 칸 입력창 | 칸을 누르면 일반 입력창, 칠 때마다 문서의 그 칸 범위를 고침 | 칸 안에서 `[[` 자동완성·단축키·구문 색이 없다 | 코디네이터 추천, **사용자가 고르지 않음** |
| **B. 칸 편집기(CodeMirror)** | 칸 안에 CodeMirror 편집기를 넣고 본문 문서와 맞춘다(Obsidian 방식) | 실행 취소·포커스·IME 경계를 직접 맞춰야 한다. A 의 두세 배 | **사용자 선택** |
| C. 팝업 표 편집 | 표를 창에 띄워 고치고 닫을 때 반영 | 「그 자리에서」 가 아니다 | 버림 |
| D. 외부 표 라이브러리 | ProseMirror/TipTap 표 등 | CodeMirror 마크다운 문서와 맞물리지 않는다 | 버림 |

B 를 고른 까닭(사용자): 칸 안에서도 본문과 똑같이 `[[` 자동완성·단축키·구문 색이 되어야 한다. (처음 설명에서 「칸 안 Live Preview」 도 된다고 했으나, 본문 규칙상 고치는 줄은 원문이라 칸 안에서는 해당이 없다 — 6.3, 사용자 확인.)

## 설계

### 1. 구분선

- lezer 의 `HorizontalRule` 노드. 그 줄에 커서가 없으면 줄 내용을 가로줄 위젯으로 바꾼다(`Decoration.replace`, 줄 하나). 커서가 그 줄에 오면 `---` 원문.
- 맨 앞 프런트매터의 `---` 는 lezer 가 구분선으로 읽을 수 있으므로 **프런트매터 범위(`frontmatterEnd`)는 건너뛴다.**
- `글\n---` 는 lezer 가 `SetextHeading2` 로 읽으므로 구분선이 아니다(바꿀 것 없음 — 미리보기와 같다).
- 누르면 커서를 그 줄로(원문). 기존 `BlockWidget` 의 `mousedown` 과 같은 동작.

### 2. 인용

- 콜아웃이 아닌 `Blockquote`(첫 줄이 `> [!` 가 아님). 콜아웃은 지금처럼 `liveBlocks` 위젯.
- 커서가 없는 줄에서 `QuoteMark`(`>`)와 뒤 공백 하나를 숨기고, 인용의 **모든 줄**에 줄 장식(`Decoration.line`)으로 왼쪽 막대를 단다(커서가 있는 줄도 막대는 둔다 — 줄마다 모양이 들쭉날쭉하지 않게). 겹친 인용 `>>` 은 단계마다 들여쓰기를 늘린다(막대 하나, 단계 수만큼 왼쪽 여백).
- 인용 안의 굵게·링크 등은 지금 규칙대로 숨긴다.

### 3. 목록 글머리

- 커서가 없는 줄의 `ListMark` 중 `-`·`*`·`+` 를 점(•) 위젯으로 바꾼다. 들여쓰기(앞 공백)는 그대로 둔다 — 단계는 공백 너비로 보인다.
- 번호 목록(`1.`·`1)`)은 바꾸지 않는다.
- 할 일 항목(아래 4)은 글머리 대신 체크박스가 그 자리를 차지한다.

### 4. 할 일

- `ListItem` 안의 `Task` → `TaskMarker`(`[ ]`·`[x]`). 커서가 없는 줄에서 `- [ ] ` 전체(글머리 + 표시 + 뒤 공백)를 체크박스 위젯으로 바꾼다.
- 체크박스를 누르면 **커서를 옮기지 않고** 그 줄의 `[ ]`↔`[x]` 한 글자만 바꾼다(`Editor.tsx` 의 `toggleTask` 와 같은 변경, `userEvent: "input"`). 읽기 전용이면 누를 수 없다(`disabled`).
- 끝낸 항목 글은 꾸미지 않는다 — 미리보기의 `task-item` 에도 꾸밈이 없다(사용자 확인, 1차 리뷰).

### 5. 코드 블록

- `FencedCode`. **커서가 블록의 어느 줄에도 없으면** 여는 펜스 줄과 닫는 펜스 줄을 숨기고(줄째 `Decoration.replace`), 여는 줄 자리에 언어 이름(있으면)과 「복사」 단추가 든 머리 위젯을 둔다. 안쪽 코드 줄에는 줄 장식으로 상자 배경을 단다. 코드 줄은 **문서의 글 그대로**라 커서를 넣어 바로 고친다.
- 커서가 블록 안에 들어오면 펜스 줄이 원문으로 다시 보인다(언어를 고칠 수 있게).
- Mermaid 블록은 지금처럼 `liveBlocks` 의 그린 위젯이 먼저다(바꾸지 않는다). 들여쓴 코드 블록(`CodeBlock`)은 펜스가 없으니 상자 배경만 단다.
- 「복사」 는 안쪽 코드만 클립보드에 넣는다(펜스 빼고).
- 코드 접기(`codeFoldProp`, 6줄 이상)와 함께 동작해야 한다 — 접힌 블록은 머리 위젯 + 접힘 표시.

### 6. 표 편집기

#### 6.1 원칙: 문서가 유일한 원본이다

- 표의 내용은 **언제나 본문 문서(`EditorView` 의 doc)에만** 있다. 표 위젯과 칸 편집기는 문서의 한 구간을 보여 주는 창이다.
- 칸 편집기에서 친 것은 **본문 문서를 고치는 트랜잭션**으로 바뀌어 본문 뷰에 들어간다(`view.dispatch`). 그래서 저장·미러링(`mirror.ts`)·실행 취소·`updateListener` 가 지금 경로 그대로 돈다.
- 본문 문서가 바뀌면(칸 편집기에서 왔든, 미러링·합치기·실행 취소로 왔든) 표 위젯이 문서를 다시 읽어 칸을 맞춘다. 편집 중인 칸의 글이 바뀌었으면 그 칸 편집기의 내용을 바꾸고 커서를 변경에 맞춰 옮긴다(`ChangeSet.mapPos`).

#### 6.2 표 위젯

- lezer 의 `Table` 노드(문서 최상위만). 표는 **커서가 표 안에 있어도 늘 그린다**(`Decoration.replace({ block: true })` 로 표 줄 전체). 본문 커서는 표 안으로 들어가지 않는다 — 표 안의 편집은 칸 편집기가 한다.
- 원문으로 고치고 싶을 때를 위해 표 메뉴에 **「원문으로 편집」** 을 둔다. 고르면 그 표만 원문 줄로 돌아가고 본문 커서를 표 첫 줄에 둔다. 커서가 표 밖으로 나가면 다시 그린다. (코디네이터 판단: 원문 길이 막히면 모양이 깨진 표를 고칠 방법이 없다.)
- 칸은 평소에 **그린 HTML** 이다(칸 글을 미리보기 렌더러의 인라인 렌더로 — 굵게·링크·`[[위키링크]]`·인라인 수식·이미지). 칸 안 링크는 `ctx.onLink` 로 미리보기처럼 따라간다(`Ctrl/Cmd` 와 함께 누르면 새 탭 등 기존 규칙).
- **칸 편집기는 한 번에 하나만 띄운다**: 칸을 누르거나 키보드로 칸에 들어가면 그 칸 자리에 CodeMirror 편집기를 붙이고, 칸을 떠나면 떼고 다시 HTML 로 그린다. (코디네이터 판단: 칸마다 편집기를 상시로 두면 수백 칸 표에서 편집기가 수백 개가 되어 느려진다. 사용자가 원한 것은 「편집 중인 칸에서 본문과 같은 편집 기능」 이고, 그것은 하나로 충분하다.)
- 열 정렬(`:---`·`:---:`·`---:`)을 칸의 `text-align` 으로 보인다. 칸 편집기도 같은 정렬.
- 머리 행은 굵게, 구분 줄(`|---|`)은 그리지 않는다.

#### 6.3 칸 편집기

- 칸 편집기에 붙는 것: 마크다운 언어와 구문 색(`headingStyle`·`classHighlighter` — 본문과 같은 색, 9절), 위키링크 자동완성(같은 `linkCandidates`), 서식 키맵(`Mod-b`/`Mod-i`/`Mod-k`/`Mod-Shift-h`), 코드 고정폭. **자기 실행 취소 기록은 두지 않는다.**
- **고치는 칸은 원문이다**(사용자). 본문의 「커서가 있는 줄은 원문」 규칙과 같다 — 칸은 한 줄이라 고치는 동안 늘 원문(`**`·`[[…|`·`==` 가 보임, 구문 색 있음)이고, 칸을 떠나면 HTML 로 그린다. 그래서 칸 편집기에 Live Preview 의 기호 숨기기·줄 안 장식은 붙이지 않는다. 요소 단위(커서가 닿은 요소만 원문)는 고르지 않았다 — 본문의 줄 단위 판정을 바꿔야 하고 본문 동작까지 흔든다.
- 칸 글과 문서의 대응:
  - 칸의 문서 구간은 `|` 사이에서 앞뒤 공백을 뺀 부분이다. 칸 편집기는 그 구간의 글을 보인다.
  - 칸 안의 `|` 는 문서에 `\|` 로 쓴다. 칸 편집기에서는 `|` 로 보이고, 칠 때 `\|` 로 바꿔 넣는다(위치 대응은 이 이스케이프를 따라 맞춘다).
  - 줄바꿈은 칸에 넣을 수 없다. `Shift+Enter` 는 `<br>` 을 넣는다(GFM 표 관례).
  - 칸이 모자란 행(다른 행보다 `|` 칸이 적음)의 빈 칸을 고치면 그 행 끝에 필요한 만큼 칸을 붙인다.
- 실행 취소: 칸 편집기 안의 `Mod-z`/`Mod-Shift-z`(`Mod-y`)는 **본문 뷰의 `undo`/`redo`** 를 부른다. 칸에서 친 글자는 본문에서 친 것과 같은 묶음 규칙(본문 `history()` 의 시간 묶음)으로 묶여야 한다 — 글자마다 따로 되돌아가면 안 된다. 그러려면 칸 변경을 **칸 전체 바꾸기가 아니라 실제로 바뀐 위치의 변경**으로, `userEvent: "input.type"` 등 본문과 같은 이벤트 이름으로 보낸다.
- 실행 취소로 되돌린 변경이 다른 칸이나 표 구조에 닿으면 표 위젯이 다시 그리고, 커서는 실행 취소가 남긴 본문 선택을 따른다(그 자리가 칸 안이면 그 칸 편집기를 연다).
- 한글 입력: 조합(composition) 중에는 표를 다시 그리거나 칸 편집기를 떼지 않는다. 조합 중에 본문 문서가 바깥(미러링)에서 바뀌면 조합이 끝난 뒤에 맞춘다.

#### 6.3.1 본문 선택이 표 안으로 오면 (코디네이터 판단)

- 실행 취소·찾기 막대(다음·이전·바꾸기)·검색 결과 이동(`gotoLine`)·제목/블록 링크 이동 등 **무엇이든** 본문 선택을 표 안의 **한 칸 안**에 두면, 표 위젯이 그 칸의 칸 편집기를 열고 같은 선택(찾은 글이면 그 글을 고른 상태)을 보인다. 그래서 표 위젯은 실행 취소만이 아니라 모든 선택 변경을 본다.
- 선택이 여러 칸에 걸치거나 표 밖까지 걸치면(`Mod-A` 등) 칸 편집기를 열지 않고 표는 그린 채로 둔다. 그 선택으로 지우거나 바꾸면 본문 문서가 바뀌는 것이므로 그대로 된다.
- 편집 중이 아닌 칸(HTML)에는 찾기 강조를 칠하지 않는다. 다음 일치로 가면 그 칸이 열리며 강조가 보인다. 이것을 사용자 문서에 적는다.

#### 6.3.2 칸 편집 중에 밖에서 글이 들어오면 (코디네이터 판단)

- 칸 편집기 안의 붙여넣기: 여러 줄 글은 줄바꿈을 `<br>` 로 바꿔 칸에 넣는다. 파일 붙여넣기·끌어놓기는 칸 편집기에도 업로드 처리기를 붙여 그 칸에 링크를 넣는다 — 자리 표시는 줄바꿈 없는 글로, 여러 파일의 링크는 공백으로 잇는다.
- 파일 패널의 「넣기」(`insertText`, `ownLine`): 칸 편집기가 열려 있으면 그 칸의 커서 자리에 `ownLine` 없이 넣는다(표 칸 안 `![[이미지]]` 는 GFM 에서 성립한다).
- 템플릿 넣기 등 여러 줄을 넣는 `insertText`: 칸 편집기를 닫고 **표 바로 뒤 줄**에 넣는다.
- 이를 위해 `EditorHandle` 이 「칸 편집기가 열려 있으면 그쪽으로」 를 판단할 수 있게 한다(경로는 만드는 사람에게).

#### 6.4 키보드

| 키 | 동작 |
| --- | --- |
| `Tab` / `Shift+Tab` | 다음 / 이전 칸. 마지막 칸에서 `Tab` 은 아래에 빈 행을 하나 넣고 그 첫 칸으로 |
| `Enter` | 아래 칸. 마지막 행에서는 아래에 빈 행을 넣고 그 칸으로 |
| `Shift+Enter` | 칸 안에 `<br>` |
| `←` `→` | 칸 글의 처음/끝에서 누르면 옆 칸으로 |
| `↑` `↓` | 위/아래 칸. 첫 행 위·마지막 행 아래로 나가면 표 밖 본문(표 앞 줄 / 뒤 줄)으로 |
| `Esc` | 칸 편집을 끝내고 본문 커서를 표 바로 뒤 줄로 |
| `Mod-z` 등 | 6.3 대로 본문 실행 취소 |
| 자동완성이 열려 있을 때 | `Enter`·`Tab`·`↑` `↓` 는 자동완성이 먼저 받는다 |

본문에서 표로 들어가기: 본문 커서가 표 바로 위 줄에서 `↓`, 바로 아래 줄에서 `↑` 를 누르면 첫 행 / 마지막 행의 첫 칸 편집기로 들어간다.

#### 6.5 행·열 작업

각 행 왼쪽과 각 열 위에 손잡이(마우스를 올리면 보임, 터치에서는 칸 편집 중인 행·열에 늘 보임)를 둔다. 손잡이를 누르면 메뉴, 끌면 옮기기.

- **행 메뉴**: 위에 행 넣기, 아래에 행 넣기, 위로 옮기기, 아래로 옮기기, 행 지우기.
- **열 메뉴**: 왼쪽에 열 넣기, 오른쪽에 열 넣기, 왼쪽으로 옮기기, 오른쪽으로 옮기기, 열 지우기, 정렬(왼쪽·가운데·오른쪽·없음), 이 열로 정렬(오름차순·내림차순).
- 표 전체 메뉴(표 오른쪽 위): 원문으로 편집.
- **끌어 옮기기**: 행 손잡이를 위아래로, 열 손잡이를 좌우로 끌면 놓을 자리에 선을 보이고, 놓으면 옮긴다. 마우스와 터치(포인터 이벤트) 둘 다. 끄는 중 `Esc` 는 취소.
- **머리 행**은 옮기거나 지울 수 없고 sort 에서 빠진다(GFM 표는 머리 행이 반드시 있다). 머리 행의 「위에 행 넣기」 는 없다. 남은 열이 하나면 열 지우기는 없다(표를 통째로 지우려면 원문으로).
- 파일에 쓰는 범위(anti-goal 「고치지 않은 줄」 의 구체):
  - 행 넣기·지우기: 그 행 줄 하나를 넣거나 지운다.
  - 행 옮기기: 옮긴 행 줄과 그 자리 사이 줄들의 순서만 바뀐다(줄 글은 그대로).
  - 열 넣기·지우기·옮기기: 모든 행 줄과 구분 줄이 바뀐다. 각 줄 안에서는 해당 칸만 넣고/빼고/옮기고 다른 칸의 글과 공백은 그대로 둔다.
  - 정렬: 구분 줄만 바뀐다. 그 열의 구분 칸만 `:---`·`:---:`·`---:`·`---` 로(원래 `-` 개수는 지킨다, 최소 3개).
  - sort: 본문 행 줄들의 순서만 바뀐다.
  - 새 행·새 열의 빈 칸은 `|  |`(공백 둘)로 쓴다. 바깥 `|` 유무 등 표의 기존 모양을 따른다(첫 행 줄이 `|` 로 시작하면 새 줄도).
- 모든 작업은 본문 트랜잭션 **하나**다 — 실행 취소 한 번에 통째로 되돌아간다.

#### 6.6 sort

- 본문 행만, **안정 정렬**(같은 값이면 원래 순서).
- 비교 값은 칸의 **보이는 글**(마크다운 기호를 뺀 글 — `**12**` 는 `12`, `[[노트|별칭]]` 는 `별칭`).
- 둘 다 숫자로 읽히면(앞뒤 공백, 쉼표 천 단위, 부호, 소수, 끝의 `%` 허용) 숫자로, 아니면 `localeCompare(…, undefined, { numeric: true, sensitivity: "base" })` 로 비교한다.
- 빈 칸은 오름·내림 어느 쪽이든 맨 뒤.
- sort 는 정렬 상태를 기억하지 않는 **한 번의 편집**이다(머리에 화살표를 남기지 않는다). 파일의 행 순서가 바뀐다.

#### 6.7 읽기 전용과 Live Preview 꺼짐

- 읽기 전용 편집기: 표는 그리고 칸 링크는 따라가지만, 칸 편집기·손잡이·메뉴는 없다. 체크박스도 누를 수 없다.
- Live Preview 를 끄면(원문 모드) 이 문서의 모든 그리기와 표 편집기가 꺼지고 지금처럼 원문이다.

### 7. 줄 안 `![글](주소)`

- 줄에 다른 글이 있을 때의 `Image` 노드(lezer). 커서가 없는 줄이면 `InlineImage` 로 바꾼다. 주소가 볼트 안 상대 경로면 `![[…]]` 와 같은 해석(`resolver.resolve` → `api.rawUrl`), `http(s):` 면 그대로. `SAFE_URI` 에 걸리는 주소는 그리지 않는다.
- `livePreview.ts` 의 `if (name === "Image") return false;` 는 `liveBlocks` 쪽으로 옮겨 처리한다(지금은 그대로 두라는 뜻의 주석).

### 8. HTML 블록

- `HTMLBlock` 노드(`<!-- … -->` 주석 블록 제외 — 붙여넣기 업로드 자리 표시 `<!-- uploading… -->` 이 이 모양이다). 커서가 없으면 `BlockWidget` 으로, 렌더러는 `renderMarkdown`(DOMPurify 정화 그대로). 누르면 원문.

### 9. 코드 블록 언어별 색

- **지금**: 편집 화면은 `markdown({ codeLanguages: languages })`(`@codemirror/language-data`)로 언어별 파서를 받지만 **코드를 칠하지 않는다** — `syntaxHighlighting(defaultHighlightStyle, { fallback: true })` 는 다른 하이라이터(`headingStyle`)가 있으면 쓰이지 않으므로 한 번도 켜진 적이 없다(1차 리뷰가 `highlightingFor` 로 확인). 미리보기(`markdown.ts` 의 markdown-it)도 칠하지 않는다. `classHighlighter` 로 바꾸면 코드 색과 함께 본문 원문의 `**굵게**`·`*기울임*`·`[ ]`·HTML 태그에도 모양이 처음 생긴다 — 받아들이고 `docs/ops/ux.md` 에 적는다.
- **방식(코디네이터)**: 미리보기도 같은 lezer 파서로 칠한다 — `languages` 에서 `LanguageDescription.matchLanguageName(languages, info, true)` 로 찾아 `load()`(편집기와 같은 지연 로딩 청크) 뒤 `@lezer/highlight` 의 `highlightCode` + `classHighlighter`(`tok-*` 클래스)로 `<code>` 안을 다시 그린다. KaTeX·Mermaid 처럼 그린 뒤 `enhance.ts` 에서 비동기로 한다(모르는 언어·실패면 지금처럼 글자만).
- 색은 `styles.css` 의 `tok-*` 규칙으로, 밝은·어두운 테마 토큰을 둔다. 편집 화면도 `defaultHighlightStyle` 대신 같은 `classHighlighter` 를 써(`syntaxHighlighting(classHighlighter)`) 두 화면이 같은 색이 된다. 제목 굵기(`headingStyle`)는 그대로.
- **언어 별칭(사용자)**: `language-data` 에 없는 흔한 짧은 이름도 칠한다 — `py`→Python, `sh`·`zsh`·`bash`→Shell, `yml`→YAML, `md`→Markdown, `rb`→Ruby, `rs`→Rust, `kt`→Kotlin, `ps1`→PowerShell 등. 별칭 표는 한곳에 두고 편집 화면(`markdown({ codeLanguages })` 에 함수로)과 미리보기가 함께 쓴다.
- 버린 방식: highlight.js·shiki — 새 의존성, 편집기와 색이 갈리고, 오프라인 캐시 목록(`sw`)에 따로 넣어야 한다.
- 미리보기 색칠은 DOMPurify 정화 뒤에 하므로 만든 `<span class="tok-…">` 는 글자만 감싼다(정화된 글 노드에서 만든다 — HTML 을 문자열로 다시 넣지 않는다).

- `docs/ops/ux.md`: 새 절(요청·정한 것·확인한 것)을 더하고, 「2차 남은 것·알려진 한계」 의 「표·목록 글머리·HTML은 원문 그대로다」 줄을 고친다.
- 화면 글은 `packages/core/src/messages/{en,ko}.json`(메뉴 항목, 복사, 원문으로 편집 등).

## 시험과 확인

- 표 모델은 화면과 떼어 순수 함수로 둔다(문서 글 → 표 구조·칸 구간, 작업 → 변경 목록). 단위 시험: 파싱(바깥 `|` 유무, 칸이 모자란 행, `\|`, 정렬 표시), 각 작업이 **바꾸는 줄이 위 6.5 의 범위뿐인지**, sort 비교(숫자·`%`·쉼표·빈 칸·안정성), 이스케이프 위치 대응.
- 할 일 토글·구분선·코드 블록 펜스 숨김 범위는 `EditorState` 단위 시험(`livePreview.test.ts` 처럼).
- 브라우저(시험 서버, 임시 `KEYRING_DATA`, 다른 포트): 8가지 각각의 그리기와 원문 전환, 표에서 한글 입력(조합 중 `Tab`·`Enter`·클릭 포함), 칸 안 `[[` 자동완성, 실행 취소 순서(본문 → 칸 → 행 작업 섞어서), 같은 문서를 두 칸에 열고 한쪽 표를 고칠 때 다른 쪽, 끌어 옮기기(마우스, 390px 터치 에뮬레이션), 읽기 전용 노트, 어두운 테마.
- 루트 `pnpm test`·`pnpm typecheck`·`pnpm build`.

## 만드는 사람에게 맡기는 것

- 칸 편집기를 위젯 안에 붙이는 방법(위젯의 `updateDOM` 으로 같은 DOM 을 지키기, `ignoreEvent`, 포커스 이동), 칸 변경 → 본문 변경 위치 대응의 구현.
