# 모바일(PWA) 다듬기 — 설계

Nov 2, 2026 · 기준 커밋 `28063b9`

## 왜

휴대폰에 설치한 PWA(주로 읽기, 가끔 빠른 메모)를 쓰면서 사용자가 불편을 넷 짚었다. 트리를 펴고 접기 어렵고, 노트를 열기만 해도 화면 키보드가 올라오고, 노트가 어디 있는지(상위 경로) 안 보이고, 서랍·시트를 연 채 뒤로가기를 누르면 앱이 꺼진다. 앞 작업(`2026-11-01-mobile-bottom-bar-design.md`)이 하단 바를 만들었고, 이번은 그 위의 손질이다.

## 범위

| 항목 | 이번에 | 정한 사람 |
| --- | --- | --- |
| 1. 안드로이드 하단(시스템 내비게이션 줄) 색 | **하지 않는다** | 사용자 |
| 2. 트리 펴고 접기 터치 영역 | 한다 | 사용자(방식) |
| 3. 노트를 열 때 키보드가 올라오지 않게 | 한다 | 사용자(요청), 범위는 코디네이터 |
| 4. 노트의 상위 경로(빵부스러기) 보이기 | 한다 | 사용자(요청), 모양은 코디네이터 |
| 5. 뒤로가기로 열린 것 닫기 | 한다, B 방식 | 사용자 |

**하지 않는 것(non-goals)**

- 하단 내비게이션 줄 색. 조사 결과 안드로이드 Chrome 의 설치 앱(WebAPK)은 그 줄을 **설치 때 받은 manifest 색**으로 칠하고 페이지의 `theme-color` 를 따르지 않는다(상단 상태 줄은 따른다). 저장소 manifest 는 이미 흰색이다. 사용자 기기의 하단이 아직 파란 것은 설치된 앱이 옛 manifest(`#3b6fd8`)를 들고 있어서로 보이며, 재설치하거나 Chrome 이 앱을 갱신하면 흰색이 된다. 어두운 테마에서도 흰색으로 남는 한계는 받아들인다. `docs/ops/ux.md` 「모바일 하단 바·PWA 색·새 버전 알림」 의 「확인하지 못한 것」 에 이 결론을 적는다.
- **노트 사이 뒤로가기**. 뒤로가기는 열린 것을 닫기만 한다. 노트를 옮겨 다닌 기록은 남기지 않는다(지금처럼 `replaceState`). 열 것이 없으면 지금처럼 앱이 꺼진다(브라우저 기본).
- 마우스 환경의 동작 변경. 아래 2·3·5 는 모두 **터치 환경(`(pointer: coarse)`)** 에만 걸고, 마우스 환경은 창 폭과 상관없이 지금 그대로다(코디네이터 판단 — 좁게 줄인 데스크톱 창에서 브라우저 뒤로 단추·Esc 가 달라지면 안 된다는 실패 조건 때문. 넓은 태블릿에도 걸린다). 판정은 한곳(예: `isTouch()`)에 두고 세 기능이 같이 쓴다.

**실패로 보는 것(anti-goals)**

- 뒤로가기 처리 때문에 주소(`#/노트`, `#/:settings/...`)가 틀어지거나, 설정 화면의 기존 뒤로가기(닫기 전 확인 포함)가 깨지는 것.
- 데스크톱(웹·Tauri 앱)에서 클릭·Esc·포커스 동작이 바뀌는 것.
- 새 노트를 만들었는데 제목 칸에 커서가 안 가는 것(빠른 메모가 느려진다).

## 지금 코드

- 트리(`web/src/Tree.tsx`): 노트 행의 펴고 접기는 너비 14px 화살표(`.tree-chevron`)를 눌렀을 때만이고, 이름을 누르면 `activate` 가 노트를 연다. 노트가 없는 칸(워크스페이스 최상위)은 누르면 펴고 접는다. `(pointer: coarse)` 에서 행 높이는 36px.
- 편집기(`web/src/Editor.tsx`): `autoFocus` 기본 true, `DocPane.tsx` 가 포커스된 칸이면 `autoFocus={focused}` 를 넘겨 노트가 열릴 때마다 `view.focus()`.
- 빵부스러기(`DocPane.tsx` `crumbs`): 넓은 화면에는 보이고, `styles.css` 의 좁은 화면 규칙 `.crumbs .crumb:not(.current) { display: none; }` 이 지금 노트 이름만 남긴다.
- 주소: 활성 노트가 바뀌면 `Workspace.tsx` 가 `history.replaceState(null, "", "#/노트")`. 설정 화면은 `#/:settings/<묶음>` 을 `pushState` 하고, `hashchange` 에서 설정이 닫히면 `attemptCloseTopModal()` 로 닫기 확인을 거친다(`settingsNav.ts` 가 `history.state` 의 `{ back }` 을 쓴다).
- 위에 뜨는 것: 왼쪽 서랍(`drawer === "left"`)·오른쪽 패널 서랍, `Modal` 기반(더 보기 `MoreSheet`, 탭 시트 `TabSwitcher`, 그래프·검토·정리 점검·가져오기·팔레트·설정 등 — `Modal.tsx` 의 `stack`, `attemptCloseTopModal`), 띄우는 메뉴(`ui.tsx` `Menu`), 확인 창(`dialog.ts`, `.ask-dialog`).

## 접근 방식

뒤로가기(5번)에 세 가지를 견줬다.

| 방식 | 내용 | 득실 |
| --- | --- | --- |
| A. CloseWatcher API | 열 때 등록, 뒤로가기는 맨 위 것을 닫음, 주소 기록 안 건드림 | 안전하지만 지원 브라우저 한정, 데스크톱 Esc 와 겹침 |
| **B. 주소 기록에 표시 하나** | 무언가 열리면 같은 주소로 `pushState`, 뒤로가기(`popstate`)가 그 기록을 지우면 맨 위 것을 닫음 | 거의 모든 브라우저. 단추로 닫을 때 쌓아 둔 기록을 치워야 하고 설정 해시·노트 주소와 얽힘 |
| C. A 기본 + B 대체 | 둘 다 | 가장 넓지만 코드·시험 두 벌 |

**사용자는 B 를 골랐다.** 코디네이터는 A 를 권했었다(위험이 작아서). B 의 얽힘은 아래 「뒤로가기 설계」 의 불변식으로 막는다.

## 설계

### 2. 트리 — 이름은 펴고 접기, 오른쪽 열기 아이콘 (사용자 결정)

터치 환경(`(pointer: coarse)`)에서만:

- **하위 항목이 있는 노트**(펼칠 수 있는 행, 지금 `expandable(n)` 이 참이고 노트가 있는 것): 행 아무 데나(이름 포함) 누르면 펴고 접는다. 행 **오른쪽 끝에 열기 아이콘 단추**를 두고, 그것을 누르면 노트를 연다(지금 이름을 눌렀을 때와 같은 `actions.open`).
- 하위 항목이 없는 노트: 지금처럼 누르면 연다. 열기 아이콘 없음.
- 노트가 없는 칸(워크스페이스 최상위)·첨부 묶음 행: 지금처럼 누르면 펴고 접는다.
- 열기 단추의 누르는 자리는 44×36px 이상(행 높이 36px). 단추에는 `aria-label`(새 키, 예: `tree.openNote` — 이름 포함 「{name} 열기」). 아이콘은 Lucide 에서 고른다(빌더 몫).
- 마우스 환경은 지금 그대로(화살표 = 펴고 접기, 이름 = 열기, 열기 단추 없음).
- 길게 누르기 메뉴(오른쪽 클릭 메뉴)·끌어 옮기기는 그대로.

### 3. 노트를 열 때 키보드를 올리지 않는다 (코디네이터 범위)

- 터치 환경(`(pointer: coarse)`)에서는 노트를 **열 때** 편집기에 자동 포커스를 주지 않는다 — 트리·검색·탭 시트·링크·빵부스러기·홈·뒤로/앞으로 어느 길로 열든.
- **사람이 명시적으로 고른 「새 노트」**(하단 바 ＋ 짧게, 트리·메뉴·탭 시트·팔레트의 「새 노트」·「새 하위 노트」)만 지금처럼 제목 칸에 커서를 둔다(키보드가 올라온다). 그 밖에 노트가 **덤으로 만들어지는** 길 — 데일리 노트(＋ 길게, 오늘 노트 명령, 없으면 만들어짐), 없는 노트를 가리키는 링크를 눌러 만들어짐 — 은 「여는 것」 으로 보고 포커스를 주지 않는다(코디네이터 판단: 규칙을 하나로 — 「새 노트」 를 눌렀을 때만 키보드).
- 동기화 다시 읽기·칸 전환 등으로 편집기가 다시 만들어질 때도 터치에서는 자동 포커스하지 않는다.
- 사람이 본문을 누르면 그때 포커스(지금 동작).
- 데스크톱은 그대로(열면 포커스).

### 4. 좁은 화면에서도 상위 경로를 보인다 (코디네이터 모양)

- 좁은 화면 규칙의 숨김을 걷고, 빵부스러기를 문서 머리의 한 줄 안에서 **가로로 밀어 볼 수 있게** 한다(줄바꿈 없음, 스크롤 막대 숨김).
- 처음 그릴 때와 노트가 바뀔 때 **오른쪽 끝(지금 노트)** 이 보이게 스크롤한다.
- 상위 칸을 누르면 지금처럼 그 노트를 연다(3번에 따라 포커스 없음). 칸의 누르는 자리는 터치에서 높이 32px 이상.
- 문서 머리의 다른 도구(보기 전환·⋯·데일리 이동)는 밀리지 않고 제자리.

### 5. 뒤로가기 설계 — B (사용자 결정)

**적용 범위**: 터치 환경(`(pointer: coarse)`)에서만. 마우스 환경은 지금 그대로다.

**닫히는 것은 이 넷뿐이다**(위에 뜬 것, 맨 위부터 하나씩. 코디네이터 판단): 확인 창(`dialog.ts`), 띄우는 메뉴(`ui.tsx` `Menu` — 이것을 쓰는 워크스페이스 전환기 등 포함), `Modal` 스택의 맨 위(더 보기·탭 시트·그래프·검토 등. 닫기 확인 `CloseGuard` 를 거친다 — 거부되면 닫지 않고 표시를 다시 쌓는다), 서랍(왼쪽·오른쪽). 편집기 자동완성 팝업·툴팁·입력칸 포커스·이름 바꾸기 입력은 대상이 아니다(뒤로가기가 그것을 건너뛰고 위 넷 중 맨 위를 닫거나, 넷이 없으면 브라우저 기본). 무엇이 「맨 위」 인지는 화면에 쌓인 순서다.

**확인 창의 뒤로가기**(코디네이터 판단): `confirmDialog`·`chooseDialog` 는 취소(`false`·`null`)와 같다. 취소가 없는 `alertDialog` 는 확인과 같다(닫힌다 — 「닫을 수 없는 맨 위」 상태를 만들지 않는다).

**설정 화면은 지금 방식을 그대로 둔다.** 설정은 이미 자기 해시(`#/:settings/...`)를 `pushState` 하고 `hashchange` 로 닫는다. 새 표시 기록은 설정 해시 기록과 겹치지 않게 다룬다 — 설정 위에 뜬 것(예: 설정 안 확인 창)을 뒤로가기로 닫을 때 설정까지 닫히지 않아야 한다.

- **위에 뜬 것에서 설정을 열 때**(더 보기 → 설정, 코디네이터 판단): 표시 항목을 설정 해시로 **갈아 끼운다**(`replaceState`) — `history.back()` 으로 치운 뒤 push 하지 않는다(비동기 back 이 설정 항목을 꺼내는 경쟁을 막는다). 결과: 설정에서 뒤로가기 한 번이면 노트로 돌아간다.
- **뒤로가기로 설정을 닫으려다 닫기 확인 창이 뜬 경우**(`hashchange` 처리기의 `attemptCloseTopModal` 이 띄우는 것): 이 확인 창은 다른 확인 창과 똑같이 위에 뜬 것이다. 그 위에서 다시 뒤로가기 = 취소 = 설정 유지. 지금 처리기가 거부 때 설정 해시를 다시 push 하는 것과 표시 항목이 겹쳐 기록이 둘 쌓이지 않게 정리한다(정리 방법은 빌더 몫, 결과는 「설정이 열린 채, 뒤로가기 한 번이면 다시 닫기 시도」).

**불변식**(빌더가 지켜야 할 것):

1. 터치 환경에서 위에 뜬 것이 하나 이상이면, 지금 기록 항목은 표시 항목(`history.state` 에 이 앱의 표시 — 예 `{ kOverlay: n }`)이다. 없으면 표시 항목이 아니다. 표시 항목은 **하나만** 쌓는다(여럿이 열려도 하나, 하나를 닫고 남은 게 있으면 다시 하나).
2. 뒤로가기(`popstate` 로 표시 항목을 떠남) → 맨 위 것 하나를 닫는다. 남은 게 있으면 표시를 다시 쌓는다.
3. 단추·배경·Esc·항목 선택으로 마지막 것이 닫히면 → 쌓아 둔 표시 항목을 치운다(`history.back()`). 이 `popstate` 는 2번으로 처리하지 않는다(이미 닫혔다).
4. 표시 항목의 주소는 그 아래 항목과 같다. 표시 항목 위에서 활성 노트가 바뀌면(예: 탭 시트에서 고름) 주소 갱신은 **표시를 지운 채** `replaceState(null, …)` 하지 않는다 — 표시를 지키거나, 닫힘과 순서를 맞춘다. 결과적으로 뒤로가기 뒤 주소는 지금 활성 노트여야 한다.
5. 새로 고침·앱 다시 열기 때 표시 항목에 서 있으면(위에 뜬 것은 없다) 그 항목을 표시가 아닌 것으로 정리한다 — 첫 뒤로가기가 아무 일도 안 하는 것처럼 보이지 않게.
6. 화면이 넓어져(800px 초과) 서랍·더 보기·탭 시트가 닫히면 3번처럼 표시 항목을 치운다(위에 뜬 것이 남아 있으면 그대로).

**노트 사이 뒤로가기는 없다**: 노트를 열 때의 `replaceState` 는 그대로다.

**판단을 DOM 없이 시험할 수 있게** 표시 항목 상태 판단(쌓을지·치울지·popstate 를 닫기로 볼지)을 작은 모듈로 떼어 단위 시험한다(앞 작업의 `bottomBarState.ts`·`moreMenu.ts` 와 같은 결).

## 빌더에게 맡기는 것

- 열기 아이콘의 모양(Lucide 중), 정확한 크기·여백.
- 위에 뜬 것을 한곳에서 아는 방법(`Modal` 스택·메뉴·확인 창·서랍을 어떻게 모을지), 표시 상태 모듈의 이름과 모양.
- 터치 판정 방법(`matchMedia("(pointer: coarse)")` 를 한곳에 두는 것 권장).
- 빵부스러기 스크롤 구현.

## 확인

- 단위 시험: 표시 항목 판단 모듈, 트리 행의 누르기 결과(터치/마우스 × 하위 있음/없음/노트 없음), 편집기 자동 포커스 조건.
- 시험 서버(임시 `KEYRING_DATA`, 다른 포트) + 헤드리스 모바일 에뮬레이션(`isMobile`·`hasTouch`, 390×844):
  - 트리: 하위 있는 노트 이름 → 펴고 접기, 열기 아이콘 → 열림. 데스크톱(1280, 마우스)은 지금 그대로.
  - 노트 열기(트리·탭 시트·빵부스러기·링크) 뒤 `document.activeElement` 가 편집기가 아님. ＋ 새 노트는 제목 칸 포커스.
  - 깊은 노트에서 빵부스러기가 보이고 오른쪽 끝이 보임, 상위 칸 누르면 열림.
  - 뒤로가기(`page.goBack()`): 서랍·더 보기·탭 시트·그래프 모달·메뉴·확인 창이 하나씩 닫히고 주소가 지금 노트 그대로. 둘을 겹쳐 연 뒤 뒤로가기 두 번. X·배경으로 닫은 뒤 뒤로가기가 「닫을 게 없는 상태」 의 기본 동작(이전 기록)으로 감. 설정 화면 열기 → 설정 안 확인 창 → 뒤로가기는 확인 창만 닫음 → 다시 뒤로가기는 설정을 닫음(기존 확인 유지). 탭 시트에서 다른 노트를 골라 닫힌 뒤 주소 = 그 노트. 새로 고침 뒤 첫 뒤로가기.
- 실기기(안드로이드 PWA) 뒤로가기 단추 확인은 사용자 몫으로 남기고 보고에 적는다.
