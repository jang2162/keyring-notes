# 모바일 하단 바·PWA 상하단 색·PWA 새 버전 알림 — 설계

## 의도

휴대폰에서 이 앱은 **주로 읽고, 가끔 빠르게 메모한다**(사용자). 지금 좁은 화면(폭 800px 이하)에서는 자주 쓰는 것(파일·검색·탭)이 위쪽 ☰ 서랍과 탭 개수 단추(☐N) 뒤에 숨어 있어 한 손으로 닿기 어렵다. 아래쪽에 하단 바를 두어 자주 쓰는 것을 엄지 자리로 꺼낸다.

같은 모바일 작업으로 둘을 함께 고친다.
- 설치한 웹 앱(PWA)의 상단 상태 표시줄·하단 영역이 앱 강조색(파랑 `#3b6fd8`)으로 칠해져 이질적이다(사용자). 앱 배경색에 맞춘다.
- 열려 있는 PWA 는 서버가 새 버전으로 바뀌어도 새로 고칠 때까지 옛 화면으로 돌고, 그 사이 새 서비스 워커가 옛 캐시를 지워 아직 안 불러온 조각(수식·다이어그램·아이콘 고르기 창 등)이 열리지 않을 수 있다. 새 버전 알림을 띄우고 옛 캐시를 한 세대 남긴다(사용자 동의).

`docs/ops/ux.md` 의 처음 화면 구상에 「좁은 화면: 레일은 아래쪽 탭 바로」 가 있었고 만들지 않았다. 이 설계가 그 자리를 채운다.

## 목표

- 좁은 화면에서 하단 바: **파일 · 검색 · ＋ 새 노트 · 탭 · 더 보기**(5칸, ＋ 는 가운데 강조).
- PWA 의 상단·하단 시스템 영역 색이 앱 배경색이고, 밝은·어두운 테마(설정에서 고른 것 포함)를 따른다.
- 열려 있는 PWA 가 새 버전을 받으면 「새 버전이 있습니다 · 새로 고침」 을 알리고, 새로 고치기 전에도 옛 화면이 깨지지 않는다.

## 비목표

- 넓은 화면(800px 초과)·데스크톱 앱 창의 배치. 그대로 둔다.
- 파일·검색을 화면 전체 페이지로 바꾸는 모바일 전용 화면 구조(검토 후 버림 — 아래 「접근」).
- 빠른 메모를 한곳(받은편지함 노트 등)에 모으기. 새 노트는 지금처럼 **읽던 노트 옆**에 만든다(사용자).
- 서버에 버전을 묻는 API(검토 후 버림).
- 데스크톱 앱(Tauri) 업데이트 알림. 이미 있다(설정 「정보」 의 주황 점).

## 반목표

- **입력하는데 바가 화면 키보드 위에 떠서 쓸 자리를 먹는다.**
- **하단 바가 본문 끝·아이폰 홈 표시줄과 겹쳐 마지막 줄이나 바가 가려진다.**
- **새 버전 알림이 자동 저장 전에 새로 고침을 일으켜 쓰던 글을 잃는다.** 새로 고침은 사람이 누를 때만, 그리고 저장되지 않은 변경이 있으면 기존 저장·충돌 흐름을 지난 뒤에.
- **데스크톱 웹의 넓은 화면 배치가 바뀐다.**

## 접근 (검토한 것과 고른 것)

**하단 바**
- **고른 것: 지금 화면에 바 하나를 얹는다.** 좁은 화면일 때만 하단 바 컴포넌트를 그리고, 각 칸은 이미 있는 동작을 부른다. 범위가 작고 넓은 화면은 그대로다.
- 버린 것: 모바일 전용 화면 구조(파일·검색을 전체 페이지로). 앱다운 느낌은 더하지만 배치 코드가 두 벌이 되고 일이 몇 배다.

**상하단 색**
- **고른 것:** `index.html` 의 `theme-color` 를 `prefers-color-scheme` 별 두 벌(앱 배경색)로 두고, 설정에서 테마를 직접 고른 경우(`html[data-theme]`)도 따르게 테마가 바뀔 때 그 값을 코드로 맞춘다. `manifest.webmanifest` 의 `theme_color` 는 한 값만 가지므로 밝은 배경색으로 둔다 — 앱 전환 화면 등 일부 시스템 화면은 어두운 테마에서도 밝게 보일 수 있다(받아들인 대가).

**PWA 새 버전 알림**
- **고른 것: 서비스 워커가 바뀐 것을 알림으로.** 새 워커가 자리를 잡으면(`controllerchange`) 「새 버전이 있습니다 · 새로 고침」 알림. 옛 빌드의 캐시는 바로 지우지 않고 한 세대 남긴다.
- 버린 것: 서버 버전 API 를 주기적으로 묻기. API 하나와 계속 나가는 요청이 늘고, 서비스 워커가 이미 아는 것을 다시 묻는다.

## 하단 바

**보이는 조건.** 좁은 화면(`isNarrow`, `max-width: 800px` — 지금 서랍·탭 시트를 고르는 것과 같은 기준)일 때만. 웹(브라우저·PWA)과 모바일 앱 모두. 넓은 화면은 지금 그대로.

**칸과 동작.**

| 칸 | 누르면 | 비고 |
| --- | --- | --- |
| 파일 | 왼쪽 서랍을 파일 보기(`leftView: "files"`)로 연다. 이미 그 보기로 열려 있으면 닫는다 | 지금 ☰ 가 여는 서랍과 같은 것 |
| 검색 | 왼쪽 서랍을 검색 보기로 열고 검색 칸에 포커스(팔레트의 검색 명령과 같은 동작) | |
| ＋ 새 노트 | `createDoc()` — 읽던 노트 옆에 「제목 없음」, 제목 칸에 커서 | **길게 누르면 오늘 노트**(`openDaily(0)`). 데일리를 끈 워크스페이스면 길게 누르기는 아무것도 하지 않거나 알림(빌더 몫) |
| 탭 | 지금 칸의 열린 탭 시트(`TabSwitcher`, `setTabSheet`)를 연다. 칸 이름 아래·옆에 열린 탭 수 | 지금 위쪽 `TabCountButton` 이 하는 일 |
| 더 보기 | 아래에서 올라오는 목록: 오늘 노트, 태그, 첨부, 그래프, 수집, 검토, 정리 점검, 동기화, 설정. 지금 레일에 있는 항목 중 바에 없는 것(쓸 수 없는 것은 레일과 같은 조건으로 뺀다 — 예: 검토는 검토 기능이 있을 때만) | 단축키 화면은 모바일에서 이미 숨긴다 |

- 지금 열린 서랍 보기에 해당하는 칸(파일·검색)은 켜진 모양. 「더 보기」 목록에서 태그·첨부를 고르면 왼쪽 서랍을 그 보기로 연다.
- **위쪽 탭 줄은 좁은 화면에서 통째로 없앤다(사용자).** ☰·탭 개수 단추(☐N)는 바로 옮겨 갔고 새 노트 단추는 바의 ＋ 와 겹친다. 문서 머리(경로·⋯·오른쪽 서랍 단추)가 맨 위가 된다.
- **상태 표시줄(`.statusbar`)은 좁은 화면에서 숨긴다(사용자).** 알아야 할 상태 — 오프라인, 보낼 변경 수, 저장 실패·충돌, 검토 대기 — 가 있으면 「더 보기」 칸에 점이나 숫자를 보이고, 「더 보기」 목록 맨 위에 그 상태를 자세히(지금 상태 표시줄이 보이는 것과 같은 내용·동작, 예: 「지금 보내기」) 보인다. 「저장됨 3초 전」 처럼 평소 상태는 보이지 않는다.
- **좁은 화면의 왼쪽 서랍에서 레일을 빼고 패널만 둔다(내 결정).** 레일 항목은 하단 바와 「더 보기」 가 맡는다. 서버 모드의 **로그아웃**은 「더 보기」 목록 끝으로 옮긴다.
- 아래쪽에 고정된 알림(`.toasts`)은 바 위에 뜬다.
- 바의 높이는 아이콘+작은 이름, 누르는 자리는 칸마다 44×44px 이상. 아이폰 홈 표시줄만큼 아래 여백(`env(safe-area-inset-bottom)`; `viewport-fit=cover` 는 이미 켜져 있다).
- 본문·서랍·탭 시트·모달이 바에 가리지 않게 그만큼 아래를 비운다(본문 마지막 줄까지 스크롤된다).
- 레일의 알림 배지(동기화 보낼 변경 수·검토 대기 수·업데이트 주황 점 등)는 「더 보기」 칸에 합쳐 점이나 숫자로 보이고, 목록 안 각 항목에도 그대로 보인다.

**화면 키보드.** 입력칸·편집기에 포커스가 있고 화면 키보드가 올라와 있으면 바를 숨긴다. 판단은 `visualViewport` 의 높이가 창 높이보다 크게 줄었을 때(문턱은 빌더 몫). 키보드가 내려가면 다시 보인다.

## 상하단 색

**대상은 아이폰·안드로이드 둘 다(사용자).**

- `index.html`: `<meta name="theme-color" content="#3b6fd8">` 를 `media="(prefers-color-scheme: light)"`·`media="(prefers-color-scheme: dark)"` 두 벌로 바꾼다. 값은 위쪽 줄(탭·상단 바)의 배경색과 같은 앱 배경 토큰 — 밝은 테마·어두운 테마 각각(정확한 토큰은 빌더가 `styles.css` 의 `:root`·어두운 테마 블록에서 고른다).
- 설정에서 테마를 직접 고르면(`prefs.ts` 의 `applyTheme` 류 — `html[data-theme]` 를 두거나 지우는 자리) 두 메타의 `content` 를 그 테마의 색으로 맞춘다. 「시스템」 이면 미디어 쿼리 두 벌로 돌려 둔다.
- 하단 바의 배경도 같은 토큰이라, 안드로이드 하단 내비게이션 줄·아이폰 홈 표시줄 영역과 이어져 보인다.
- `manifest.webmanifest`: `theme_color` 를 밝은 배경색으로, `background_color`(실행 직후 화면)는 그대로 흰색.
- **아이폰 홈 화면 앱**: 상태 표시줄 모양은 `theme-color` 가 아니라 `apple-mobile-web-app-status-bar-style` 이 정한다. 밝은·어두운 테마 모두 상태 표시줄 뒤가 앱 배경색으로 보이게 고른다 — 예: `black-translucent` 로 본문을 상태 표시줄 밑까지 깔고 맨 위에 `env(safe-area-inset-top)` 만큼 앱 배경색 여백을 둔다(이 경우 상태 표시줄 글자가 흰색이라 밝은 테마에서 안 보이는지 확인해야 한다). 어느 방법도 두 테마를 다 맞추지 못하면 어느 테마에서 무엇이 남는지 `ux.md` 에 적는다. 방법 선택은 빌더 몫이되 위 조건을 지킨다.
- **안드로이드 하단 내비게이션 줄**: 색을 `theme-color` 가 정하지 않을 수 있다(브라우저·기기마다 다름). 하단 바 배경과 이어지지 않으면 그 사실을 `ux.md` 에 적는다 — 이 줄을 칠하려고 추가 장치를 만들지는 않는다.

## PWA 새 버전 알림

- **확인(내 결정):** 브라우저는 페이지를 새로 열 때만 새 워커를 찾으므로, 열어 둔 PWA 에서는 그대로 두면 새 버전을 거의 알아채지 못한다. 앱이 앞으로 돌아올 때(`visibilitychange` 가 보임으로) `registration.update()` 를 부른다. 너무 잦지 않게 마지막 확인 뒤 일정 시간(빌더 몫, 예: 30분)이 지났을 때만. 요청은 `sw.js` 하나이고 바뀌지 않았으면 작다 — 버린 「버전 API 를 주기적으로」 와 달리 새 API 가 없고 돌아올 때만 묻는다.
- **알림 조건(내 결정):** 빌드할 때 화면(번들)에도 서비스 워커와 같은 빌드 id 를 넣는다(`vite.config.ts` 의 서비스 워커 도장이 이미 빌드 id 를 만든다). 새 워커가 자리를 잡았을 때(`controllerchange`) **그 워커의 빌드 id 가 지금 화면의 빌드 id 와 다를 때만** 기존 알림(`toast`)으로 「새 버전이 있습니다」 와 「새로 고침」 단추를 띄운다 — 배포 뒤 처음 연 화면은 이미 새 빌드이므로 알리지 않는다. 처음 설치 때도 띄우지 않는다. 워커의 빌드 id 를 화면이 아는 방법(메시지, 캐시 이름 등)은 빌더 몫. 누르기 전에는 아무것도 바뀌지 않는다. 화면 글은 `messages/{en,ko}.json`.
- **새로 고침:** 단추를 누르면 저장되지 않은 문서를 먼저 저장(기존 저장 흐름 — 실패·충돌이면 새로 고치지 않고 그 상태를 보인다)한 뒤 `location.reload()`. **자동 저장이 꺼져 있고 저장 안 한 변경이 있으면 「저장하고 새로 고침 · 저장하지 않고 새로 고침 · 취소」 를 묻는다(내 결정 — 데스크톱 앱의 창 닫기와 같은 방식).** iOS 홈 화면 앱에서는 `beforeunload` 경고를 믿을 수 없으므로 이 물음이 유일한 안전장치다.
- **옛 캐시:** `sw.js` 의 `activate` 가 지금은 이 빌드 것이 아닌 `keyring-shell-*` 캐시를 모두 지운다. 바로 앞 빌드의 캐시 하나는 남기고 그보다 오래된 것만 지운다. 옛 화면이 새로 고치기 전에 옛 조각을 요청하면 그 캐시에서 받는다(`assets` 는 이미 캐시 우선이고 이름에 해시가 있어 섞이지 않는다). 「바로 앞」 을 아는 방법(캐시 이름 순서, 따로 적어 두기)은 빌더 몫.
- 데스크톱·모바일 앱(Tauri)은 서비스 워커를 쓰지 않으므로 해당 없다.

## 화면 글과 문서

- 하단 바 칸 이름·「더 보기」 목록·새 버전 알림 문구는 `messages/{en,ko}.json`(영어 기준). 칸 이름은 레일의 기존 키를 쓸 수 있으면 쓴다.

## 확인

- 390px 폭(iPhone)·412px(Android) 터치 에뮬레이션, 밝은·어두운 테마에서 바의 다섯 칸 동작, 키보드가 올라올 때 숨김, 본문 마지막 줄이 가리지 않음, 넓은 화면(1280px) 배치가 그대로인지.
- PWA: 빌드를 두 번 해 서비스 워커를 바꿨을 때 알림이 뜨는지, 새로 고치기 전 옛 화면에서 아직 안 불러온 조각(예: 아이콘 고르기 창)이 열리는지.
- 좁은 화면에서 위쪽 탭 줄·상태 표시줄이 없고, 오프라인·보낼 변경이 있을 때 「더 보기」 칸의 점과 목록 맨 위 상태가 보이는지. 서버 모드 로그아웃이 「더 보기」 에 있는지.
- 실제 휴대폰에서 상태 표시줄·홈 영역 색은 에뮬레이션으로 확인할 수 없다 — 확인하지 못했으면 그렇게 적는다.
