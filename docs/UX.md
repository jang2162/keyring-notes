# 사용성 개선 계획

Oct 7, 2026 · 기준 커밋 `4e77c7d`(8단계까지)

8단계까지 기능은 갖췄지만 매일 쓰기에는 불편하다. 이 문서는 사용자가 직접 느낀 불편 10가지와 코드·화면을 보고 찾은 문제를 묶어, 무엇을 어떤 순서로 고칠지 정리한다. 구현은 이 문서를 보고 따로 한다.

## 요약

화면이 "코드 편집기 + 관리 도구"처럼 보이는 것이 핵심 문제다. 기능마다 버튼·모달·배너를 하나씩 붙여 와서, 도구가 상단 한 줄과 사이드바 머리에 몰려 있고, 문서 편집 자체(제목·저장·트리)는 불편하다.

고치는 방향은 세 가지다.

1. **배치를 다시 짠다**: 왼쪽 아이콘 레일 + 왼쪽 패널, 위쪽 탭·문서 머리, 오른쪽 패널, 아래쪽 상태 표시줄.
2. **편집 흐름을 매끄럽게**: 자동 저장, 제목 인라인 수정, 트리에서 바로 만들기·이름 바꾸기·옮기기.
3. **겉모습을 한 체계로**: 아이콘 세트, 글꼴·간격·색 토큰, 설정 화면 하나.

```
┌레일┐┌ 왼쪽 패널(크기 조절·접기) ┐┌ 가운데 ─────────────────────────────┐┌ 오른쪽 패널(크기 조절·접기) ┐
```

- **왼쪽 레일**(세로 아이콘 줄): 파일, 검색, 태그, 오늘 노트, 그래프, 수집, 검토, 정리 점검. 아래쪽 끝에 설정·동기화·계정. 지금 사이드바 머리의 이모지 버튼 8개를 대신한다.
- **위쪽**: 탭 바는 늘 보인다(지금은 2개 이상일 때만 나타나 화면이 들썩인다). 문서 머리에는 경로(빵부스러기), 아이콘, 제목만 두고, 이동·삭제·이력·복제·경로 복사·내보내기는 `⋯` 메뉴로 보낸다. 삭제가 저장 옆에 노출된 지금 배치는 실수하기 쉽다.
- **오른쪽 패널**: 개요·백링크·출처·이력을 탭으로 모은다. 지금 백링크·출처(`References`)는 미리보기 칸 안에 있어서 "편집" 모드에서는 아예 안 보인다.
- **아래쪽 상태 표시줄**: 저장 상태, 동기화·오프라인·보낼 변경 수, 검토 대기 수, 글자 수, 커서 위치. 지금 화면 위쪽에 쌓이는 상태 배너(오프라인·보내는 중)가 여기로 온다.
- **그래프·정리 점검·검토**는 모달 대신 가운데 탭(또는 오른쪽 패널)으로 열어, 문서와 같이 볼 수 있게 한다. 수집·확인 대화상자처럼 짧게 끝나는 것만 모달로 둔다.
- **좁은 화면**: 레일은 아래쪽 탭 바로, 왼쪽·오른쪽 패널은 서랍으로 바뀐다(지금 ☰ 서랍을 넓힌다).

## 항목별 내용

### 1. 자동 저장 (P0, 사용자)

**지금**: 저장은 Ctrl/Cmd+S나 "저장" 버튼뿐이다. 저장 안 한 상태는 ●로만 보이고, 이동하려면 먼저 저장해야 한다("먼저 저장한 뒤 이동하세요"). 창을 닫을 때만 경고한다(`beforeunload`).

**제안**:
- 입력이 멈추고 약 1.5초 뒤, 탭을 바꿀 때, 창에서 포커스가 빠질 때 저장한다. 설정에서 끌 수 있게 한다.
- 상태 표시줄에 "저장 중… / 저장됨 / 저장 못 함(재시도)"을 보여 주고, "저장" 버튼은 없애거나 `⋯` 메뉴로 보낸다.
- 충돌은 지금처럼 3방향 병합을 쓰고, 같은 줄 충돌일 때만 묻는다. 자동 저장 중 충돌이 나면 자동 저장을 멈추고 배너 대신 상태 표시줄과 토스트로 알린다.

**주의**:
- **서버 모드는 저장 1번이 Git 커밋 1개다.** 그대로 자동 저장하면 이력이 몇 초 단위 커밋으로 가득 찬다. 둘 중 하나를 정해야 한다.
  - 같은 작성자가 같은 문서를 N분 안에 연달아 저장하면 직전 커밋에 합친다(amend). 이미 백업·동기화로 나간 커밋은 합치면 안 된다.
  - 디스크·인덱스에는 바로 쓰고 커밋만 묶어서(유휴 N분·탭 닫기·문서 이동 때) 남긴다. 그 사이 서버가 죽으면 다음 시작 때 "서버 밖 변경"으로 흡수된다.
- 해시가 자주 바뀌어 에이전트가 409를 더 자주 받는다. 에이전트는 다시 읽는 규약이라 괜찮지만, 웹훅 `doc.changed`가 몇 초마다 나가지 않게 커밋을 묶는 쪽이 낫다.
- 앱(LocalVault)은 저장마다 기록(journal)과 스냅샷이 쌓이고, 저장 10초 뒤 동기화가 돈다. 같은 방식으로 묶는다.
- 오프라인 대기열(PWA)도 저장마다 쌓이지 않도록 문서당 마지막 것만 남긴다.

### 2. 문서 제목 인라인 수정 (P0, 사용자)

**지금**: 화면 위쪽에는 경로(`폴더/문서.md`)가 글자로만 나온다. 이름을 바꾸려면 "이동"을 눌러 경로 전체를 다시 쳐야 한다.

**제안**: 에디터 맨 위에 큰 제목 칸(Obsidian의 inline title, SiYuan의 문서 제목)을 둔다. 고치고 Enter나 포커스 이탈 때 파일 이름을 바꾼다(8단계 링크 자동 갱신 사용). 탭 이름·트리도 바로 바뀐다.

**정할 것**:
- 제목 = 파일 이름으로 둔다(Obsidian 방식, 권장). 지금 색인은 프런트매터 `title` → 첫 `#` 제목 → 파일 이름 순으로 제목을 정한다. 프런트매터 `title`이 있는 문서는 제목 칸에 무엇을 보이고 무엇을 고칠지 정해야 한다(권장: 칸은 파일 이름, `title`은 속성 칸에서).
- 새 문서에 `# 제목` 줄을 자동으로 넣던 것(`createDoc`)은 제목 칸이 생기면 중복이다. 빼는 쪽을 권한다.
- 파일 이름에 못 쓰는 글자(`/ \ : * ? " < > |`, 앞의 `.`)는 입력 중에 막고 이유를 보여 준다.

### 3. 새 문서·이동 흐름 (P0, 발견)

**지금**: ＋를 누르면 "새 문서 경로 (.md 생략 가능)" 입력창이 뜬다. 이동도 경로를 입력하는 창이고, 그 전에 저장해야 한다.

**제안**:
- 새 문서는 지금 폴더(또는 트리에서 고른 폴더)에 "제목 없음"으로 바로 만들고, 제목 칸에 커서를 둔다. 같은 이름이 있으면 "제목 없음 2".
- 이동은 트리 끌어 놓기, 또는 폴더 고르기 창(검색되는 폴더 목록)으로 한다. 경로 직접 입력은 고급 기능으로만 남긴다.
- 자동 저장이 생기면 "먼저 저장" 제약은 저장 후 이동으로 바꿔 사용자에게 묻지 않는다.

### 4. 사이드바 크기 조절·접기 (P0, 사용자)

**지금**: `.sidebar { width: 260px }` 고정, 이력·개요 칸도 280px 고정이다.

**제안**:
- 왼쪽·오른쪽 패널 경계를 끌어서 크기 조절(최소·최대 폭), 두 번 누르면 기본 폭으로.
- 단축키로 접기·펴기, 접힌 상태와 폭은 이 기기에 기억한다.
- 가운데 본문은 읽기 폭(약 720~800px)을 가운데 정렬하고, "넓게 보기" 설정을 둔다. 지금은 화면이 넓으면 줄이 끝없이 길어진다.

### 5. 트리 사용성·아이콘 (P0, 사용자)

**지금**: `details/summary`와 링크로 그린다. 폴더·문서 아이콘이 없고, 첨부도 문서 사이에 섞여 나온다. 붙여넣은 이미지가 들어가는 `attachments/` 폴더가 문서 폴더마다 생겨 트리를 어지럽힌다. 오른쪽 클릭 메뉴, 끌어 옮기기, 이름 바꾸기, 키보드 이동이 없다.

**제안**:
- 아이콘: 폴더(열림·닫힘), 문서, 이미지·PDF·기타 첨부를 아이콘 세트로 구분한다. 문서 아이콘을 정했으면 그 아이콘을 쓴다(10번).
- 오른쪽 클릭(길게 누르기) 메뉴:
  - 폴더: 새 문서, 새 폴더
  - 공통: 이름 바꾸기(F2), 이동, 복제, 새 탭·옆 창에서 열기, 경로·링크 복사, 삭제
- 끌어 놓기로 이동(링크 자동 갱신), 놓을 자리 강조, 폴더 위에 잠시 머무르면 펼치기.
- 키보드: ↑↓ 이동, ←→ 접기·펴기, Enter 열기, F2 이름 바꾸기, Delete 삭제.
- 트리 위 작은 도구줄: 새 문서, 새 폴더, 모두 접기, 지금 문서 찾아 보이기, 정렬(이름·수정 시각).
- 표시 옵션: 첨부 숨기기 또는 아래로 모으기, `attachments` 폴더 숨기기. 들여쓰기 안내선, 지금 문서와 그 상위 폴더 강조.
- 첨부를 누르면 새 브라우저 탭으로 원본이 열리는 지금 동작(PDF 빼고)은 앱 안 보기로 바꾼다. 원본 열기는 메뉴로.

### 6. 키보드 단축키 (P0, 사용자)

**지금 있는 것**: Ctrl/Cmd+S 저장, Ctrl/Cmd+O 빠른 열기, Ctrl/Cmd+P·Shift+P 명령 팔레트, 에디터 기본 키(CodeMirror). 명령 팔레트에 단축키 표시는 2개뿐이다.

**제안 단축키**(Mod = macOS Cmd, 그 밖 Ctrl):

| 동작 | 키 | 비고 |
| --- | --- | --- |
| 빠른 열기 / 명령 팔레트 | Mod+O / Mod+P | 있음 |
| 새 문서 | Mod+N | 브라우저에서는 막힘 → Alt+N 대체 |
| 볼트 검색 / 문서 안 찾기 | Mod+Shift+F / Mod+F | 문서 안 찾기는 있음 |
| 탭 닫기 / 닫은 탭 다시 열기 | Mod+W / Mod+Shift+T | 브라우저에서는 막힘 → Alt+W 대체 |
| 다음·이전 탭 / N번째 탭 | Ctrl+Tab·Ctrl+Shift+Tab / Mod+1~9 | |
| 뒤로·앞으로(열어 본 문서) | Mod+Alt+← / → | 탐색 기록 필요 |
| 편집 ↔ 미리보기 | Mod+E | |
| 오른쪽으로 분할 | Mod+\ | |

**주의**:
- **브라우저(웹·PWA)에서는 Mod+W/N/T를 페이지가 가로챌 수 없다.** 웹은 대체 키를 쓰고 Tauri 앱만 원래 키를 쓴다. 한 표에 둘을 같이 보여 준다.
- 한글 입력 중(IME 조합 중) 키 처리를 거른다(`event.isComposing`).
- 설정에서 바꿀 수 있게 하고, 명령 팔레트의 모든 명령 옆에 키를 보여 준다.

### 7. 설정 페이지 분리 (P1, 사용자)

**지금**: 설정이 흩어져 있다.
- 관리 콘솔(서버 상태·에이전트·백업·업데이트·보안)은 앱 위를 덮는 전체 화면(`position: fixed`)이라, 문서로 돌아가려면 닫아야 하고 주소(URL)가 없다.
- 데일리 노트·템플릿은 명령 팔레트에서만 여는 작은 대화상자이고, 값은 이 기기 `localStorage`에만 있다(다른 기기·앱과 공유 안 됨).
- Live Preview·속성 칸·열린 탭은 버튼 상태로 `localStorage`에 따로 저장된다.

**제안**: 레일 아래 ⚙에서 여는 전체 화면 설정(`#/settings`). 왼쪽 목록 + 오른쪽 내용, 위에 설정 검색.

| 묶음 | 내용 |
| --- | --- |
| 일반 | 테마(시스템·밝게·어둡게), 시작 화면(홈·마지막 문서) |
| 편집기 | 글꼴·크기·줄 간격, 읽기 폭, 줄 번호, Live Preview 기본값, 자동 저장(켜기·간격), 맞춤법 검사 |
| 파일·링크 | 새 문서 위치, 첨부 폴더, 링크 형식(최단·전체 경로), 이동 때 링크 갱신, 삭제 확인 |
| 데일리·템플릿 | 지금 `NoteSettingsDialog` 내용 |
| 외관 | 아이콘 표시, 트리 표시 옵션, 상태 표시줄 항목 |
| 단축키 | 목록·바꾸기·초기화 |
| 이 기기·동기화 | 앱: 볼트 폴더, 서버 연결(지금 ⇅ 화면) |
| 서버 관리(소유자) | 지금 관리 콘솔의 탭들(상태·에이전트·백업·자동화·업데이트·보안·기기) |

**정할 것**: 설정을 어디에 두나.
- 이 기기만(테마·패널 폭·단축키)인 것과 모든 기기 공통(데일리·템플릿·첨부 폴더·링크 형식)인 것을 나눈다.
- 공통 설정을 볼트 안 파일로 두면 앱 동기화와 다른 편집기에 따라간다. 하지만 점 폴더는 동기화·API에서 빠지므로 위치를 따로 정해야 한다. 서버 설정에 두면 앱 오프라인 시작 때 읽을 수 없다.

### 8. 화면 분할 (P1, 사용자)

**지금**: "나란히"는 같은 문서의 원문과 미리보기를 나란히 보여 줄 뿐이다. 다른 문서 두 개를 같이 볼 수 없다.

**제안**:
- 가운데를 좌우(필요하면 위아래)로 나누고, 칸마다 자기 탭 바와 문서를 가진다. 탭은 칸 사이로 끌어 옮긴다.
- 링크를 Mod+클릭하면 옆 칸에서 연다. 칸 크기 조절, 칸 닫기.
- Live Preview를 기본으로 삼고, 지금 "나란히"는 "미리보기 옆에 띄우기"(같은 문서를 옆 칸 읽기 전용으로) 명령으로 바꾼다. 그래야 "분할"과 이름이 겹치지 않는다.
- 같은 문서를 두 칸에 열면 한 원본을 같이 편집해야 한다. 지금 `doc` 상태가 하나라서 상태 구조를 칸별로 바꾸는 작업이 크다. 먼저 상태를 "열린 문서 저장소 + 칸 배치"로 나누는 정리가 필요하다.

### 9. 투박한 겉모습 (P1, 사용자)

**지금**:
- 아이콘이 이모지(＋ 📅 📥 ✔ ◎ 🧹 ⚙ ⎋ ☰ ×)라 운영체제마다 다르게 보이고 굵기·크기가 제각각이다.
- 에디터가 고정폭 글꼴 + 줄 번호 + Live Preview 꺼짐이 기본이라 코드 편집기처럼 보인다.
- 도구가 글자 버튼(편집·나란히·미리보기·Aa·속성·저장·이동·삭제·이력·개요)으로 한 줄에 붙어 있다.
- 색은 토큰이 있지만 간격·글자 크기·둥글기·그림자 체계가 없다. 어두운 테마는 시스템 설정을 따를 뿐 직접 고를 수 없다.

**제안**:
- 아이콘 세트 하나로 통일(예: Lucide, MIT, 필요한 것만 묶을 수 있음). 이모지는 문서 아이콘(사용자 콘텐츠)에만 쓴다.
- 디자인 토큰: 간격(4px 단위), 글자 크기 단계, 둥글기, 그림자, 강조·위험·성공 색, 포커스 링. `styles.css`의 값들을 토큰으로 바꾼다.
- 에디터 기본값: 본문 글꼴(비례폭), Live Preview 켜짐, 줄 번호 끔, 읽기 폭 가운데 정렬. 코드 블록만 고정폭.
- 버튼: 아이콘 버튼 + 툴팁(단축키 포함), 눌림 상태, 크기 통일. 위험한 동작은 메뉴 안으로.
- 테마를 직접 고를 수 있게 한다.

### 10. 문서마다 아이콘 (P2, 사용자, SiYuan 참고)

SiYuan은 문서마다 이모지(또는 사용자 이미지) 아이콘을 정한다. 그 아이콘은 문서 트리·탭·제목 옆·링크에 같이 보이고, 선택으로 문서 위 배너(커버) 이미지도 둔다.

**제안**:
- 제목 칸 옆 아이콘 자리를 누르면 이모지 고르기 창(검색, 최근 쓴 것, 지우기)이 열린다.
- 저장은 프런트매터 `icon: 📘`. 마크다운 원본 원칙에 맞고, 다른 편집기에서도 깨지지 않으며, 에이전트도 읽을 수 있다.
- 보이는 곳: 트리, 탭, 문서 머리, 빠른 열기, 검색 결과, 위젯 목록, 그래프 노드(선택).
- 커버 이미지(`cover:` 첨부 경로)는 그다음에 고려한다.

**정할 것**: 폴더 아이콘은 프런트매터가 없다. 폴더 노트(폴더와 같은 이름의 문서)의 `icon`을 쓰거나, 공통 설정(7번) 파일에 둔다.

### 11. 백링크·출처 위치 (P1, 발견)

**지금**: 백링크·연결되지 않은 언급·출처·인용(`References`)이 미리보기 칸 맨 아래에 그려진다. "편집" 모드로 쓰면 볼 방법이 없고, 긴 문서는 끝까지 내려가야 보인다.

**제안**: 오른쪽 패널의 탭으로 옮기고, 개수를 탭 이름에 표시한다. 문서 끝에 두는 표시는 설정으로 남긴다(Obsidian의 "문서 끝 백링크").

### 12. 오류·알림 (P1, 발견)

**지금**: 오류도 "info" 모양 배너로 위쪽에 쌓이고, 눌러야 사라진다. 오프라인·충돌·과거 버전·자동 생성 문서 배너가 모두 같은 자리에 쌓여 본문을 밀어낸다.

**제안**:
- 금방 끝나는 결과(저장 실패·이동 완료·링크 N곳 고침)는 토스트(몇 초 뒤 사라짐, 되돌리기 버튼 가능)로.
- 오래 가는 상태(오프라인·보낼 변경)는 상태 표시줄로.
- 문서 자체 상태(충돌·과거 버전 보기·자동 생성 문서)만 배너로 남기고, 오류는 위험 색으로 구분한다.

### 13. 홈 화면 (P2, 발견)

**지금**: 문서를 안 열면 "왼쪽에서 문서를 고르거나 ＋ 로 새 문서를 만드세요." 한 줄만 나온다.

**제안**: 최근 문서, 고정(즐겨찾기) 문서, 오늘 노트, 검토 대기·정리 점검 요약, 빠른 검색 칸. 고정 기능은 트리 메뉴와 레일에서도 쓴다.

### 14. 휴지통 (P2, 발견)

**지금**: 삭제 확인 창은 "이력에서 되돌릴 수 있습니다"라고 하지만, 지운 문서는 트리에 없어서 그 이력을 열 방법이 화면에 없다.

**제안**: "삭제된 문서" 화면(Git 이력의 삭제 커밋에서 목록, 앱은 journal에서)에서 내용 보기·되살리기. 토스트의 "되돌리기"도 같은 기능을 쓴다. 에이전트에게는 지금처럼 숨김 경로가 보이지 않게 거른다.

### 15. 검색 (P2, 발견)

**지금**: 검색하면 트리 자리가 결과로 바뀐다. 결과에 줄 번호가 있지만 누르면 문서 처음이 열리고, 본문에서 검색어가 강조되지 않는다. 폴더·태그·경로를 고르는 칸이 없다(`#태그`만 문법으로).

**제안**: 결과를 누르면 그 줄로 가서 강조한다. 결과마다 일치 줄 여러 개를 보여 주고, 폴더·태그 필터와 정렬을 둔다. 레일의 검색 패널로 옮겨 트리와 따로 둔다.

## 구현 순서 제안

1. **기반**: 디자인 토큰·아이콘 세트, 패널 배치 틀(레일·왼쪽·가운데·오른쪽·상태 표시줄, 크기 조절·접기), 토스트. 이후 항목이 모두 이 틀 위에 올라간다.
2. **편집 흐름**: 자동 저장(커밋 묶기 결정 포함), 제목 인라인 수정, 새 문서·이동 흐름.
3. **트리**: 아이콘·메뉴·이름 바꾸기·끌어 옮기기·키보드.
4. **단축키 체계**: 명령 하나에 단축키·팔레트 항목·메뉴를 같이 등록하는 구조로(지금 팔레트 명령 목록을 확장).
5. **오른쪽 패널**: 개요·백링크·출처·이력 이동.
6. **설정 페이지**: 관리 콘솔·노트 설정 흡수, 기기 설정과 공통 설정 나누기.
7. **화면 분할**: 열린 문서 상태를 칸별 구조로 바꾼 뒤.
8. **문서 아이콘, 홈, 휴지통, 검색 개선**.

## 결정이 필요한 것

- **자동 저장과 Git 커밋**: 연속 저장을 직전 커밋에 합칠지(amend), 커밋만 묶어서 남길지. 백업·동기화로 이미 나간 커밋은 건드리지 않는다는 전제는 같다.
- **제목 = 파일 이름**으로 둘지, 프런트매터 `title`을 제목 칸에 쓸지.
- **공통 설정의 저장 위치**: 볼트 안 파일(어디에, 동기화 규칙은), 서버 설정, 기기별.
- **폴더 아이콘** 저장 방식.
- **"나란히" 모드의 운명**: Live Preview 기본 + "미리보기 옆에 띄우기"로 바꾸는 데 동의하는지.

## 확인한 방법과 한계

- 코드: `web/src/App.tsx`(배치·트리·단축키·새 문서·이동), `styles.css`(고정 폭·테마), `Editor.tsx`, `Palette.tsx`, `noteSettings.ts`, 각 모달 컴포넌트를 읽었다.
- 화면: 시험 서버(임시 볼트)에서 문서 화면을 브라우저로 확인했다. 관리 콘솔·그래프·좁은 화면은 화면으로 보지 못했다(브라우저 연결 끊김).
- 데스크톱 앱(Tauri, macOS)은 실행만 확인했고, 앱 창 안의 사용성은 따로 보지 않았다.

### 정한 것

- **자동 저장과 Git 커밋 → 직전 커밋에 합치기(amend)**. 웹이 자동 저장에 `coalesce: true`를 보내면, 서버는 같은 소유자가 같은 문서 하나만 고친 직전 커밋이 아직 HEAD이고 그 묶음을 시작한 지 10분 안이면 그 커밋에 합친다. 다른 커밋, 서버 밖 변경 흡수(백업 직전에 부른다)가 끼면 끊는다 — 백업에 들어간 커밋은 고쳐 쓰지 않는다. 에이전트 쓰기와 `Ctrl/Cmd+S`는 묶지 않는다. 디스크·색인은 저장마다 바로 바뀐다.
- **제목 = 파일 이름**(Obsidian 방식). 프런트매터 `title`은 속성 칸에서.
- **"나란히"는 남김**: Live Preview를 기본으로 하고 보기 전환에 그대로 둔다(원문과 미리보기를 나란히). 다른 문서를 같이 보는 것은 "옆 칸".
- **설정 저장 위치**: 이번에는 모두 이 기기(`localStorage`의 `keyring:prefs`, 데일리·템플릿은 지금처럼 `keyring:note-settings`). 기기 공통 설정 파일은 아직.

### 남은 것·알려진 한계

- 앱(LocalVault)은 자동 저장마다 기록(journal)·스냅샷이 하나씩 쌓인다(서버처럼 합치지 않는다). 기록 파일이 덧붙이기 전용이라 합치려면 기록 형식을 바꿔야 한다.
- 웹훅 `doc.changed`는 자동 저장이 합쳐질 때마다 새 `rev`로 다시 나간다. 몇 초 단위로 나가지 않게 묶는 것은 아직.
- 폴더 이름 바꾸기·옮기기는 안의 문서를 하나씩 옮긴다(문서마다 커밋, 중간 실패 시 일부만 옮겨짐). 첨부는 API가 옮기기를 지원하지 않아 첨부가 든 폴더는 막는다.
- 빈 폴더는 이력에 남지 않아, "새 폴더"는 그 안에 "제목 없음" 문서를 같이 만든다.
- 브라우저에서 `Ctrl+Tab`·`Ctrl+1~9`·`Ctrl+W`는 브라우저가 먼저 가져가 대체 키를 쓴다.
- 확인한 방법: 시험 서버(임시 볼트)와 `?local`(브라우저 로컬 볼트)에서 Chromium으로 새 문서→제목 바꾸기, 끌어 옮기기, F2, 검색→줄 이동, 옆 칸, 삭제→되돌리기, 단축키 창, 설정, 어두운 테마, 390px 화면을 눌러 보고 화면을 찍어 확인했다. 데스크톱 앱(Tauri) 창 안과 실제 터치 기기는 보지 못했다.
