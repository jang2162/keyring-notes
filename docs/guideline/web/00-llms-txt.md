# llms.txt

## 서비스는 루트 경로 `/llms.txt` 로 에이전트용 사용 안내를 낸다

배포된 서비스의 `GET /llms.txt` 가 Markdown 본문을 `text/plain; charset=utf-8` 로 돌려준다. 형식은 [llmstxt.org](https://llmstxt.org/) 를 따른다: 첫 줄 `# <서비스 이름>`, 다음에 `> <한두 문장 요약>`, 그 뒤 `##` 절.

담을 것:

- 무엇을 하는 서비스이고 누가 쓰는가
- 준비: 설치할 CLI·패키지, 로그인과 토큰 발급 방법
- 주요 사용법: 자주 쓰는 명령이나 요청과 그 결과
- API: 엔드포인트, 인증 방식, 응답 코드
- 지킬 것: 쓰는 쪽이 하면 안 되는 일

비밀값과 내부망 주소는 담지 않는다. 로그인 방법을 담는 문서이므로 llms.txt 자체는 로그인 없이 읽혀야 한다.

- **Why:** 서비스를 쓰는 에이전트는 사용법을 먼저 `<주소>/llms.txt` 에서 찾는다. 이 파일이 없으면 에이전트는 화면이나 소스를 뒤지거나 추측으로 API 를 부르고, 틀린 호출은 서비스가 아니라 그것을 쓰는 프로젝트 쪽에서 실패로 드러난다.
- **How to apply:** 배포한 뒤 아래로 응답과 첫 줄을 확인한다.

  ```bash
  curl -sI <주소>/llms.txt | grep -i content-type
  curl -s <주소>/llms.txt | head -3
  ```

## llms.txt 에 적는 서비스 주소는 하드코딩하지 않고 그 서버의 설정에서 채운다

본문의 명령·API 예시에 들어가는 주소는 요청을 받은 그 서버의 공개 주소 설정으로 채워서 낸다. 정적 파일이라면 배포할 때 주소를 바꿔 넣는다.

- **Why:** 같은 코드를 여러 곳(스테이징, 다른 팀의 서버)에 배포하면 하드코딩한 주소는 다른 서버를 가리킨다. 에이전트는 llms.txt 의 명령을 그대로 복사해 쓰므로 엉뚱한 서버에 쓰게 된다.
- **How to apply:** llms.txt 원본에서 `https://` 로 시작하는 서비스 자신의 주소를 찾아, 주소 설정 값으로 바꾼다. 바꾼 뒤 배포한 두 곳 이상에서 `curl -s <주소>/llms.txt` 로 각자의 주소가 나오는지 본다.

## 사용법을 바꾸는 변경은 같은 변경에서 llms.txt 도 고친다

라우트, API 요청·응답 형식, CLI 명령·옵션, 인증 방식을 바꾸거나 더하거나 지우면 같은 커밋에서 llms.txt 를 고친다.

- **Why:** llms.txt 가 낡아도 테스트는 깨지지 않는다. 에이전트는 옛 명령과 엔드포인트를 그대로 따르고, 실패는 이 서비스를 쓰는 다른 프로젝트에서 늦게 드러난다.
- **How to apply:** 커밋 전에 diff 에 라우트·CLI·인증 코드가 있으면 llms.txt 의 해당 절을 다시 읽고 고친다. llms.txt 를 서버 코드에서 만든다면, 적힌 엔드포인트 목록이 실제 라우트와 같은지 확인하는 테스트를 둔다.

## 에이전트용 사용법의 정본은 llms.txt 하나로 두고, 다른 곳에는 옮겨 적지 않고 가리킨다

이 서비스를 쓰는 프로젝트의 지침이나 `AGENTS.md` 에는 「정본은 `<주소>/llms.txt`」 라고 가리키고, 거기서 놓치기 쉬운 것만 적는다. 명령·스키마·엔드포인트 목록을 옮겨 적지 않는다.

- **Why:** 두 곳에 적으면 서비스가 바뀔 때 llms.txt 만 고쳐지고, 옮겨 적은 쪽은 낡은 채 남아 에이전트가 어느 쪽을 따를지 모른다.
- **How to apply:** 지침에 서비스의 사용법을 쓰려 하면 먼저 그 내용이 llms.txt 에 있는지 본다. 있으면 링크로 바꾸고, 없으면 llms.txt 에 더한다.
