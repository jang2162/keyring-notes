# 문체와 표기

## 한 문장에 한 내용, 같은 대상에는 같은 이름을 쓴다

- **어조(영어):** 독자를 「you」 로 부르고 현재형·능동태로 쓴다. 단계 안내는 명령형으로 시작한다(「Run the following command.」). 「simply」, 「just」, 「easy」 는 쓰지 않는다.
- **어조(한국어):** 「~합니다」 체로 통일하고, 지시할 때는 「~하세요」 를 쓴다.
- **문장:** 한 문장에 한 가지 내용만 쓰고, 25단어를 넘으면 나눈다. 「간단히」, 「쉽게」 같은 표현은 쓰지 않는다.
- **용어:** 같은 대상은 문서 전체에서 같은 이름으로 부른다. 처음 나오는 약어는 풀어 쓴다. 영어 원어와 번역어의 대응은 `docs/manual/glossary.md` 에 표로 모은다.
- **번역할 때 원문 유지:** 제품 이름·명령·파일 이름·설정 키·코드는 번역하지 않는다. UI 버튼 이름은 사용자가 실제로 보는 화면 언어 그대로 굵게 쓴다(**Save** 클릭).

- **Why:** 독자는 처음 쓰는 사용자라, 같은 것을 다른 이름으로 부르면 다른 것으로 읽는다. 「쉽게」 는 막힌 독자에게 아무것도 알려 주지 않는다.
- **How to apply:** 새 용어를 쓰면 `docs/manual/glossary.md` 에 이미 있는 이름인지 먼저 본다.

## 코드·링크·강조는 정한 문법으로 쓴다

- **코드 블록:** 언어를 늘 지정한다(` ```bash `, ` ```python `). 명령과 출력은 다른 블록으로 나눈다. 코드 안의 주석은 번역본에서도 영어로 둔다.
- **인라인 코드:** 파일 이름, 경로, 명령, 설정 키, 값은 백틱으로 감싼다.
- **링크:** 링크 글은 이동할 곳을 말한다(「여기」 대신 「설정 문서」). 저장소 안 문서는 상대 경로로, 같은 언어의 문서에 잇는다.
- **강조:** 굵게는 한 단락에 한 번 이하로 쓴다. 경고는 GitHub 알림 문법을 쓴다(`> [!NOTE]`, `> [!WARNING]`).

- **Why:** 명령과 출력이 한 블록에 있으면 복사한 그대로 실행되지 않는다. 다른 언어 문서로 가는 링크는 번역본 독자를 원본으로 빼낸다.
- **How to apply:** 링크를 쓴 뒤 GitHub 화면에서 눌러 같은 언어의 문서가 열리는지 본다.
