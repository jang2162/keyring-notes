# README 구조와 섹션

## README 는 정한 순서의 섹션만 두고, 빈 섹션을 남기지 않는다

필수 섹션은 모든 저장소에 넣고, 선택 섹션은 내용이 있을 때만 넣는다. 빈 섹션, 「작성 예정」, `TODO` 는 남기지 않는다.

| 순서 | 섹션 | 영문 제목 (`README.md`) | 구분 | 답하는 질문 |
| --- | --- | --- | --- | --- |
| 0 | 언어 전환 줄 | English \| 한국어 링크 | 필수 | 다른 언어로 볼 수 있나? |
| 1 | 제목 + 한 줄 설명 | (프로젝트 이름) | 필수 | 이게 뭐지? |
| 2 | 배지 | — | 선택 | 유지되고 있나? 어떤 버전인가? |
| 3 | 대표 이미지·데모 GIF | — | 필수(UI 가 있을 때) | 실제로 어떻게 생겼나? |
| 4 | 간단한 소개 | Overview | 필수 | 왜 만들었고 누구를 위한 건가? |
| 5 | 주요 기능 | Features | 필수 | 무엇을 할 수 있나? |
| 6 | 설치 | Installation | 필수 | 어떻게 설치하나? |
| 7 | 빠른 시작 | Quick Start | 필수 | 가장 간단하게 어떻게 써 보나? |
| 8 | 설정 | Configuration | 선택 | 어떻게 바꿔서 쓰나? |
| 9 | 문서 링크 | Documentation | 선택 | 더 자세한 내용은 어디에? |
| 10 | FAQ·문제 해결 | FAQ / Troubleshooting | 선택 | 막히면 어떻게 하나? |
| 11 | 기여 방법 | Contributing | 선택 | 어떻게 참여하나? |
| 12 | 후원 | Support | 선택 | 어떻게 지원할 수 있나? |
| 13 | 라이선스 | License | 필수 | 어떤 조건으로 쓸 수 있나? |

목차는 섹션이 6개 이상이고 README 가 화면 세 장을 넘을 때만 넣는다.

- **Why:** 첫 화면에서 30초 안에 판단하게 하려면 질문의 순서대로 답이 나와야 한다. GitHub 는 README 오른쪽 위에 자동 목차 버튼을 주므로 짧은 README 의 목차는 자리만 차지한다.
- **How to apply:** 새 저장소는 이 스택 「README 템플릿」 의 뼈대에서 시작한다. 후원은 「후원 링크」, 이미지는 「이미지·GIF」, 언어 전환 줄은 「다국어 문서」 를 따른다.

## 섹션마다 정한 분량과 내용으로 쓴다

**제목과 한 줄 설명**

- 제목은 저장소 이름과 같게 쓴다. 로고가 있으면 제목 위에 가운데 정렬로 넣는다.
- 바로 아래 한 줄 설명은 「무엇을 + 누구를 위해 + 어떻게」 를 20단어 안에 담는다. 좋은 예: 「터미널에서 마크다운 파일을 실시간으로 미리 보는 CLI 도구」. 나쁜 예: 「마크다운 관련 프로젝트입니다」, 「최고의 생산성 도구」.
- 한 줄 설명은 GitHub 저장소의 About 설명과 같게 둔다.

**배지**

- 빌드 상태, 최신 버전, 라이선스 등 3~5개만 한 줄에 나란히 넣는다. 의미 없는 배지(언어 종류, 방문자 수)는 넣지 않는다. 깨진 배지는 바로 지운다.

**간단한 소개**

- 3~5문장으로, 해결하는 문제 → 이 프로젝트의 해결 방법 → 기존 대안과의 차이 순서로 쓴다.
- 대상 사용자를 밝힌다(예: 「Python 3.10 이상을 쓰는 데이터 분석가」). 기술 스택 나열로 시작하지 않는다.

**주요 기능**

- 3~7개의 불릿, 각 항목은 동사로 시작하는 한 줄이다.
- 기능 이름보다 사용자가 얻는 결과를 쓴다(「캐시 지원」 → 「같은 요청을 다시 보내지 않아 실행이 2배 빨라짐」).
- 지원 예정 기능은 별도의 로드맵으로 나누고 현재 기능과 섞지 않는다.

**설치**

- 요구 사항(OS, 런타임 버전, 필요한 도구)을 먼저 쓴다.
- 명령은 복사해 그대로 실행되게 코드 블록에 넣고, 프롬프트 기호(`$`)는 붙이지 않는다.
- 설치 방법이 여럿이면 가장 일반적인 하나를 먼저 쓰고 나머지는 접거나 `docs/manual/` 로 보낸다.
- 설치 성공을 확인하는 명령과 예상 출력을 함께 쓴다(예: `mytool --version`).

**빠른 시작**

- 가장 흔한 사용 사례 하나를 3단계 이내로 보이고, 입력 명령(또는 코드)과 실제 출력을 함께 보인다.
- 치환할 값은 `<YOUR_API_KEY>` 처럼 표시한다.

**설정**

- 항목이 5개 이하면 표(항목 · 기본값 · 설명)로 README 에 넣는다. 그보다 많으면 `docs/manual/<lang>/configuration.md` 로 나누고 링크만 둔다.

**FAQ·문제 해결**

- 실제 이슈로 반복해 들어온 질문만, 사용자가 겪는 증상 그대로 쓴다. 답이 길면 `docs/manual/<lang>/troubleshooting.md` 로 잇는다.

**기여 방법과 라이선스**

- 기여 방법은 2~3줄 요약 뒤 `CONTRIBUTING.md` 로 잇는다.
- 라이선스는 이름과 `LICENSE` 링크만 쓴다(예: 「MIT License. See LICENSE for details.」).

- **Why:** 5분 안에 첫 실행에 성공하게 하려면 설치·빠른 시작의 명령이 복사한 그대로 돌아야 한다. 실행해 보지 않은 예제는 첫 실행에서 틀어진다.
- **How to apply:** 설치·빠른 시작의 예제는 실제로 실행해 확인한 것만 넣는다. 확인은 이 스택 「배포 전 확인」 의 목록으로 한다.
