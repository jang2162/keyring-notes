# 페이지 자동화 도구를 얹을 때

## 새 브라우저를 띄우지 말고 이미 로그인된 브라우저의 CDP 에 붙는다

브라우저 도구가 못 하는 것(첫 로드 콘솔, 상태 코드가 보이는 네트워크, 뷰포트 변경)이 필요하면 **그 브라우저가 열어 둔 CDP 에 붙는다.**

- **Why:** 같은 브라우저·같은 프로필·같은 로그인을 그대로 쓰면서 그 넷이 전부 열린다. 반대로 **새 브라우저를 띄우면 로그인을 잃어 붙이는 목적 자체가 사라진다.**
- **How to apply:**
  - **예외 — 로그인이 필요 없는 검증에서 둘 중 하나가 필요하면 독립 브라우저를 띄운다**(자동화 도구가 자체 브라우저를 띄우는 모드). ① **보이는 탭이어야 도는 것**(`requestAnimationFrame`·`ResizeObserver`·캔버스 렌더)을 잰다 — 사람의 화면을 뺏지 않으려고 백그라운드로 연 탭은 `visibilityState` 가 `hidden` 이라 이것들이 돌지 않고, 멈춘 렌더가 고치려는 렌더 결함과 구분되지 않는다. ② **다른 계정의 둘째 클라이언트**가 필요하다 — 한 프로필은 쿠키를 공유해 두 계정이 서로를 덮는다(「여러 세션이 한 브라우저를 볼 때」). 독립 브라우저는 headless 여도 `visible` 이다.
  - CDP 포트는 **그 브라우저의 설정이 갖는다.** 포트 번호를 지침에 박지 말고 설정에서 읽는다.
  - ⚠ **새 브라우저를 띄우는 옵션(`--isolated`·`--browser` 류)을 주지 않는다.**
  - 상시로 쓸 거면 **기존 엔트리를 고치지 말고 별도 엔트리로 더한다** — 원래 엔트리를 쓰던 자리가 조용히 바뀐다.
  - 한 번만 필요하면 브라우저를 내려받지 않는 코어 패키지로 붙인다. 끝낼 때 **연결만 끊는다** — 브라우저는 살려 둔다.

## 붙기 전에 page 대상이 하나라도 있는지 본다

- **Why:** page 대상이 **하나도 없으면 CDP 연결이 곧바로 끊긴다**(`Browser context management is not supported.`). 다시 시도해도 같다. 그리고 **붙은 뒤에 쓰는 API 로는 그 탭을 만들 수 없다** — 붙기 전에 만들어야 한다.
- **How to apply:**
  - 붙기 전에 `/json/list` 를 보고 `"type": "page"` 가 없으면 **원시 CDP 로 빈 탭을 하나 백그라운드로 만든다**(`Target.createTarget` 에 `background: true`). 하나만 생기면 같은 호출이 곧바로 붙는다.
  - ⚠ **스크립트가 자기 탭을 닫을 때 그것이 마지막 page 대상이면 닫지 않는다** — 닫으면 다음 연결부터 막힌다.

## 붙은 뒤에도 탭은 백그라운드로 만들고, 한 탭을 양쪽에서 번갈아 만지지 않는다

- **Why — 백그라운드:** 자동화 도구의 기본 탭 생성은 **브라우저 창을 최전면으로 끌어올린다.** `base` 스택 「에이전트 기본」의 손해가 이쪽에서 그대로 난다.
- **Why — 한쪽이 조작:** 자동화 도구가 연 탭은 브라우저 도구 쪽에서 **사람의 탭으로 분류될 수 있다.** 막히지는 않아도, 양쪽이 번갈아 만지면 서로의 상태 가정이 깨지고 누가 닫을지도 흐려진다.
- **How to apply:**
  - 탭은 `Target.createTarget` 에 `background: true` 를 주어 만든 뒤 그 탭을 찾아 쓴다. **탭을 앞으로 가져오는 호출도 부르지 않는다.**
  - **한 탭을 열어 두고 `goto` 로 옮겨 쓰면 새로 열 일 자체가 줄어든다.**
  - **조작은 한쪽이 맡고 다른 쪽은 관찰만 한다.** 끝나면 **연 쪽이 닫는다** — 다른 쪽 목록에서는 사람의 탭처럼 보여 아무도 닫지 않는다.
