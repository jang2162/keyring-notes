# 여러 세션이 한 브라우저를 볼 때

## 탭 소유권은 막아 주지 않고, 로그인 세션은 갈리지 않는다

- **Why:** 탭마다 소유자를 **표시하는** 도구도 남의 탭 조작을 **막지 않을 수 있다** — 남의 탭을 옮기거나 닫아도 안내 문구만 붙고 그대로 된다. 막힌다고 가정하고 만지면 사람이나 다른 세션이 보던 화면을 흩뜨린다. 서로의 탭을 밟지 않는 것은 도구가 아니라 **각 세션의 규율**이다. **그리고 프로필이 하나라 쿠키는 공유된다** — 같은 호스트에 붙은 두 세션은 세션 쿠키 **한 칸**을 두고 서로를 덮는다. 한쪽이 로그인하는 순간 다른 쪽이 끊기고, 그 반대도 같다.
- **How to apply:**
  - 같은 앱의 인스턴스를 둘 이상 띄울 때는 **세션 쿠키 이름을 갈라야 한다**(`base` 스택 「워크트리가 함께 쓰는 자원」의 「머신 전역 자원은 워크트리가 공유한다」).
  - **자기 탭만 쓰고, 탐색은 새 탭에서 한다.** 누구의 탭인지는 탭 목록의 분류로 판단한다 — 조작 결과에 붙는 안내 문구는 소유자를 틀리게 적을 수 있다.
  - ⚠ **세션 정체성이 갈리면 먼저 연 탭이 남의 탭으로 표시될 수 있다.** 표시가 바뀌어도 닫을 수 있으면 새 세션에서 탭 목록의 주소로 자기가 연 탭을 찾아 **직접 닫는다.** 닫히지 않을 때만 사람에게 닫아 달라고 말한다.
  - 브리프에 **「네가 연 탭은 네가 닫아라」**를 넣는다 — 워커가 여럿이면 닫히지 않은 탭이 쌓인다.
