# 사용성 개선 계획

Oct 7, 2026 · 기준 커밋 `4e77c7d`(8단계까지)

8단계까지 기능은 갖췄지만 매일 쓰기에는 불편하다. 이 문서는 사용자가 직접 느낀 불편 10가지와 코드·화면을 보고 찾은 문제를 묶어, 무엇을 어떤 순서로 고칠지 정리한다. 구현은 이 문서를 보고 따로 한다.

## 요약

화면이 "코드 편집기 + 관리 도구"처럼 보이는 것이 핵심 문제다. 기능마다 버튼·모달·배너를 하나씩 붙여 와서, 도구가 상단 한 줄과 사이드바 머리에 몰려 있고, 문서 편집 자체(제목·저장·트리)는 불편하다.

고치는 방향은 세 가지다.

1. **배치를 다시 짠다**: 왼쪽 아이콘 레일 + 왼쪽 패널, 위쪽 탭·문서 머리, 오른쪽 패널, 아래쪽 상태 표시줄.
2. **편집 흐름을 매끄럽게**: 자동 저장, 제목 인라인 수정, 트리에서 바로 만들기·이름 바꾸기·옮기기.
3. **겉모습을 한 체계로**: 아이콘 세트, 글꼴·간격·색 토큰, 설정 화면 하나.

```
┌레일┐┌ 왼쪽 패널(크기 조절·접기) ┐┌ 가운데 ─────────────────────────────┐┌ 오른쪽 패널(크기 조절·접기) ┐
│ 📁 ││ 파일 트리 / 검색 / 태그   ││ 탭 바(늘 보임, 분할 창마다 하나씩)     ││ 개요                        │
│ 🔍 ││ (레일에서 고른 것)        ││ 문서 머리: 경로 › 아이콘 제목(인라인)  ││ 백링크·연결되지 않은 언급    │
│ 🏷 ││                          ││        보기 전환 · ⋯ 메뉴             ││ 출처·인용                   │

│ ✔  ││                          ││                                      ││                             │
│ ⚙  ││                          ││                                      ││                             │

```

- **왼쪽 레일**(세로 아이콘 줄): 파일, 검색, 태그, 오늘 노트, 그래프, 수집, 검토, 정리 점검. 아래쪽 끝에 설정·동기화·계정. 지금 사이드바 머리의 이모지 버튼 8개를 대신한다.
- **위쪽**: 탭 바는 늘 보인다(지금은 2개 이상일 때만 나타나 화면이 들썩인다). 문서 머리에는 경로(빵부스러기), 아이콘, 제목만 두고, 이동·삭제·이력·복제·경로 복사·내보내기는 `⋯` 메뉴로 보낸다. 삭제가 저장 옆에 노출된 지금 배치는 실수하기 쉽다.
- **오른쪽 패널**: 개요·백링크·출처·이력을 탭으로 모은다. 지금 백링크·출처(`References`)는 미리보기 칸 안에 있어서 "편집" 모드에서는 아예 안 보인다.
- **아래쪽 상태 표시줄**: 저장 상태, 동기화·오프라인·보낼 변경 수, 검토 대기 수, 글자 수, 커서 위치. 지금 화면 위쪽에 쌓이는 상태 배너(오프라인·보내는 중)가 여기로 온다.
- **그래프·정리 점검·검토**는 모달 대신 가운데 탭(또는 오른쪽 패널)으로 열어, 문서와 같이 볼 수 있게 한다. 수집·확인 대화상자처럼 짧게 끝나는 것만 모달로 둔다.
- **좁은 화면**: 레일은 아래쪽 탭 바로, 왼쪽·오른쪽 패널은 서랍으로 바뀐다(지금 ☰ 서랍을 넓힌다).

## 항목별 내용

각 항목의 「지금」은 요청을 받았을 때의 모습이다. 지금 동작은 「구현 현황」 절에 있다.

### 1. 자동 저장 (P0, 사용자)

**지금**: 저장은 Ctrl/Cmd+S나 "저장" 버튼뿐이다. 저장 안 한 상태는 ●로만 보이고, 이동하려면 먼저 저장해야 한다("먼저 저장한 뒤 이동하세요"). 창을 닫을 때만 경고한다(`beforeunload`).

**제안**:
- 입력이 멈추고 약 1.5초 뒤, 탭을 바꿀 때, 창에서 포커스가 빠질 때 저장한다. 설정에서 끌 수 있게 한다.
- 상태 표시줄에 "저장 중… / 저장됨 / 저장 못 함(재시도)"을 보여 주고, "저장" 버튼은 없애거나 `⋯` 메뉴로 보낸다.
- 충돌은 지금처럼 3방향 병합을 쓰고, 같은 줄 충돌일 때만 묻는다. 자동 저장 중 충돌이 나면 자동 저장을 멈추고 배너 대신 상태 표시줄과 토스트로 알린다.

**주의**:
- **서버 모드는 저장 1번이 Git 커밋 1개다.** 그대로 자동 저장하면 이력이 몇 초 단위 커밋으로 가득 찬다. 둘 중 하나를 정해야 한다.
  - 같은 작성자가 같은 문서를 N분 안에 연달아 저장하면 직전 커밋에 합친다(amend). 이미 백업·동기화로 나간 커밋은 합치면 안 된다.
  - 디스크·인덱스에는 바로 쓰고 커밋만 묶어서(유휴 N분·탭 닫기·문서 이동 때) 남긴다. 그 사이 서버가 죽으면 다음 시작 때 "서버 밖 변경"으로 흡수된다.
- 해시가 자주 바뀌어 에이전트가 409를 더 자주 받는다. 에이전트는 다시 읽는 규약이라 괜찮지만, 웹훅 `doc.changed`가 몇 초마다 나가지 않게 커밋을 묶는 쪽이 낫다.
- 앱(LocalVault)은 저장마다 기록(journal)과 스냅샷이 쌓이고, 저장 10초 뒤 동기화가 돈다. 같은 방식으로 묶는다.
- 오프라인 대기열(PWA)도 저장마다 쌓이지 않도록 문서당 마지막 것만 남긴다.

### 2. 문서 제목 인라인 수정 (P0, 사용자)

**지금**: 화면 위쪽에는 경로(`폴더/문서.md`)가 글자로만 나온다. 이름을 바꾸려면 "이동"을 눌러 경로 전체를 다시 쳐야 한다.

**제안**: 에디터 맨 위에 큰 제목 칸(Obsidian의 inline title, SiYuan의 문서 제목)을 둔다. 고치고 Enter나 포커스 이탈 때 파일 이름을 바꾼다(8단계 링크 자동 갱신 사용). 탭 이름·트리도 바로 바뀐다.

**정할 것**:
- 제목 = 파일 이름으로 둔다(Obsidian 방식, 권장). 지금 색인은 프런트매터 `title` → 첫 `#` 제목 → 파일 이름 순으로 제목을 정한다. 프런트매터 `title`이 있는 문서는 제목 칸에 무엇을 보이고 무엇을 고칠지 정해야 한다(권장: 칸은 파일 이름, `title`은 속성 칸에서).
- 새 문서에 `# 제목` 줄을 자동으로 넣던 것(`createDoc`)은 제목 칸이 생기면 중복이다. 빼는 쪽을 권한다.
- 파일 이름에 못 쓰는 글자(`/ \ : * ? " < > |`, 앞의 `.`)는 입력 중에 막고 이유를 보여 준다.

### 3. 새 문서·이동 흐름 (P0, 발견)

**지금**: ＋를 누르면 "새 문서 경로 (.md 생략 가능)" 입력창이 뜬다. 이동도 경로를 입력하는 창이고, 그 전에 저장해야 한다.

**제안**:
- 새 문서는 지금 폴더(또는 트리에서 고른 폴더)에 "제목 없음"으로 바로 만들고, 제목 칸에 커서를 둔다. 같은 이름이 있으면 "제목 없음 2".
- 이동은 트리 끌어 놓기, 또는 폴더 고르기 창(검색되는 폴더 목록)으로 한다. 경로 직접 입력은 고급 기능으로만 남긴다.
- 자동 저장이 생기면 "먼저 저장" 제약은 저장 후 이동으로 바꿔 사용자에게 묻지 않는다.

### 4. 사이드바 크기 조절·접기 (P0, 사용자)

**지금**: `.sidebar { width: 260px }` 고정, 이력·개요 칸도 280px 고정이다.

**제안**:
- 왼쪽·오른쪽 패널 경계를 끌어서 크기 조절(최소·최대 폭), 두 번 누르면 기본 폭으로.
- 단축키로 접기·펴기, 접힌 상태와 폭은 이 기기에 기억한다.
- 가운데 본문은 읽기 폭(약 720~800px)을 가운데 정렬하고, "넓게 보기" 설정을 둔다. 지금은 화면이 넓으면 줄이 끝없이 길어진다.

### 5. 트리 사용성·아이콘 (P0, 사용자)

**지금**: `details/summary`와 링크로 그린다. 폴더·문서 아이콘이 없고, 첨부도 문서 사이에 섞여 나온다. 붙여넣은 이미지가 들어가는 `attachments/` 폴더가 문서 폴더마다 생겨 트리를 어지럽힌다. 오른쪽 클릭 메뉴, 끌어 옮기기, 이름 바꾸기, 키보드 이동이 없다.

**제안**:
- 아이콘: 폴더(열림·닫힘), 문서, 이미지·PDF·기타 첨부를 아이콘 세트로 구분한다. 문서 아이콘을 정했으면 그 아이콘을 쓴다(10번).
- 오른쪽 클릭(길게 누르기) 메뉴:
  - 폴더: 새 문서, 새 폴더
  - 공통: 이름 바꾸기(F2), 이동, 복제, 새 탭·옆 창에서 열기, 경로·링크 복사, 삭제
- 끌어 놓기로 이동(링크 자동 갱신), 놓을 자리 강조, 폴더 위에 잠시 머무르면 펼치기.
- 키보드: ↑↓ 이동, ←→ 접기·펴기, Enter 열기, F2 이름 바꾸기, Delete 삭제.
- 트리 위 작은 도구줄: 새 문서, 새 폴더, 모두 접기, 지금 문서 찾아 보이기, 정렬(이름·수정 시각).
- 표시 옵션: 첨부 숨기기 또는 아래로 모으기, `attachments` 폴더 숨기기. 들여쓰기 안내선, 지금 문서와 그 상위 폴더 강조.
- 첨부를 누르면 새 브라우저 탭으로 원본이 열리는 지금 동작(PDF 빼고)은 앱 안 보기로 바꾼다. 원본 열기는 메뉴로.

**주의**:

**창 닫기**(`web/src/closeWindow.ts`, `app/src-tauri/src/close_guard.rs`, 2026-10-26, 묻기 2026-10-27): 창이 여럿일 때 단축키로 창을 닫는다. 명령 `close-window`(탭 묶음, 팔레트·단축키 설정에 나온다), 기본 키 Mod+Shift+W.
- 데스크톱 앱(주 창·새 창)에만 둔다. 웹은 브라우저가 Mod+Shift+W 를 먼저 가져가고 `window.close()` 도 스크립트로 연 창에만 먹으며, 모바일 앱은 창이 하나다. 웹의 새 창(`?solo`)은 `window.open` 으로 연 팝업이라 `window.close()` 가 먹으므로 대체 키(예: Alt+Shift+W)로 둘 수는 있다 — 지금은 두지 않았다.
- **정한 것(사용자): 저장 안 한 변경이 있으면 어느 길로 닫든 무조건 묻는다.** 묻지 않고 버리는 길도, 묻지 않고 몰래 저장하는 길도 두지 않는다.
  - 물음 하나, 단추 셋: 「저장하고 닫기」(기본·Enter) / 「저장하지 않고 닫기」 / 「취소」(Esc). 저장 안 한 노트 이름을 들고, 셋이 넘으면 몇 개인지와 앞의 셋. 자동 저장이 켜져 있어도 저장하기 전에 먼저 묻는다(앞 회차의 「먼저 저장 → 남은 것만 묻기」는 없앴다). 대화상자는 `dialog.ts` 의 `chooseDialog`(확인 단추 왼쪽에 단추를 더 둔다).
  - 「저장하고 닫기」는 자동 저장 설정과 상관없이 모두 저장하고, **다 저장됐을 때만** 닫는다. 남은 것(충돌 중·저장 실패)이 있으면 닫지 않고 그 노트를 들어 알린다(저장 실패 자체는 기존 「저장하지 못했습니다」 알림도 뜬다). 오프라인이라 기기 대기열에 넣은 것은 저장으로 본다 — 저장 표시가 「대기 중」으로 바뀌고 저장 안 한 변경에서 빠지는 지금 앱의 정의를 따른다.
  - 「저장하지 않고 닫기」는 초안을 버리고 닫는다. 다시 묻지 않는다.
  - 물음이 떠 있는 동안과 **닫기로 정한 뒤 창이 사라질 때까지** 자동 저장(타이머·창 blur·숨김·편집기 이탈 저장)을 멈추고, 닫기 직전에 걸린 자동 저장 타이머를 지운다(`SaveHold`·`savesHeld`). 물음이 포커스를 가져가면 편집기 이탈 저장이 돌아 「저장하지 않고 닫기」를 골라도 이미 저장돼 있던 것을 실측으로 찾아 막았고, 리뷰에서 「물음이 끝난 뒤 destroy 까지」의 틈을 찾아 닫았다. 취소하면 자동 저장이 다시 돈다.
- **닫는 길은 모두 Tauri 닫기 요청(`CloseRequested`) 하나로 모이고, 막을지는 앱(Rust)이 정한다**(`close_guard.rs`, 데스크톱 전부).
  - 화면은 저장 안 한 변경이 생기고 없어질 때 창의 **지킴**을 켜고 끈다(명령 `set_close_guard`. 요청마다 페이지 번호 — 문서를 만든 시각 — 와 그 페이지 안의 번호를 싣는다. 늦게 도착한 옛 요청은 앱이 버린다: 같은 페이지의 지난 번호, 새로고침으로 사라진 페이지의 요청, 두 페이지가 겹치면 먼저 만든 페이지의 요청. 재리뷰 지적 — 번호를 페이지마다 1부터 셌을 때는 새로고침 뒤 늦게 닿은 옛 페이지의 「끔」이 새 페이지의 지킴을 가릴 수 있었다). 지킴이 꺼진 창은 그대로 닫힌다. 켜진 창은 앱이 닫기를 막고 그 창에 물음 요청(`close-ask`)을 보낸다. 화면은 받았다고 답하고(`close_ask_ack`) 묻는다. 닫기로 정하면 `destroy()`(닫기 요청을 다시 거치지 않는다), 취소·저장 실패면 `close_ask_done`(차례 닫기는 그 차례가 기다리던 창의 취소일 때만 멈춘다). 묻는 중에 또 온 요청에는 화면이 답만 하고 다시 묻지 않는다(물음이 겹치지 않는다).
  - **새 페이지가 로드되기 시작하면(`on_page_load`) 지킴을 끈다.** 앞 회차는 Tauri 의 JS 리스너(`onCloseRequested`)에 맡겼는데, Tauri 는 JS 리스너가 하나라도 있으면 닫기를 막고 그 리스너는 새로고침 뒤에도 남는다. 그래서 새로고침으로 Workspace 가 사라진 창(볼트 열기 실패 화면 등)은 닫기 단추로도 Cmd+Q 로도 닫히지 않았다(리뷰 지적, 회귀).
  - **응답하지 않는 창**(정한 것): 화면이 물음 요청에 **3초** 안에 답하지 않으면 앱이 **OS 대화상자**(창에 붙은 시트)로 직접 묻는다 — 「이 창이 응답하지 않는데 저장하지 않은 변경이 있습니다. 그래도 닫을까요?」, 단추 「취소」(첫 단추 — 기본 단추라 Return 이 누른다. 영어 "Cancel" 은 NSAlert 가 따로 다뤄 기본 단추가 없고 Escape 가 누른다 — 4회차 실측)/「저장하지 않고 닫기」. 「저장하지 않고 닫기」 단추를 눌렀을 때만 버리고, 단추가 아닌 끝(Escape·대화상자 닫기)은 모두 취소로 본다. 앞 회차는 「저장하지 않고 닫기」가 첫 단추라 **Return 한 번에 초안을 버렸다**(재리뷰 실측 — 「기본 포커스 「취소」」는 AX 포커스를 기본 단추로 잘못 읽은 서술이었다). dialog 플러그인을 거치지 않고 rfd 를 바로 부른다: 플러그인은 단추가 아닌 끝을 두 번째 단추를 누른 것으로 바꿔 돌려주므로, 「취소」를 첫 단추에 두면 Windows·Linux 에서 Escape 가 「저장하지 않고 닫기」가 된다(소스 확인). 묻지 않고 버리지도 않고, 답할 수 없는 창 때문에 앱이 영영 안 꺼지지도 않게 하는 갈림길이다. 글은 화면이 지킴을 켤 때 그때 언어로 넘긴다. 늦게 온 답은 웹 물음을 띄우지 않는다(대화상자가 둘 뜨지 않는다). 화면이 묻다가 멈춘 경우도 닫기를 다시 누르면 같은 확인을 거쳐 OS 대화상자로 넘어간다.
  - capability `default` 에 `core:window:allow-close`·`core:window:allow-destroy`. 앱 명령(`set_close_guard` 등)은 앱이 직접 등록한 명령이라 따로 권한이 없다.
  - 창 닫기 단추·OS 의 창 닫기(Alt+F4)·「창 닫기」 명령: 곧바로 닫기 요청.
  - **macOS 메뉴**(`app/src-tauri/src/lib.rs`): Tauri 기본 메뉴(`Menu::default`, macOS 에만 넣는다)와 같은 구성으로 앱이 직접 만들고 둘을 바꿨다. ① Close Window 를 Cmd+W(`performClose:`)에서 **Cmd+Shift+W** 의 앱 항목으로 — 웹뷰가 키를 흘려보낼 때(모달이 떠 있을 때 등) 「탭 닫기」 대신 묻지 않고 창이 닫히던 길을 없앤다. 항목은 지금 창에 닫기 요청을 보낸다. ② Quit(Cmd+Q)을 `terminate:` 에서 앱 항목으로 — tao 0.37 은 `applicationShouldTerminate` 를 두지 않아 `terminate:` 가 창에 닫기 요청 없이 곧바로 앱을 끝냈다(소스 확인). 앱 항목은 창마다 차례로 닫기 요청을 보낸다(지금 창 먼저, 나머지는 이름 순. 차례가 된 창은 최소화를 풀고 앞으로 가져온 뒤 요청한다 — 물음이 안 보여 끝내기가 멈춘 것처럼 보이지 않게). 그 창이 사라지면 다음 창, 차례가 된 창이 취소·저장 실패(OS 대화상자의 취소 포함)면 멈추고 남은 창은 그대로 둔다. 차례와 상관없는 창을 사람이 따로 닫으려다 취소한 것은 차례를 멈추지 않는다(`stop_for`, 재리뷰 지적). 마지막 창이 사라지면 Tauri 가 앱을 끝낸다. 차례 로직은 `close_guard.rs` 의 `Sequence`(단위 시험).
  - **업데이트 설치 뒤 다시 시작**(`web/src/update.tsx`·`updateCheck.ts` 의 `installAndRestart`): 플러그인의 `relaunch()` 는 창에 닫기 요청 없이 곧바로 끝나 초안을 묻지 않고 버렸다(리뷰 지적). 이제 앱 명령 `restart_after_closing` 이 Quit 과 같은 차례로 창마다 묻고, 다 닫히면 다시 시작한다. 누가 취소하면 다시 시작하지 않고 업데이트 대화상자에 「다시 시작을 취소했습니다. 업데이트는 설치됐고 다음에 Keyring Notes 를 열 때 적용됩니다.」(원래 창이 먼저 닫혔으면 새 창에 같은 알림). 화면이 다시 시작을 직접 부르지 못하게 capability `desktop` 에서 `process:allow-restart` 를 뺐고, 쓰는 곳이 없어진 process 플러그인(`tauri-plugin-process`·`@tauri-apps/plugin-process`)도 의존성에서 뺐다.

- **남은 것**:
  - Dock 의 Quit·로그아웃·시스템 종료는 여전히 `terminate:` 라 묻지 않는다(tao 에 `applicationShouldTerminate` 가 생기거나 앱이 그 메서드를 직접 달아야 한다 — 실측은 안 했다).
  - Windows 의 업데이트 설치는 플러그인이 설치 프로그램을 띄우며 곧바로 앱을 끝낸다(`tauri-plugin-updater` 의 `std::process::exit(0)`) — 묻기 전에 끝난다. 지금 릴리스는 macOS 만이라 실제 길은 아니다. Windows 를 내보낼 때는 설치 **전에** 창마다 묻도록 바꿔야 한다.
  - 응답하지 않는 창의 OS 대화상자가 떠 있는 동안 화면이 다시 살아나면 자동 저장이 돌 수 있다(실측: 멈춤이 풀린 뒤 저장됐다). 그 뒤 「저장하지 않고 닫기」를 고르면 대화상자의 「사라집니다」와 달리 이미 저장된 것이 남는다(버려지는 것은 없다).
  - 지킴은 저장 안 한 변경이 생긴 뒤 화면이 앱에 알리기까지(효과 실행·IPC, 수 ms) 꺼져 있다. 그 사이의 닫기 요청은 묻지 않고 닫힌다.
  - **응답하지 않는 창의 OS 시트(한국어)에서 키보드 탐색이 켜져 있으면 Space 한 번에 「저장하지 않고 닫기」가 눌린다**(4회차 실측). NSAlert 는 Return 을 첫 단추에, 키 포커스를 두 번째 단추에 둔다(3회차 순서에서도 포커스는 두 번째인 「취소」였다). 두 단추 시트로는 Return·Space 를 둘 다 「취소」에 둘 수 없다 — 시트가 뜬 뒤 AppKit 으로 「취소」에 포커스와 Escape 를 직접 줘야 한다(rfd 는 그 손잡이를 주지 않는다). 한국어 「취소」에는 Escape 도 붙지 않는다. 영어는 NSAlert 가 "Cancel" 을 따로 다뤄 Space·Escape 모두 취소다.
  - 「저장하고 닫기」의 저장이 끝나지 않으면(영영 돌아오지 않는 저장) 그 창은 닫을 수도, Quit 도 안 된다 — 화면이 묻는 중으로 남아 닫기 요청마다 답(ack)만 하고 다시 묻지 않는다. 로컬 볼트에서는 일어나기 어려워 받아들인 위험으로 둔다(재리뷰 지적). 고치려면 `save` 에 시한을 둔다.
  - 페이지 번호는 문서를 만든 시각이라, 지킴을 한 번도 바꾸지 않은 옛 페이지의 첫 요청이 새로고침 뒤 늦게 닿고 **그 사이 시계가 뒤로 갔으면** 옛 페이지를 따르고 새 페이지의 요청을 그 페이지가 끝날 때까지 버린다(그동안 묻지 않고 닫힌다). 옛 페이지의 첫 요청은 Workspace 가 뜰 때 보내므로, 뜨자마자 새로고침되고 그 요청이 새로고침 뒤에 닿고 그사이 시계가 뒤로 가야 하는 길이다.
  - 메뉴 Close Window 가 Tauri 창이 아닌 창(정보 창·파일 고르기 창)은 닫지 못한다. 저장 실패로 닫지 않는 경로(「저장하고 닫기」 실패)와 메뉴 Close Window 클릭은 앱 실측을 못 했다(단위 시험만). Windows·Linux 실측은 아직 없다(메뉴가 없고 Alt+F4·닫기 단추는 같은 닫기 요청·지킴을 거친다).

**노트 안 찾기 막대**(`web/src/findBar.ts`, 2026-10-20): CodeMirror 기본 찾기 패널(아래쪽 줄, 번역 안 된 영어, 일치 수 없음, 바꾸기 줄이 늘 보임)을 앱 모양의 막대로 바꿨다.
- 에디터 위 오른쪽에 떠 있고(VS Code 식) 본문을 밀지 않는다. 스크롤해도 칸 위에 남는다. 칸을 나누면 칸마다 따로 열린다.
- 한 줄 입력에 대소문자·단어 단위·정규식 토글, 일치 수 「3/12」(선택이 일치 위가 아니면 「?/12」, 1000개 넘으면 「1000+」), 이전·다음, 닫기. 결과가 없거나 정규식이 잘못되면 빨간 테두리와 「결과 없음」·「잘못된 정규식」.
- 치는 대로 지금 자리부터 첫 일치로 옮긴다. Enter·Shift+Enter 로 다음·이전, Mod+G·Mod+Shift+G(F3) 도 같다(막대가 닫혀 있으면 연다). 끝에서는 처음으로 돈다. Opt+Enter 는 모든 일치를 선택하고 에디터로 간다.
- 고른 글이 있으면 그 글로 시작한다(100자 이하, 열린 채 Mod+F 를 다시 눌러도). Esc 는 닫고 에디터로 포커스를 돌린다.
- Mod+Alt+F 로 바꾸기 줄을 펼쳐 연다(찾을 글이 있으면 바꿀 글 칸에 포커스). 바꿀 글 칸에서 Enter 는 하나 바꾸기, Mod+Enter 는 모두 바꾸기. 펼침 단추(›)로 접고 편다. 새로 열 때(Mod+F)는 접혀 있다. 읽기 전용 문서에는 바꾸기가 없다.
- 찾기 칸 안의 Mod+Z 는 입력칸 글을 되돌린다(에디터 되돌리기는 Esc 뒤에).
- 한글 조합을 끝내는 Enter 는 다음 찾기로 치지 않는다(`isComposing`). 헤드리스 WebKit 은 실제 IME 조합을 못 만들어 macOS 앱에서만 확인할 수 있다.

### 7. 설정 페이지 분리 (P1, 사용자)

**지금**: 설정이 흩어져 있다.
- 관리 콘솔(서버 상태·에이전트·백업·업데이트·보안)은 앱 위를 덮는 전체 화면(`position: fixed`)이라, 문서로 돌아가려면 닫아야 하고 주소(URL)가 없다.
- 데일리 노트·템플릿은 명령 팔레트에서만 여는 작은 대화상자이고, 값은 이 기기 `localStorage`에만 있다(다른 기기·앱과 공유 안 됨).
- Live Preview·속성 칸·열린 탭은 버튼 상태로 `localStorage`에 따로 저장된다.

**제안**: 레일 아래 ⚙에서 여는 전체 화면 설정(`#/settings`). 왼쪽 목록 + 오른쪽 내용, 위에 설정 검색.

| 묶음 | 내용 |
| --- | --- |
| 일반 | 테마(시스템·밝게·어둡게), 시작 화면(홈·마지막 문서) |
| 편집기 | 글꼴·크기·줄 간격, 읽기 폭, 줄 번호, Live Preview 기본값, 자동 저장(켜기·간격), 맞춤법 검사 |
| 파일·링크 | 새 문서 위치, 첨부 폴더, 링크 형식(최단·전체 경로), 이동 때 링크 갱신, 삭제 확인 |
| 데일리·템플릿 | 지금 `NoteSettingsDialog` 내용 |
| 외관 | 아이콘 표시, 트리 표시 옵션, 상태 표시줄 항목 |
| 단축키 | 목록·바꾸기·초기화 |
| 이 기기·동기화 | 앱: 볼트 폴더, 서버 연결(지금 ⇅ 화면) |
| 서버 관리(소유자) | 지금 관리 콘솔의 탭들(상태·에이전트·백업·자동화·업데이트·보안·기기) |

**정할 것**: 설정을 어디에 두나.
- 이 기기만(테마·패널 폭·단축키)인 것과 모든 기기 공통(데일리·템플릿·첨부 폴더·링크 형식)인 것을 나눈다.
- 공통 설정을 볼트 안 파일로 두면 앱 동기화와 다른 편집기에 따라간다. 하지만 점 폴더는 동기화·API에서 빠지므로 위치를 따로 정해야 한다. 서버 설정에 두면 앱 오프라인 시작 때 읽을 수 없다.

### 8. 화면 분할 (P1, 사용자)

**지금**: 가운데를 좌우·위아래로 거듭 나눠(Zed 처럼) 여러 문서(또는 같은 문서)를 함께 편집한다. 노트 하나를 새 창(웹은 브라우저 창, 데스크톱 앱은 앱 창)으로도 열고, 데스크톱 앱에서는 탭을 창 밖으로 끌어 놓아 새 창으로 떼어 낸다. 동작은 아래 「구현 현황」 표의 8번 행.

**제안**:
- 가운데를 좌우(필요하면 위아래)로 나누고, 칸마다 자기 탭 바와 문서를 가진다. 탭은 칸 사이로 끌어 옮긴다.
- 링크를 Mod+클릭하면 다른 칸에서 연다. 칸 크기 조절, 칸 닫기.
- Live Preview를 기본으로 삼고, 지금 "나란히"는 "미리보기 옆에 띄우기"(같은 문서를 다른 칸에 읽기 전용으로) 명령으로 바꾼다. 그래야 "분할"과 이름이 겹치지 않는다.
- 같은 문서를 두 칸에 열면 한 원본을 같이 편집해야 한다. 지금 `doc` 상태가 하나라서 상태 구조를 칸별로 바꾸는 작업이 크다. 먼저 상태를 "열린 문서 저장소 + 칸 배치"로 나누는 정리가 필요하다.

**설계(승인됨)**: `docs/superpowers/specs/2026-10-12-split-panes-design.md`(칸마다 탭, 같은 문서는 원본 하나), `docs/superpowers/specs/2026-10-19-pane-splits-design.md`(나눈 트리·상하 분할·개수 제한 없음·단축키·데스크톱 새 창). "같은 문서를 미리보기로 옆에 띄우기"는 나눈 칸을 미리보기 모드로 두는 것으로 대신한다.

### 9. 투박한 겉모습 (P1, 사용자)

**지금**:
- 아이콘이 이모지(＋ 📅 📥 ✔ ◎ 🧹 ⚙ ⎋ ☰ ×)라 운영체제마다 다르게 보이고 굵기·크기가 제각각이다.
- 에디터가 고정폭 글꼴 + 줄 번호 + Live Preview 꺼짐이 기본이라 코드 편집기처럼 보인다.
- 도구가 글자 버튼(편집·나란히·미리보기·Aa·속성·저장·이동·삭제·이력·개요)으로 한 줄에 붙어 있다.
- 색은 토큰이 있지만 간격·글자 크기·둥글기·그림자 체계가 없다. 어두운 테마는 시스템 설정을 따를 뿐 직접 고를 수 없다.

**제안**:
- 아이콘 세트 하나로 통일(예: Lucide, MIT, 필요한 것만 묶을 수 있음). 이모지는 문서 아이콘(사용자 콘텐츠)에만 쓴다.
- 디자인 토큰: 간격(4px 단위), 글자 크기 단계, 둥글기, 그림자, 강조·위험·성공 색, 포커스 링. `styles.css`의 값들을 토큰으로 바꾼다.
- 에디터 기본값: 본문 글꼴(비례폭), Live Preview 켜짐, 줄 번호 끔, 읽기 폭 가운데 정렬. 코드 블록만 고정폭.
- 버튼: 아이콘 버튼 + 툴팁(단축키 포함), 눌림 상태, 크기 통일. 위험한 동작은 메뉴 안으로.
- 테마를 직접 고를 수 있게 한다.

### 10. 문서마다 아이콘 (P2, 사용자, SiYuan 참고)

SiYuan은 문서마다 이모지(또는 사용자 이미지) 아이콘을 정한다. 그 아이콘은 문서 트리·탭·제목 옆·링크에 같이 보이고, 선택으로 문서 위 배너(커버) 이미지도 둔다.

**제안**:
- 제목 칸 옆 아이콘 자리를 누르면 이모지 고르기 창(검색, 최근 쓴 것, 지우기)이 열린다.
- 저장은 프런트매터 `icon: 📘`. 마크다운 원본 원칙에 맞고, 다른 편집기에서도 깨지지 않으며, 에이전트도 읽을 수 있다.
- 보이는 곳: 트리, 탭, 문서 머리, 빠른 열기, 검색 결과, 위젯 목록, 그래프 노드(선택).
- 커버 이미지(`cover:` 첨부 경로)는 그다음에 고려한다.

**정할 것**: 폴더 아이콘은 프런트매터가 없다. 폴더 노트(폴더와 같은 이름의 문서)의 `icon`을 쓰거나, 공통 설정(7번) 파일에 둔다.

### 11. 백링크·출처 위치 (P1, 발견)

**지금**: 백링크·연결되지 않은 언급·출처·인용(`References`)이 미리보기 칸 맨 아래에 그려진다. "편집" 모드로 쓰면 볼 방법이 없고, 긴 문서는 끝까지 내려가야 보인다.

**제안**: 오른쪽 패널의 탭으로 옮기고, 개수를 탭 이름에 표시한다. 문서 끝에 두는 표시는 설정으로 남긴다(Obsidian의 "문서 끝 백링크").

### 12. 오류·알림 (P1, 발견)

**지금**: 오류도 "info" 모양 배너로 위쪽에 쌓이고, 눌러야 사라진다. 오프라인·충돌·과거 버전·자동 생성 문서 배너가 모두 같은 자리에 쌓여 본문을 밀어낸다.

**제안**:
- 금방 끝나는 결과(저장 실패·이동 완료·링크 N곳 고침)는 토스트(몇 초 뒤 사라짐, 되돌리기 버튼 가능)로.
- 오래 가는 상태(오프라인·보낼 변경)는 상태 표시줄로.
- 문서 자체 상태(충돌·과거 버전 보기·자동 생성 문서)만 배너로 남기고, 오류는 위험 색으로 구분한다.

### 13. 홈 화면 (P2, 발견)

**지금**: 문서를 안 열면 "왼쪽에서 문서를 고르거나 ＋ 로 새 문서를 만드세요." 한 줄만 나온다.

**제안**: 최근 문서, 고정(즐겨찾기) 문서, 오늘 노트, 검토 대기·정리 점검 요약, 빠른 검색 칸. 고정 기능은 트리 메뉴와 레일에서도 쓴다.

### 14. 휴지통 (P2, 발견)

**지금**: 삭제 확인 창은 "이력에서 되돌릴 수 있습니다"라고 하지만, 지운 문서는 트리에 없어서 그 이력을 열 방법이 화면에 없다.

**제안**: "삭제된 문서" 화면(Git 이력의 삭제 커밋에서 목록, 앱은 journal에서)에서 내용 보기·되살리기. 토스트의 "되돌리기"도 같은 기능을 쓴다. 에이전트에게는 지금처럼 숨김 경로가 보이지 않게 거른다.

### 15. 검색 (P2, 발견)

**지금**: 검색하면 트리 자리가 결과로 바뀐다. 결과에 줄 번호가 있지만 누르면 문서 처음이 열리고, 본문에서 검색어가 강조되지 않는다. 폴더·태그·경로를 고르는 칸이 없다(`#태그`만 문법으로).

**제안**: 결과를 누르면 그 줄로 가서 강조한다. 결과마다 일치 줄 여러 개를 보여 주고, 폴더·태그 필터와 정렬을 둔다. 레일의 검색 패널로 옮겨 트리와 따로 둔다.

## 구현 순서 제안

1. **기반**: 디자인 토큰·아이콘 세트, 패널 배치 틀(레일·왼쪽·가운데·오른쪽·상태 표시줄, 크기 조절·접기), 토스트. 이후 항목이 모두 이 틀 위에 올라간다.
2. **편집 흐름**: 자동 저장(커밋 묶기 결정 포함), 제목 인라인 수정, 새 문서·이동 흐름.
3. **트리**: 아이콘·메뉴·이름 바꾸기·끌어 옮기기·키보드.
4. **단축키 체계**: 명령 하나에 단축키·팔레트 항목·메뉴를 같이 등록하는 구조로(지금 팔레트 명령 목록을 확장).
5. **오른쪽 패널**: 개요·백링크·출처·이력 이동.
6. **설정 페이지**: 관리 콘솔·노트 설정 흡수, 기기 설정과 공통 설정 나누기.
7. **화면 분할**: 열린 문서 상태를 칸별 구조로 바꾼 뒤.
8. **문서 아이콘, 홈, 휴지통, 검색 개선**.

## 결정이 필요한 것

- **자동 저장과 Git 커밋**: 연속 저장을 직전 커밋에 합칠지(amend), 커밋만 묶어서 남길지. 백업·동기화로 이미 나간 커밋은 건드리지 않는다는 전제는 같다.
- **제목 = 파일 이름**으로 둘지, 프런트매터 `title`을 제목 칸에 쓸지.
- **공통 설정의 저장 위치**: 볼트 안 파일(어디에, 동기화 규칙은), 서버 설정, 기기별.
- **폴더 아이콘** 저장 방식.
- **"나란히" 모드의 운명**: Live Preview 기본 + "미리보기 옆에 띄우기"로 바꾸는 데 동의하는지.

### 정한 것

- **자동 저장과 Git 커밋 → 직전 커밋에 합치기(amend)**. 웹이 자동 저장에 `coalesce: true`를 보내면, 서버는 같은 소유자가 같은 문서 하나만 고친 직전 커밋이 아직 HEAD이고 그 묶음을 시작한 지 10분 안이면 그 커밋에 합친다. 다른 커밋, 서버 밖 변경 흡수(백업 직전에 부른다)가 끼면 끊는다 — 백업에 들어간 커밋은 고쳐 쓰지 않는다. 에이전트 쓰기와 `Ctrl/Cmd+S`는 묶지 않는다. 디스크·색인은 저장마다 바로 바뀐다.
- **제목 = 파일 이름**(Obsidian 방식). 프런트매터 `title`은 속성 칸에서.
- **"나란히"는 남김**: Live Preview를 기본으로 하고 보기 전환에 그대로 둔다(원문과 미리보기를 나란히). 다른 문서를 같이 보는 것은 화면 분할.

#### 2차에서 구현하며 정한 것

- **공통 설정 파일 이름·위치 = 볼트 맨 위 `keyring-settings.md`**. 점으로 시작하지 않고(동기화·API에 들어가야 한다) 마크다운이라 양방향 동기화를 탄다. 다른 편집기(Obsidian)에서는 보통 문서로 보인다 — 이름으로 알아보게 하고, 본문에 "설정 화면에서 고치세요" 안내를 넣는다. 키는 펼친 이름(`dailyFolder`·`dailyFormat`·`dailyTemplate`·`dailyWeekStart`·`dailyIcon`·`templateFolder`·`attachmentFolder`·`linkFormat`·`folderIcons`). 쓸 수 없는 데일리 형식을 손으로 넣었으면 읽을 때 기본값으로 본다(같은 날 노트가 엉뚱한 곳에 생기지 않게).
- **공통 설정 쓰기 = 값 하나씩 다시 읽고 바꿔 쓰기**(baseHash, 409면 3번까지 다시). 다른 기기가 고친 다른 값을 덮어쓰지 않아 3방향 병합 없이 같은 효과. 글자 칸은 Enter·포커스 이탈 때만 쓴다.
- **서버가 공통 설정을 읽는 길**: 권한 계층 밖(`Vault.sharedSettings()`, 크기·수정 시각이 바뀔 때만 다시 읽기)이지만 응답에 내용을 싣지 않고, 읽는 사람이 볼 수 있는 경로 목록 안에서 링크를 해석하는 데만 쓴다. 숨김 데일리 노트는 `[[날짜]]`로도 해석되지 않는다(테스트). 정리 점검의 데일리 속성 점검도 볼 수 있는 문서만.
- **패널 단축키를 옮김**: CodeMirror 접기 기본 키(`Ctrl+Alt+[`·`]` 모두 접기·펴기, macOS `Cmd+Alt+[`·`]` 접기·펴기)가 1차의 패널 키 `Mod+Alt+[`·`]`와 겹쳐, 왼쪽 패널 `Mod+Shift+E`, 오른쪽 패널 `Mod+Alt+B`로 바꿨다(VS Code의 탐색기·보조 사이드바와 같은 자리). 명령에 macOS 전용 기본 키(`macKeys`)를 둘 수 있게 했다.
- **이전·다음 데일리 노트에는 기본 키를 두지 않음**: `Mod+Alt+↑/↓`는 에디터의 "위·아래에 커서 더하기"와 겹친다. 문서 머리 ◀ ▶와 명령으로, 설정에서 키를 줄 수 있다.
- **접기 기억 단위 = 블록 첫 줄의 글**: 줄 번호만으로는 위에 한 줄을 더하면 엉뚱한 곳이 접힌다. 같은 글의 줄이 여럿이면 원래 줄 번호에 가장 가까운 것. 코드 블록은 6줄(여닫는 줄 포함) 이상만 접는다(편집·미리보기 같은 기준). 미리보기의 인용은 콜아웃만 접는다(접기 표시가 있는 콜아웃 `[!x]-`·`+`는 원래의 펼침 단추).
- **앱(LocalVault)에서 첨부가 든 폴더 옮기기**: 앱 안에서는 문서·첨부를 한 기록으로 옮기고(첨부는 지금처럼 기록·스냅샷에 남지 않음) 링크를 고친다. 동기화 규칙을 하나 더했다: **기기에서 지운 첨부는 서버가 기준점 그대로일 때만 서버에서도 지운다**(그 사이 서버에서 바뀌었으면 서버 것을 다시 받는다). 그래서 다음 동기화에서 새 자리의 첨부는 "기기에서 새로 만든 첨부"로 올라가고 원래 자리는 서버에서 지워진다 — 옮긴 첨부의 원래 자리가 되살아나지 않는다. 서버에는 한 커밋이 아니라 올리기·지우기 커밋이 따로 남는다(동기화는 경로별 상태 비교라 이동을 알지 못한다). 기기에서 고친 첨부는 지금처럼 보내지 않는다.
- **`doc.changed` 조용한 시간 = 90초**(정한 것 10의 "1~2분" 가운데). 대기 중인 것은 서버 메모리에만 있어, 정상 종료(SIGTERM)는 바로 보내지만 갑자기 죽으면 잃는다(커밋·이력은 그대로).
- **설정 모달에서 테마·패널 같은 이 기기 값과 공통 값을 한 화면에**: 공통 값에는 "모든 기기" 표시를 붙여 구분한다. 일반 묶음에 공통 설정 파일 "원문 열기".

#### 앱 자동 저장 기록 정리 검토(정한 것 9, 구현하지 않음)

지금 앱은 자동 저장마다 `journal.jsonl`에 한 줄, `objects/<해시>`에 내용 스냅샷 하나가 쌓인다(같은 내용은 해시로 한 번만). 서버처럼 직전 기록에 합치려면 덧붙이기 전용인 기록 파일을 고쳐 써야 해서, "볼트를 열 때 오래된 자동 저장 기록 정리"를 검토했다.

- **방식**: `open()`에서 기록을 읽은 뒤, 하루보다 오래된 기록 중 같은 작성자가 같은 문서 하나만 "수정"한 연속 기록을 10분 묶음(서버의 자동 저장 묶기와 같은 창)마다 마지막 것만 남긴다. 기록을 새 파일에 쓰고 바꿔 끼운 뒤, 어떤 기록·지금 파일·동기화 기준점(`sync.json`의 `base`)도 가리키지 않는 `objects/`를 지운다.
- **꼭 지킬 것**: 동기화 기준점이 가리키는 스냅샷은 3방향 병합의 기준 내용(`contentByHash`)이라 지우면 안 된다. "기존 내용"·이동·삭제·동기화·외부 변경 기록은 합치지 않는다. 이력 화면의 되돌리기 대상이 사라지므로 합치는 것은 오래된(하루 이상) 것만.
- **필요한 것**: `FileStore`에 메타데이터 목록(`listMeta`)과 안전한 바꿔 끼우기(임시 파일 → 이름 바꾸기)가 없다. Tauri 파일 쓰기는 원자적이지 않아 쓰다 끊기면 기록 전체를 잃을 수 있다. 같은 폴더를 두 앱(또는 파일 동기화 도구)이 같이 열면 정리끼리 겹칠 수 있어 잠금 파일도 필요하다.
- **비용**: 열 때 이미 기록 전체를 읽으므로 합치기 판단은 O(기록 수). 지울 스냅샷을 찾는 데 `objects/` 목록이 필요하다. 매번 하지 않고 기록이 수천 줄을 넘거나 마지막 정리가 7일 이상 지났을 때만.
- **결론**: 할 수 있지만 `FileStore` 확장(목록·원자적 바꾸기·잠금)과 동기화 기준점 보호가 먼저다. 다음에 앱 저장소를 손볼 때 같이 한다.

#### 3·4차에서 구현하며 정한 것

- **링크 해석 순서**: 정확한 경로 → 같은 워크스페이스의 같은 이름(가장 얕은 것) → 같은 워크스페이스의 그날 데일리 노트(`[[2026-10-07]]`) → 볼트 전체의 같은 이름 → 다른 워크스페이스의 데일리 노트. 같은 이름 노트가 데일리 노트보다 먼저인 2차 규칙을 워크스페이스 안에서도 지킨다.
- **공통 설정 파일 키**: `vault`(language·linkFormat·workspaceOrder), `workspaces.<이름>`(daily·templateFolder·attachmentFolder, 빠진 값은 볼트 언어의 기본값), `ui`(따라가는 화면 값). 2차의 펼친 키(`dailyFolder`·`folderIcons` 등)는 읽지 않는다(이전 코드 없음). 값을 지우면(`null`) 빈 부모 묶음도 지운다.
- **볼트 언어를 아직 정하지 않은 볼트**: 서버는 서버 언어, 앱은 화면 언어를 쓴다. 웹이 설정 파일을 처음 만들 때 `vault.language`를 그때 화면 언어로 적는다.
- **오류 코드 이름**: 메시지 키 `error.<code>`(예: `doc_missing`, `conflict_path`, `widget.bad_sort`). 서버의 `message`는 로그·오래된 화면용이고 화면은 code로 다시 만든다. code가 없는 오류(오래된 서버)는 받은 글 그대로, 네트워크 오류는 화면 언어의 "서버에 연결하지 못했습니다".
- **화면 설정 쓰기는 700ms 묶기**: 같은 값이 연달아 바뀌면 마지막 값만 공통 설정에 쓴다(2차의 "값 하나씩 다시 읽고 바꿔 쓰기", 409면 다시). 덮어쓰기 값은 `keyring:prefs-local`, 마지막으로 받은 공통 값 캐시는 `keyring:ui-cache`(이 기기, 서버로 보내지 않음).
- **노드 삭제의 확인 목록**: 화면이 본 하위 파일 목록과 해시를 보내고, 서버는 지금 목록·해시와 다르면 아무것도 지우지 않는다(그 사이 에이전트가 하위를 더했을 때 모르고 지우지 않게).
- **그래프 색 묶음**: 워크스페이스 안 2단계(`업무/경제`)를 토픽으로 본다(1단계뿐이면 워크스페이스).
- **레일 글자**: 레일에는 짧은 이름(오늘·그래프·가져오기·검토·점검), 툴팁·접근성 이름은 긴 이름.
- **다른 곳에서 지워지거나 옮겨진 노트의 탭**: 트리를 받은 뒤 정리한다(지금 연 노트·저장 안 한 탭·빈 노드 탭은 남김).

#### 백업 복원과 git 백그라운드 정비(3차 확인 메모)

3차 확인에서 찾은 테스트 불안정(`ENOTEMPTY`)은 git이 커밋 뒤 띄우는 자동 정비(`maintenance.auto`, 따로 떨어진 repack)가 테스트 정리(`rm -rf`)와 겹친 것이다. 서버의 백업 복원도 `.history`를 바꾸므로 같이 검토했다.

- 복원은 `.history` 폴더를 지우거나 바꿔 끼우지 않는다. 같은 저장소 안에서 `fetch`(번들) → `update-ref` → `reset --hard` → `clean`만 하고, 이것들은 git의 잠금 파일(`*.lock`)로 백그라운드 repack과 서로 막는다. 그래서 테스트 정리 같은 `ENOTEMPTY`는 생기지 않는다.
- 복원은 `Vault.maintenance`(쓰기 잠금) 안에서 하므로 복원 중 새 커밋이 정비를 새로 띄우지 않는다. 복원 전에 이미 떠 있던 정비가 잠금을 쥐고 있으면 그 git 명령이 실패하고, 복원은 "복원 전 백업"을 남긴 채 오류로 끝난다(볼트는 `reset` 전이면 그대로).
- **결론**: 운영에서는 자동 정비를 켜 둔다(저장소 크기·속도에 필요). 테스트만 끈다. 복원이 잠금 충돌로 실패하는 일이 보고되면 그때 복원 앞에 `git maintenance` 대기(잠금이 풀릴 때까지 짧게 다시 시도)를 더한다.

**제안**: 커서가 그 블록 밖에 있을 때만 블록 위젯(CodeMirror block widget)으로 그리고, 커서가 들어가면 원문을 보인다(Obsidian 방식). 렌더러는 미리보기와 같은 것(`markdown.ts`, `render/katex.ts`, `render/mermaid.ts`)을 쓴다. 순서: 이미지 임베드 → 콜아웃 → 수식 → 주석·블록 ID 숨기기 → Mermaid·문서 임베드 → 각주.

### 20. 속성은 문서 위가 아닌 다른 곳에 (P1, 사용자)

**지금**: 속성 칸(`Properties`)이 제목 칸 바로 아래, 본문 위에 표로 나온다(`Workspace.tsx`의 `propsOpen`). 그 아래 에디터에도 "프런트매터 N줄 — 위 속성 칸에서 고치거나, 눌러서 원문 보기" 줄이 한 줄 더 있다. 속성이 많은 위키 페이지(`sources`·`summary`·`tags`…)는 본문이 한참 아래로 밀린다.

**제안**:
- 속성 칸을 **오른쪽 패널의 "속성" 탭**으로 옮긴다(개요·연결·이력 옆). 개수를 탭 이름에 보이고, 문서를 바꿔도 탭이 유지된다.
- 본문 위에는 아무것도 두지 않는다. 에디터의 프런트매터는 지금처럼 접어 두되, 안내 줄 문구를 "속성 N개 — 오른쪽 패널에서 보기"로 바꾸고 누르면 속성 탭을 연다. 원문을 고치고 싶을 때는 같은 줄의 "원문 보기"로 펼친다.
- 속성 단추(지금 문서 머리의 "속성 칸")는 오른쪽 패널 속성 탭을 여닫는 단추로 바꾼다.
- 미리보기에서도 속성을 본문 위에 그리지 않는다(`hideFrontmatter`를 늘 켬). 필요하면 설정에 "문서 위에 속성 보기"를 둔다.
- 좁은 화면에서는 오른쪽 서랍 안 속성 탭으로 간다.

**주의**: 오른쪽 패널이 닫혀 있으면 속성이 있는지 모를 수 있다. 접힌 프런트매터 줄과 탭 이름의 개수로 알린다.

### 21. 내용 접기 (P1, 사용자)

**지금**: 에디터에서 접을 수 있는 것은 프런트매터(`frontmatterFold`)뿐이다. 제목 아래 내용, 목록, 콜아웃, 코드 블록은 접히지 않는다. 미리보기도 마찬가지다(콜아웃 `[!note]-`만 접힘).

**제안**:
- **제목 접기**: 제목 줄 왼쪽에 마우스를 올리면 ▸/▾가 보이고, 누르면 다음 같은 수준 이상의 제목 전까지 접는다. 접힌 자리에 "…"를 보이고 누르면 펼친다.
- **목록 접기**: 하위 항목이 있는 목록 항목은 그 하위 목록을 접는다.
- 콜아웃·코드 블록·표도 접을 수 있게 한다(코드 블록은 줄 수가 많을 때만 단추를 보인다).
- 편집(Live Preview·원문)과 미리보기 둘 다 같은 규칙으로 접는다. 미리보기에서는 제목 옆 단추로.
- **명령·단축키**(6번 단축키 체계에 등록): 지금 위치 접기·펴기, 모두 접기·모두 펴기, 이 수준 제목만 보기. CodeMirror 기본 접기 키(`foldKeymap`: 접기·펴기 macOS `Cmd-Alt-[`/`]`, 그 밖 `Ctrl-Shift-[`/`]`, 모두 접기·펴기 `Ctrl-Alt-[`/`]`)를 쓸지, 다른 단축키와 겹치지 않는지 정한다.
- **접힌 상태 기억**: 문서마다 이 기기에 기억한다(파일 내용은 바꾸지 않는다). 문서가 바뀌어 줄이 밀려도 제목 글자로 다시 찾는다.
- 개요 패널에서 제목을 접고 펴는 것과 연결한다(개요에서 접으면 본문도 접힘).

**주의**:
- 접기는 화면 표시만이다. 원문·저장·동기화·에이전트가 읽는 내용은 그대로다.
- 검색 결과로 이동하거나 링크로 `#제목`·`#^블록`에 갈 때, 그 자리가 접혀 있으면 자동으로 펼친다.
- 할 일 체크·자동 저장·3방향 병합으로 내용이 바뀌어도 접힌 범위가 엉뚱하게 바뀌지 않는지 확인한다.

### 22. 데일리 노트 저장 형식: 연월 묶음·주차 묶음 (P1, 사용자)

**지금**: 설정 → 데일리·템플릿에 폴더(`dailyFolder`, 기본 `일기`)와 파일 이름 형식(`dailyFormat`, 기본 `YYYY-MM-DD`) 글자 칸이 있다(`packages/core/src/templates.ts`의 `formatDate`·`dailyNotePath`).
- 형식에 `/`를 넣으면 하위 폴더가 되므로 `YYYY/MM/YYYY-MM-DD`처럼 쓰면 연월 묶음이 되긴 한다. 하지만 그걸 알아야 쓸 수 있고, 고를 수 있는 보기가 없다.
- 쓸 수 있는 토큰은 `YYYY YY MM M DD D HH H mm m ss s ddd dddd [글자]`뿐이라 **주차로 묶을 수 없다**(주차·주 기준 연도 토큰 없음).
- 설정이 이 기기 `localStorage`에만 있다.

**제안**:
- **묶음 방식 고르기**(보기 + 직접 입력):

  | 보기 | 형식 예 | 오늘(2026-10-07) 경로 |
  | --- | --- | --- |
  | 묶지 않음 | `YYYY-MM-DD` | `일기/2026-10-07.md` |
  | 연도별 | `YYYY/YYYY-MM-DD` | `일기/2026/2026-10-07.md` |
  | 연·월별 | `YYYY/MM/YYYY-MM-DD` | `일기/2026/10/2026-10-07.md` |
  | 연·주차별 | `GGGG/[W]WW/YYYY-MM-DD` | `일기/2026/W41/2026-10-07.md` |
  | 직접 입력 | 토큰 자유 조합 | 입력하는 대로 미리 보기 |

- **토큰 추가**: 주차 `W`·`WW`(ISO 주차, 01~53), 주 기준 연도 `GGGG`(연말·연초 주차가 앞뒤 해에 걸칠 때 쓰는 연도), 월 이름 `MMMM`(→"10월"). 요일은 이미 `ddd`→"수", `dddd`→"수요일"이 된다.
- **주 시작 요일** 설정(월요일 기본, ISO 기준). 일요일 시작을 고르면 주차 계산도 그 기준을 따르고, 그때는 ISO가 아님을 설정 화면에 밝힌다.
- 설정 칸 아래에 **오늘·어제·내일·연말 경계(예: 2026-12-31, 2027-01-01) 경로를 미리 보여 준다.** 주차 묶음에서 연말 날짜가 어느 폴더로 가는지 바로 보이게. 예: ISO 주차로는 2026-12-31과 2027-01-01이 둘 다 `2026/W53`이고, 2027-01-04부터 `2027/W01`이다. 그래서 주차 묶음의 연도는 `YYYY`가 아니라 `GGGG`를 써야 한다.
- 어제·내일 노트(명령 팔레트), 오늘 노트 단추가 모두 같은 형식을 쓴다(지금처럼 `dailyNotePath` 하나로).
- 트리에서 데일리 폴더는 최신이 위로 오게(내림차순) 정렬하는 옵션.
- (선택) 데일리 폴더 전용 달력 보기: 달력에서 날짜를 누르면 그날 노트를 열거나 만든다. 노트가 있는 날은 점으로 표시.
- (선택) 주간 노트: 같은 방식으로 `주간 노트 형식`(예: `GGGG/[W]WW/주간`)과 템플릿을 따로 둔다.

**주의**:
- **데일리 형식은 모든 기기가 같아야 한다.** 기기마다 다르면 같은 날 노트가 다른 경로에 두 개 생기고 동기화로 둘 다 남는다. 지금 이 기기 `localStorage`에 있는 데일리·템플릿 설정은 7번의 "모든 기기 공통 설정"으로 옮겨야 한다(저장 위치 결정이 먼저 필요).
- 형식을 바꿔도 이미 있는 노트는 옮기지 않는다. 대신 "기존 데일리 노트를 새 형식으로 옮기기" 명령을 둔다(날짜를 파일 이름에서 읽어 옮기고, 8단계 링크 자동 갱신을 쓴다. 날짜를 못 읽은 파일은 건너뛰고 목록을 보여 준다).
- 형식 결과에 파일 이름으로 못 쓰는 글자, 빈 세그먼트, `..`, 점으로 시작하는 폴더가 나오면 저장을 막고 이유를 보인다.

**추가: 형식이 앞부분에 맞으면 데일리 노트로 본다(날짜 뒤 제목)** (사용자)

보기 편하게 `2026-10-07 분기 계획 회의.md`처럼 날짜 뒤에 제목을 붙여도 그날의 데일리 노트로 인식한다.

- **판정 규칙**: 데일리 폴더 아래 경로가 형식의 폴더 부분과 맞고, 파일 이름이 형식의 날짜 부분으로 **시작**하면 데일리 노트다.
  - 날짜 바로 뒤는 이름 끝(`.md`)이거나 구분 글자(공백, ` - `, `_`, `·`)여야 한다. `2026-10-071.md`처럼 숫자가 이어지면 아니다.
  - 형식에서 정규식을 만들어(토큰 → 자리수 패턴) 날짜를 읽는다. 읽은 날짜로 다시 만든 경로가 실제 폴더와 맞는지까지 확인한다(예: `2026/W41/` 폴더에 `2026-10-20 ….md`가 있으면 아님).
  - 파일 내용·프런트매터는 보지 않는다(이름만으로 판정).
- **오늘 노트 열기**: 그날 날짜로 시작하는 노트가 있으면 그것을 연다(제목이 붙어 있어도). 없으면 날짜만으로 새로 만들고 제목 칸에 커서를 둔다. 같은 날짜로 시작하는 노트가 둘 이상이면 고르는 목록을 보인다.
- **어제·내일·이전·다음**: 날짜를 하루씩 빼고 더하는 대신, 판정 규칙으로 읽은 데일리 노트 중 바로 앞·뒤 날짜로 간다(빠진 날 건너뛰기). "어제 노트 만들기"는 따로 둔다.
- **제목 칸**: 데일리 노트에서는 날짜 부분을 고정된 앞머리(회색 글자)로 보이고, 그 뒤 제목만 고친다. 날짜를 지우면 데일리 노트가 아니게 된다고 알린다.
- **보여 주기**: 트리·탭·빠른 열기에서 날짜는 흐리게, 제목은 진하게. 제목이 없으면 `10월 7일 (수)`처럼 읽기 좋은 날짜로 보이는 설정을 둔다.
- **데일리 노트 전용 표시**: 문서 머리에 ◀ 이전 · 날짜 · 다음 ▶, 달력 보기의 점, 연·월·주차 묶음 폴더 정렬이 모두 같은 판정을 쓴다.
- **형식 옮기기 명령**(위 주의)도 날짜 뒤 제목을 그대로 살려서 옮긴다.

**정할 것**:
- **링크 해석**: 다른 문서나 템플릿의 `[[2026-10-07]]`이 `2026-10-07 분기 계획 회의.md`를 가리키게 할지. 가리키게 하려면 위키링크 해석(`resolveLink`, core)에 "데일리 날짜 → 그날 노트" 규칙을 더해야 하고, 서버·앱·에이전트 쪽이 모두 같은 데일리 설정을 알아야 한다(7번 공통 설정과 묶임). 대신 제목을 붙일 때 8단계 링크 자동 갱신으로 링크를 고치는 방법도 있지만, 그러면 모든 링크가 긴 이름이 된다.
- 판정 규칙을 core(`templates.ts` 근처)에 두어 웹·앱·서버(위젯 쿼리 `from`, 정리 점검)가 같은 판정을 쓰게 할지.

**추가: 데일리 노트 속성** (사용자)

데일리 노트를 만들 때 프런트매터에 날짜 정보를 넣어, 검색·위젯 쿼리로 찾기 쉽게 한다.

```yaml
---
daily: true          # 데일리 노트 표시
date: 2026-10-07     # 날짜(글자, YYYY-MM-DD)
year: 2026           # 연도(숫자)
month: 10            # 월(숫자)
monthday: 10-07      # 월일(글자, MM-DD) — "해마다 오늘" 찾기
week: 2026-W41       # ISO 주차(글자, GGGG-[W]WW)
weekday: 수          # 요일
icon: 📅             # 설정의 데일리 기본 아이콘(있으면)
---
```

- 이 YAML은 지금 파서(`yaml`)로 `date`·`monthday`·`week`·`weekday`는 글자, `year`·`month`는 숫자, `daily`는 참/거짓으로 읽힌다(확인함). 위젯 조건(`where: year = 2026`, `where: monthday = 10-07`)과 검색에 바로 쓸 수 있다.
- 쓰임 예: 해마다 오늘(`type: query` + `where: monthday = 10-07`), 이번 달 일기 목록(`where: [daily, year = 2026, month = 10]`), 주간 회고(`where: week = 2026-W41`).
- **이름이 기준, 속성은 따라온다**: 데일리 판정은 위 규칙대로 파일 경로·이름으로 한다. 속성은 만들 때 넣고, 앱에서 날짜 부분을 바꾸거나 "형식 옮기기"로 옮길 때 같이 고친다. 사람이 속성만 바꿔 이름과 날짜가 어긋나면 정리 점검(🧹)에 "데일리 속성과 이름 날짜가 다름"으로 나온다.
- 템플릿(`dailyTemplate`)에 프런트매터가 있으면 합친다. 같은 키는 위 자동 값이 이긴다(`icon`은 템플릿 값을 우선).
- 속성 이름은 위처럼 고정한다(영문, 기존 `title`·`summary`·`sources`와 같은 방식). 바꿀 수 있게 하지 않는다.

**바뀜: 날짜 속성 대신 자동 태그** (사용자, 2026-10-07)

위 날짜 속성(`daily`·`date`·`year`·`month`·`monthday`·`week`·`weekday`)은 넣지 않고, 프런트매터 `tags`에 계층 태그를 넣는다. 속성 탭이 날짜 값으로 차지 않고, 검색창 `#`·태그 목록·위젯 `from`에서 바로 찾을 수 있다.

```yaml
---
tags: [데일리/2026/10/07, 10-07, 2026-W41, 수요일]
icon: 📅
---
```

- 찾기: `#데일리`(모든 데일리 노트), `#데일리/2026`(그해), `#데일리/2026/10`(그달), `#10-07`(해마다 오늘), `#2026-W41`(그 주), `#수요일`. 계층 태그는 하위까지 잡힌다(검색창·위젯 `from`). 위젯 `where: tags = …`는 같은 태그만 본다.
- 맨 앞 말(`데일리`/`daily`)과 요일 이름은 볼트 언어를 따른다. 자동 태그는 모양으로 알아보므로 볼트 언어를 바꾼 뒤에도 고치고 점검한다.
- 템플릿의 다른 태그는 자동 태그 뒤에 그대로 둔다. 날짜를 바꾸면 있는 자동 태그만 고친다(사람이 지운 것은 다시 넣지 않는다). 어긋나면 정리 점검에 "데일리 태그와 이름 날짜가 다름". `icon`은 지금처럼 속성이다.
- 범위 비교(`year >= 2025`)는 태그로는 못 한다. 필요하면 경로·`modified` 조건을 쓴다.
- 태그는 프런트매터에 둔다(본문 줄과 기능은 같고, 본문을 깨끗하게 두려고). 태그 목록은 아직 평평해서 하루마다 태그가 늘어난다(→ 남은 것).
- 속성 패널(20번)에서 이 값들은 "자동" 표시를 하고 읽기 전용으로 보인다(날짜를 바꾸려면 제목 칸의 날짜 부분이나 이동으로).

### 2차에서 정한 것

### 23. 노트와 폴더 구분 없애기: 노드 = 노트이자 디렉토리 (P0, 사용자)

SiYuan·Notion처럼 모든 노드가 내용(노트)을 가지면서 하위 노드도 가진다. 트리에 "폴더"와 "문서"의 구분이 없다.

**파일 구조(정함): 형제 방식** — 노드 `A`의 노트는 `A.md`, 하위 노드는 `A/` 아래.

```
업무.md            ← 업무 노드의 노트
업무/
  프로젝트A.md      ← 하위 노드
  프로젝트A/
    회의록.md       ← 잎 노드(폴더 없음)
  주간보고.md
```

- 하위가 없으면 `A.md` 하나뿐이다. 첫 하위 노드를 만들 때 `A/`가 생기고, 마지막 하위가 없어지면 폴더도 사라진다. 그래서 "빈 폴더가 이력에 남지 않는" 1차 한계가 사라진다(새 폴더 = 새 노드 = `.md` 하나).
- `[[A]]` 링크, 다른 편집기(Obsidian 등)에서 그대로 읽힌다.
- **노트 없는 폴더**(`A/`만 있고 `A.md`가 없음)는 내용이 빈 노드로 보인다. 그 노드에 내용을 쓰면 그때 `A.md`를 만든다.
- 짝짓기는 같은 부모 안에서 이름이 정확히 같을 때만(`A.md` ↔ `A/`). 대소문자가 다르면 다른 노드다.

**트리·편집**:
- 노드마다 하위가 있으면 펼침 화살표, 이름을 누르면 그 노트를 연다. 메뉴에 "하위 노트 만들기".
- 문서 머리 경로(빵부스러기)는 상위 노드들이고, 누르면 그 노트를 연다.
- 노드 끌어 옮기기 = 노트와 하위 전체를 옮긴다. 다른 노드 위에 놓으면 그 노드의 하위가 된다.
- **이름 바꾸기·옮기기**: `A.md`와 `A/` 아래 전부를 **한 번의 일괄 쓰기(한 커밋)**로 옮긴다(2차 정한 것 8번 위에서). 링크 자동 갱신 포함.
- **삭제**: 하위 포함 삭제. 하위 개수를 보여 주고 확인받는다. 토스트 되돌리기는 하위까지 되살린다.

**권한(보안)**:
- 지금 규칙 `X`는 `X`와 `X/…`만 덮고 형제 파일 `X.md`는 덮지 않는다(`server/src/access.ts`). 노드 모델에서는 **규칙 `X`가 노드 노트 `X.md`도 덮어야 한다.**
- 그렇지 않으면 숨김 노드의 노트가 상위 규칙으로 보이는 일이 생긴다. `mayContainVisible`·트리 거르기도 같이 바꾸고, 숨김 노드의 노트·하위가 목록·검색·백링크·링크 해석에 새지 않는지 테스트한다.

**첨부(추천)**:
- 노드 모델에서 지금처럼 문서 옆 `attachments/`에 두면 `attachments`가 노트 없는 노드로 트리에 보인다.
- 그래서 붙여넣은 첨부는 **워크스페이스마다 하나인 첨부 폴더**(예: `<워크스페이스>/_첨부/`)에 두고 트리에서 숨긴다. 이름은 공통 설정에서 바꿀 수 있다.
- 노드 폴더 안에 이미 있는 비마크다운 파일은 노드가 아니라 그 노드의 "첨부 N"으로 접어 보인다.

**그 밖(추천)**:
- 정렬은 이름순(데일리 폴더는 최신순). 손으로 순서 바꾸기는 이후.
- 위젯 `from: 업무/프로젝트A`는 그 노드의 하위 전체(노드 자신의 노트는 빼고). 자신까지 넣으려면 `from: [업무/프로젝트A, 업무/프로젝트A.md]`처럼 적는다.
- LLM Wiki: `<토픽>/SCHEMA.md`·`raw/`·`wiki/`는 토픽 노드의 하위 노드로 그대로 둔다. 토픽 노드 노트(`<토픽>.md`)는 소개용으로 쓸 수 있다.
- MCP·REST는 지금처럼 경로로 다룬다. 노드 단위가 필요하면 `list_children(path)` 정도만 더한다.

### 24. 워크스페이스로 영역 나누기 (P0, 사용자)

개인노트·업무노트처럼 노트를 영역으로 나눈다.

**구조(정함): 최상위 노드 = 워크스페이스.** 볼트·Git·서버·동기화는 하나이고, 화면을 워크스페이스로 나눈다.

```
개인.md          ← 워크스페이스 노드 노트(소개·아이콘 icon 속성)
개인/

  _첨부/
업무.md
업무/
  경제/SCHEMA.md   ← 위키 토픽(워크스페이스 아래 2단계)
<공통 설정 파일>   ← 볼트 루트, 워크스페이스 밖
```

- 볼트 루트의 노드(23번 규칙의 `X.md`·`X/`)는 모두 워크스페이스다. 단, **공통 설정 파일은 루트에 있어도 워크스페이스가 아니다**(정해 둔 이름으로 뺀다). 루트에는 워크스페이스와 공통 설정 파일만 둔다. 화면에서 루트에 일반 노트를 만들 수 없다.

- 워크스페이스마다 열린 탭·트리 펼침·마지막 문서를 이 기기에 기억한다.
- 새 워크스페이스 만들기, 이름 바꾸기, 아이콘, 순서, 삭제는 설정 모달의 "워크스페이스" 묶음에서 한다.

**링크 해석(정함): 같은 워크스페이스 먼저.**
- `[[이름]]`은 링크를 쓴 노트의 워크스페이스 안에서 먼저 최단 경로로 찾고, 없으면 볼트 전체에서 찾는다. 다른 워크스페이스를 확실히 가리키려면 `[[업무/…]]`.

### 25. 아이콘만 있는 단추에 툴팁 (P0, 사용자)

**지금**: 아이콘 단추는 대부분 `IconButton`(`web/src/ui.tsx`)이고, 이름은 HTML `title`(브라우저 기본 툴팁)과 `aria-label`로만 준다. 기본 툴팁은 1초 가까이 올려 두어야 뜨고, 작고 모양이 제각각이라 무슨 단추인지 알기 어렵다. `IconButton`을 쓰지 않는 아이콘 단추(설정 검색 지우기, 속성 값 빼기 ×, 문서 목록 ☰ 등)는 `title`조차 없다.

**제안**:
- 앱 공통 **툴팁 컴포넌트** 하나: 마우스를 올리고 약 300ms 뒤, 또는 키보드로 포커스하면 바로 뜬다. 이름 + 단축키(있으면)를 보이고, 화면 가장자리에서는 반대쪽으로 뒤집는다. 다른 단추로 옮겨 가면 기다리지 않고 바로 바뀐다(레일·도구줄 훑어보기).
- `IconButton`이 `title` 대신 이 툴팁을 쓴다(접근성 이름은 `aria-label` 유지, 툴팁은 `aria-describedby`). 레일·트리 도구줄·문서 머리·오른쪽 패널 탭·상태 표시줄·모달 닫기·탭 닫기·속성 칸·이모지 고르기 등 **아이콘만 있는 모든 단추**를 `IconButton` 또는 같은 툴팁으로 바꾼다.
- 레일은 툴팁을 오른쪽에 띄운다. 처음 쓰는 사람을 위해 레일을 넓혀 이름까지 보이는 설정(아이콘 + 글자)도 둔다.
- 터치 기기에는 마우스 올리기가 없다. 길게 누르면 툴팁을 보이고, 손을 떼도 동작은 실행하지 않는다.
- 비활성 단추도 툴팁은 뜨게 하고, 왜 못 쓰는지 덧붙인다(예: "지금 문서 찾기 — 연 문서가 없음").

### 26. 다국어(i18n): 공식 영어·한국어, 비공식 언어팩 (P1, 사용자)

**지금**: 화면·서버 오류·MCP 도구 설명·정리 점검 메시지·자동 생성 문서가 모두 한국어로 코드에 박혀 있다. 한국어 글자가 든 문자열이 있는 줄이 `web/src` 약 780줄, `server/src` 약 300줄, `packages/core/src` 약 150줄이다. 날짜 표시(`10월 7일 (수)`), 요일 토큰(`ddd`→"수"), 커밋 메시지(`이동: a → b`)도 한국어 고정이다.

**공식 언어 = 영어(en)·한국어(ko)**
- 모든 화면 문자열을 키로 뺀 메시지 묶음(`en.json`·`ko.json`)으로 옮긴다. 둘이 같은 키를 갖는다. 영어가 기준(빠진 키는 영어로 대신 보임)이다.
- 끼워 넣기 `{name}`, 복수형은 `Intl.PluralRules`, 날짜·숫자는 `Intl.DateTimeFormat`·`Intl.NumberFormat`. 라이브러리는 가볍게(직접 구현 또는 작은 것). 메시지에 HTML을 넣지 않는다.
- 언어 고르기: 설정 → 일반 → 언어(이 기기). 기본값은 브라우저·OS 언어(`navigator.language`), 지원하지 않으면 영어. 바꾸면 새로고침 없이 바뀐다.
- 서버 오류는 응답에 코드(`code`)와 끼워 넣을 값을 싣고 화면이 번역한다. 코드가 없는 오래된 응답은 서버 문장을 그대로 보인다.
- 단축키 표시·툴팁(25번)·명령 팔레트 명령 이름·설정 검색 낱말도 같은 묶음을 쓴다. 설정 검색은 지금 언어와 영어 둘 다로 찾는다.

**비공식 언어팩**(내려받아 고쳐서 올리기)
- 설정 → 언어 → **"언어팩 내려받기"**: 공식 언어(en 또는 ko) 하나를 골라 JSON 파일로 받는다.
  ```json
  {
    "meta": { "id": "ja", "name": "日本語", "base": "en", "appVersion": "0.7.0", "author": "" },
    "messages": { "rail.files": "Files", "tree.newNote": "New note", "…": "…" }
  }
  ```
- 사용자가 `meta.id`·`meta.name`과 `messages`의 값을 고친다(키는 그대로).
- **"언어팩 불러오기"**: 파일을 고르면 검사한 뒤 언어 목록에 더하고 고를 수 있게 한다. 검사 결과를 보여 준다.
  - 모르는 키(무시), 빠진 키(기준 언어로 대신 보임, 개수 표시), 끼워 넣기 자리(`{name}`) 불일치(그 메시지만 기준 언어로)
  - 값은 글자로만 쓴다(HTML·스크립트로 해석하지 않음). 크기 제한(예: 1MB), JSON이 아니면 거부.
- 앱이 업데이트되어 키가 늘면, 설정에 "번역 없는 키 N개"를 보이고 **"빠진 키만 내려받기"**(그 키들과 기준 언어 문장만 담은 파일)를 둔다. 받은 것을 고쳐 다시 불러오면 합친다.
- 불러온 언어팩 내보내기(다시 받기)·지우기·바꾸기.
- 오른쪽에서 왼쪽으로 쓰는 언어(아랍어 등)의 화면 뒤집기는 이번 범위 밖(`dir`는 이후).

**화면 밖에서 쓰이는 글(정할 것 참고)**
- 볼트에 남는 글: 자동 생성 문서(위키 index·log, `SCHEMA.md` 템플릿), 새 노트 이름("제목 없음"), 충돌 사본 이름("동기화 충돌 사본"), 기본 폴더 이름(데일리 `데일리 노트`, 첨부 `_첨부`), 데일리 자동 태그(`데일리/…`·요일)·요일 토큰, `keyring-settings.md` 본문 안내
- 커밋 메시지(`생성:`·`수정:`·`이동:`…). `ScopedVault.history()`가 `/^이동: (.+) → (.+)$/`로 제목을 읽어 숨김 경로를 가리므로, 번역하면 이 처리가 깨진다.
- 에이전트에게 가는 글: MCP 도구 설명, 도구 오류, SCHEMA 템플릿
- CLI(`npm run keyring`) 출력, README

**정할 것**(추천):
1. **비공식 언어팩 저장 위치** — 추천: **이 기기**(테마처럼 화면 설정). 볼트에 두면 모든 기기가 같이 쓰지만, 마크다운이 아닌 파일은 서버 → 기기 한 방향 동기화라 기기에서 불러온 것이 올라가지 않는다.

**검증**:

### 27. 화면 설정 동기화 (P1, 사용자)

**지금**: 설정이 두 군데에 있다.
- **모든 기기 공통**(`keyring-settings.md`, 볼트 안 마크다운): 데일리·템플릿, 데일리 기본 아이콘, 첨부 위치, 새 링크 모양, 폴더 아이콘(4차 이후 볼트 언어). 웹은 서버 파일을 바로 읽고, 데스크톱·모바일 앱은 서버 동기화를 연결했을 때 동기화 주기(열 때·저장 10초 뒤·창 복귀·5분마다)로 받는다.
- **이 기기만**(`localStorage`의 `keyring:prefs` 등): 테마, 패널 폭·열림, 자동 저장 켜기·간격, 편집기 글꼴·크기, 줄 번호, Live Preview, 아이콘 보이기, 트리 표시, 데일리 표시·정렬, 단축키, 접힘, 열린 탭, 트리 펼침, 최근 이모지(26번 이후 화면 언어·비공식 언어팩). 브라우저가 다르면 웹끼리도 따로이고, 앱마다 따로다.

**제안(정함)**: 화면 설정을 "따라가는 것"과 "기기마다"로 나누고, 따라가는 것은 공통 설정 파일 안 **"화면" 묶음**에 둬서 지금 동기화를 그대로 탄다.

| 따라가는 것(공통 설정 파일 "화면") | 기기마다(`localStorage`) |
| --- | --- |
| 테마, 화면 언어 | 패널 폭·열림, 왼쪽 보기·오른쪽 탭 |
| 편집기 글꼴·크기, 줄 번호, Live Preview, 읽기 폭 | 접힌 상태, 열린 탭, 트리 펼침, 마지막 문서 |
| 자동 저장 켜기·간격 | 최근 이모지 |
| 아이콘 보이기, 트리 표시 옵션, 데일리 표시·정렬 | 비공식 언어팩(4차 정한 것 1) |
| 문서 위 속성·문서 끝 백링크 보기 | |
| 단축키(데스크톱·웹만) | |

- **이 기기에서만 다르게**: 따라가는 설정마다 "이 기기에서만 다르게" 켜기를 둔다. 켜면 그 값은 이 기기 `localStorage`에 덮어쓰기로 남고, 공통 값이 바뀌어도 따라가지 않는다. "공통 값으로 되돌리기"로 끈다.
- **값을 고르는 순서**: 이 기기 덮어쓰기 → 공통 설정 "화면" 값 → 기본값.
- **설정 화면 표시**: 항목마다 "모든 기기"·"이 기기" 표시. 덮어쓴 항목은 공통 값을 흐리게 함께 보인다.
- **단축키**: 공통 값은 데스크톱(앱)·웹에서만 쓰고, 모바일은 단축키 화면을 숨긴다. 웹의 대체 키(Alt…)는 지금처럼 웹에서 자동으로 바꿔 보이므로 저장은 같은 값 하나다.
- **화면 언어**: 26번에서 "이 기기"로 둔 것을 따라가는 설정으로 바꾼다(기기마다 다르게도 가능). 공통 값이 이 기기에 없는 비공식 언어팩이면 그 언어팩의 기준 언어(en·ko)로 보이고 "이 기기에 언어팩이 없음"을 알린다.
- **볼트 언어(4차 정한 것 2)와 화면 언어는 따로**다. 화면 언어를 바꿔도 볼트에 남는 글은 그대로.

**주의**:
- **깜빡임**: 공통 설정을 읽기 전에 화면이 기본 테마·글꼴로 먼저 그려지지 않게, 마지막으로 받은 "화면" 값을 이 기기에 캐시해 두고 시작 때 먼저 쓴다. 로그인 화면(서버 모드)도 그 캐시를 쓴다.
- **앱이 서버에 연결되지 않았으면** 따라가는 설정도 그 기기 안에서만 바뀐다(볼트 파일에는 쓰이므로 나중에 연결하면 따라간다). **공통 설정 파일은 동기화 충돌 사본을 만들면 안 된다.** 지금 문서 동기화 규칙으로는 기기와 서버가 같은 줄을 다르게 고쳤거나(처음 연결이라 기준점이 없는 경우 포함) 하면 `keyring-settings (동기화 충돌 사본 …).md`가 생기고 원래 경로는 서버 값이 된다. 설정 파일만은 줄 단위가 아니라 **값(키) 단위로 합치게** 동기화에 특별 처리를 둔다: 한쪽만 바꾼 키는 그쪽, 양쪽이 다르게 바꾼 키는 서버 값을 따르고 기기 값은 "이 기기에서만 다르게"로 남길지 묻는다.
- **쓰기 충돌**: 공통 설정은 지금처럼 값 하나씩 다시 읽고 바꿔 쓴다(baseHash, 409면 다시). 슬라이더처럼 연달아 바뀌는 값(글자 크기·자동 저장 간격)은 멈춘 뒤 한 번만 쓴다. 자동 저장 커밋 묶기(2차)와 웹훅 묶기를 같이 타서 이력·웹훅이 넘치지 않게.
- **바뀌면 바로 반영**: 동기화나 다른 탭에서 공통 설정이 바뀌면 새로고침 없이 테마·글꼴 등을 다시 적용한다(덮어쓴 항목은 제외).
- 에이전트는 공통 설정 파일을 읽을 수만 있다(2차). 화면 값은 민감하지 않지만, 덮어쓰기 값(`localStorage`)은 서버로 보내지 않는다.

**검증**: 웹(브라우저 둘)·`?local`·데스크톱 앱에서 테마·글꼴·단축키를 바꾸고 다른 쪽에 따라오는지, "이 기기에서만 다르게"가 공통 값 변경에 흔들리지 않는지, 모바일 화면에서 단축키 화면이 숨는지, 시작 때 깜빡이지 않는지, 오프라인에서 바꾼 뒤 연결했을 때.

## 데스크톱 앱 업데이트 (2026-10-18)

설계: `docs/superpowers/specs/2026-10-18-mac-distribution-design.md`. 릴리스 쪽 절차는 `docs/guides/release-macos.md`.

### 28. 앱 안에서 업데이트 받기 (P0, 사용자)

**정함·구현**:
- **실행 때 확인**: 데스크톱 앱(Tauri, 모바일 아님)이 뜨고 5초 뒤 한 번, GitHub 릴리스의 `latest.json` 을 읽는다(15초 시간 제한). 실패(오프라인 등)는 조용히 넘긴다.
- **묻기**: 새 버전이 있으면 작은 대화상자 「업데이트가 있습니다」 — 새 버전·지금 버전, 접힌 「바뀐 점」(릴리스 글), 「나중에」·「업데이트하고 다시 시작」. **받기·설치·재시작은 「업데이트하고 다시 시작」 을 누른 뒤에만** 한다. 받는 중에는 진행률(%)을, 설치 중에는 「설치하는 중…」 을 보이고 닫기를 막는다. 실패하면 오류를 보이고 단추가 「다시 시도」 가 된다. 설치 파일 서명은 앱에 박힌 공개 키로 확인한다.
- **설정**: 설정 → 이 기기·동기화 → **앱 업데이트**. 「업데이트 자동 확인」(기본 켜짐) — 끄면 실행 때 아무 요청도 보내지 않는다. 「업데이트 확인」 단추 — 바로 확인해 새 버전이 있으면 같은 대화상자, 없으면 「최신 버전입니다(버전)」 알림, 실패하면 오류 알림. 검색 낱말: 앱 업데이트·업데이트(app updates). 검색어에 맞는 줄이 없으면 이 절은 제목째 숨는다.
- **범위**: 데스크톱 앱에만 보인다. 웹·서버 모드(서버는 관리 화면 「업데이트」 탭이 따로 본다)와 모바일 앱, 브라우저 `?local` 에는 없다.
- **저장**: 기기마다(`localStorage` 의 `keyring:prefs` 안 `updateCheck`). 공통 설정 파일로 따라가지 않는다 — 이 앱 설치에 대한 결정이다. 「이 기기 설정 초기화」 를 하면 켜짐으로 돌아간다.

**확인한 것과 한계**: 「꺼져 있으면 확인 함수를 부르지 않는다」 는 단위 테스트(`web/src/updateCheck.test.ts`)로 본다. 실제 업데이트(옛 버전 설치 → 대화상자 → 설치·재시작)는 공개한 릴리스로 사람이 확인했다.

## 안내 문구 정리 (2026-10-19)

### 29. 빈 상태·안내 문구를 짧게, 필요 없는 것은 지우기 (P1, 사용자)

> 태그가 없습니다. 본문에 #태그나 프런트매터 tags를 쓰면 여기 모입니다. / 단어를 입력하세요. #태그로 태그 검색, 결과를 누르면 그 줄로 갑니다. / 아직 첨부 파일이 없습니다. 노트에 파일을 붙여넣거나 끌어다 놓으세요. 등 안내문구 좀더 간단하게 직관적으로. 필요 없는 경우는 문구 삭제. 첨부파일은 드래그 영역에 간단한 문구로 대체

**정함·구현**:
- **기준**: 빈 상태는 한 구절(한국어는 "~없음" 같은 명사구, 영어는 마침표 없는 구). 빈 목록이 스스로 뜻을 전하거나 화면의 다른 요소가 같은 말을 하면 문구를 지운다. 화면에서 알 수 없는 기능(예: `#태그` 가 모인다, 이모지를 붙여 넣고 Enter)은 짧게 남긴다. 오류·확인 대화상자·설정 항목 설명은 이 기준의 범위 밖이다.
- **지운 것**: 검색 패널의 입력 전 안내(입력칸 placeholder "검색 (#태그)" 가 같은 때 같은 말을 한다), 첨부 패널의 빈 상태와 "노트로 끌어다 놓으면 들어갑니다" 안내(끌어 놓기 영역과 항목 툴팁이 대신한다), 오른쪽 패널 "연결" 의 백링크 0개 문구(제목 "백링크 0" 이 같은 말), 빈 노드의 연결 탭 안내(문서 칸의 배너가 같은 말).
- **첨부 끌어 놓기 영역**: 첨부 패널 아래에 점선 영역 "파일을 끌어 놓거나 눌러 추가" 를 둔다. 파일을 놓거나 눌러 고르면 노트 붙여넣기·끌어 놓기와 같은 업로드(워크스페이스 첨부 폴더, 이름이 겹치면 " 2")로 올리고 노트에는 넣지 않는다. 올릴 곳은 패널이 보이는 워크스페이스("모든 워크스페이스" 면 지금 노트의 워크스페이스). 첨부가 없으면 찾기 칸을 숨기고 영역을 패널 맨 위에 크게, 있으면 목록 아래에 한 줄로 둔다. 목록의 첨부를 끌어 올 때(파일이 아닌 글)는 받지 않는다.

**확인한 것**: 시험 서버(임시 `KEYRING_DATA`, 8823)에서 헤드리스 Chromium 으로 태그·검색(입력 전·결과 없음)·첨부(빈 상태·끌어 오는 중·놓은 뒤)를 찍고, 놓은 파일이 `Work/_첨부/` 에 올라가 목록과 서버 트리에 나오는 것을 봤다. 실제 마우스로 Finder 에서 끌어 놓기와 데스크톱 앱(Tauri) 창은 보지 못했다.

## 휴지통 (2026-10-20)

### 14. 휴지통 — 삭제된 노트 목록과 되살리기

사용자는 질문 없이 바로 시작하라고 했다. 그래서 아래 「정함」은 **메인 세션이 정한 기본값이고 사용자와 합의한 값이 아니다.** 바꿀 때는 이 절과 사용자 문서(`docs/manual/*/how-to/organize-notes.md` 「Restore deleted notes」)를 함께 고친다.

**정함(메인 세션 기본값)·구현**:
- **무엇이 보이나**: 지금 볼트에 없는 마크다운 노트 중 이력에 지운 기록이 있는 것. 이동·이름 바꾸기로 사라진 옛 경로는 넣지 않는다(판정과 예외는 아래 「이동 판정」). 같은 경로(대소문자·NFC/NFD 를 가리지 않는다 — core `trashKey`)에 지금 파일이 있으면 그 노트는 보이지 않는다. 위키 자동 생성 문서(index·log)와 공통 설정 파일은 뺀다. 같은 경로를 두 번 지웠으면(다시 만들었다 또 지움) 두 줄이 다 보이고, 하나를 되살리면 다른 줄은 경로가 쓰이므로 숨는다.
- **묶음**: 한 번의 삭제(서버 커밋 하나, 앱 기록 하나) = 한 줄. 머리는 core `trashHead`: 노트 하나면 그 노트, `N.md` 와 `N/…` 만이면 노드 N, 노트 없는 폴더 노드는 모두 한 폴더 아래이고 그 폴더가 지금 없을 때 그 폴더, 그 밖(서로 상관없는 여러 노트, 일괄 쓰기 등)은 머리 없이 첫 노트 이름 + 「외 N개」. 줄마다 제목(파일 이름)·원래 위치·지운 시각·지운 사람(서버만 — 앱 기록의 작성자는 기기 이름이라 뺀다)·「하위 N개」·「첨부 N개」. 최근 것이 위.
- **미리보기**: 줄을 누르면 지우기 직전 내용을 렌더링해 읽기 전용으로 보인다(미리보기 안 링크는 눌러도 가지 않는다). 노드는 하위 노트를 골라 본다.
- **되살리기**: 화면이 본 노트(`paths`)를 지우기 직전 내용으로 원래 경로에 한 커밋/한 기록으로 만든다. 노드는 통째로. 목록을 본 뒤 그 자리에 파일이 생겼으면 덮어쓰지 않고 새 노트 이름 규칙대로 「 2」(core `restoreTargets` — 머리 노드가 있으면 노드째 「N 2」 아래로, 없으면 겹치는 파일만, `trashKey` 로 비교). 앱은 자리를 정한 뒤 대상마다 저장소에서 실제로 읽어(`store.read`, 일반 쓰기와 같은 방식) 목록이 모르는 같은 파일이 있으면 다음 이름으로 넘긴다. 서버는 `Vault.batch` 가 잠금 안에서 다시 읽어 409 로 막는다. 그 자리에 이미 같은 내용이 있으면(다른 창이 먼저 되살림) 건너뛰고, 다 건너뛰면 「되살릴 것이 없습니다」. 커밋 메시지는 `vaultText.commit.restoreDeleted`(「휴지통에서 되살리기: <노드>」). 되살린 뒤 토스트 「열기」로 노드 노트(없으면 첫 노트)를 연다. 이름이 겹쳤으면 「이름이 겹쳐 새 이름으로 되살림: …」. 링크는 고치지 않는다.
- **첨부**: 서버는 Git 에 있는 첨부를 바이트 그대로(`git show <커밋>^:<경로>`), S3 에 둔 첨부(`KEYRING_S3_BLOBS`)는 커밋 전후의 `.keyring-blobs.json` 을 대 보아 내용 해시로 S3 에서 받아 노드와 함께 되살린다. S3 를 꺼 둔 서버에서는 그 첨부를 「되살릴 수 없음」으로 센다. **앱(LocalVault)은 첨부 내용을 기록에 남기지 않으므로 되살릴 수 없다** — 노드 삭제 기록에 함께 지운 첨부 경로(`JournalEntry.attachments`, 이번에 더한 선택 필드)를 남겨 줄에 「첨부 N개는 되살릴 수 없음」을 경고색으로 보이고 마크다운만 되살린다. 이 필드가 없던 예전 기록은 0개로 보인다.
- **영구 삭제·비우기는 하지 않는다**(비목표 — Git 이력을 고쳐 쓰고 백업·동기화와 얽힌다). 「이력에 남아 있어 언제든 되살릴 수 있다」 안내 문구는 화면에 두지 않았다: 29번 기준(빈 상태는 한 구절, 빈 목록이 뜻을 전하면 지운다)에서 영구 삭제 단추가 없는 목록이 그 뜻을 전한다고 봤다. 사용자 문서에는 적었다.
- **범위**: 지금 워크스페이스, 「모든 워크스페이스」면 전부. 서버는 소유자만(에이전트 토큰은 403 `trash_owner_only`). 에이전트 MCP 도구는 없다.
- **분량**: 한 번에 50묶음(`TRASH_PAGE`), 「더 보기」로 이어 읽는다. `next` 는 그 쪽에서 마지막으로 훑은 커밋 해시(앱은 기록 id)이고, 다음 쪽은 그보다 오래된 것부터 읽는다 — 쪽 사이에 새로 지워도 겹치지 않는다. 서버는 후보를 이름 바꾸기 판정 없이 고르고(`git log --no-renames --diff-filter=D --format=%H --max-count=limit+1 [<cursor>^]`) 고른 커밋만 자세히 본다 — 커밋 객체(`git cat-file --batch`)와 변경 목록(`git diff-tree --stdin -z`, 트레일러 없는 커밋이 있으면 `-M` 으로 한 번 더). 메시지 글자로 레코드를 가르지 않으므로 메시지에 무엇이 들어도 판정이 깨지지 않는다. cursor 와 줄 id 는 지금 `HEAD` 의 조상이어야 한다(`merge-base --is-ancestor`) — 백업 복원으로 이력이 바뀌었으면 cursor 는 `rev_invalid`, 미리보기·되살리기는 없는 것으로 거부하고, 화면은 「이력이 바뀌어 목록을 처음부터 다시 불러왔습니다」를 알리고 첫 쪽부터 읽는다. 되살릴 내용은 `git cat-file --batch` 한 번으로 읽는다. `--skip` 은 `--diff-filter` 로 거르기 전의 커밋을 세므로 쓰지 않는다. 지금 있는 것만 지운 커밋은 건너뛰고, 한 요청에 후보 커밋을 limit 의 열 배까지 훑는다. 화면은 이어 붙일 때 id 로 중복을 거르고 불러오는 동안 「더 보기」를 막는다. 잰 값(3000커밋 뒤에 삭제 3개): 첫 쪽 0.9~1.6초(삭제 커밋을 찾으려 이력을 끝까지 걷는다 — git 이 커밋마다 트리를 비교하는 비용), 「더 보기」 69ms(이때 요청마다 git 2회. 지금은 커밋 객체를 따로 읽어 3~4회).
- **이동 판정**(2026-10-20 리뷰 반영, 코디네이터 판정): 내용 유사도가 아니라 **이동을 한 쪽이 아는 사실**로 가른다.
  - 서버: `Vault.batch` 가 커밋 메시지 끝 문단에 이동 트레일러를 남긴다 — `Keyring-Moves: <개수>` 와 이동마다 `Keyring-Move: <옛 경로><탭><새 경로>`(이동이 없는 일괄 쓰기도 `Keyring-Moves: 0`). 경로에는 제어 문자가 못 들어가므로(`normalizeVaultPath`) 탭·줄바꿈으로 갈라도 된다. 휴지통은 이 문단이 온전한 커밋에서는 이름 바꾸기 판정 없이 보고 트레일러의 옛 경로만 뺀다. 그래서 짧은 노트의 노드 이동·워크스페이스 이름 바꾸기·자기 링크 노트 이름 바꾸기처럼 링크를 고쳐 내용이 절반 넘게 바뀐 이동도 빠지고, 한 커밋에서 빈 노트를 지우고 다른 빈 노트를 만든 것은 지운 것이 보인다. 트레일러가 없는 커밋(예전 커밋, 서버 밖 변경 흡수)만 git 의 이름 바꾸기 짝짓기(`-M`)를 쓴다. S3 보관 첨부도 같다(트레일러가 없으면 같은 내용 해시가 새 경로에 생겼는지로). 끝 문단은 늘 서버가 쓰므로 메시지 본문에 적은 가짜 트레일러는 판정에 쓰이지 않는다 — 사람·에이전트가 준 메시지는 `Vault.batch`(검토 대기열 저장은 `review.create`)에서 줄바꿈·탭 말고 제어 문자를 지우고(`cleanMessage`, 거부하지 않는다), 휴지통은 커밋 객체를 그대로 읽으며, 트레일러 경로에 제어 문자가 있으면 믿지 않는다(재리뷰 R1: 전에는 `\x1e`·`\x1f` 를 넣어 레코드를 쪼개면 지운 노트를 숨길 수 있었다). 이력 화면·에이전트 이력(숨김 경로 가림 포함)·웹훅은 제목 줄(`%s`)만 읽어 트레일러가 보이지 않는다.
  - 앱: 앱 안의 이동은 기록의 `R`(from) 이다. 동기화로 받은 이름 바꾸기와 앱 밖(Finder 등) 이름 바꾸기는 한 기록 안의 지우기(`D`)와 만들기(`A`)로 남으므로, **같은 기록 안에서 지우기 직전 해시와 같은 해시의 `A`** 를 이동으로 본다. 해시마다 지운 것과 만든 것을 경로 순으로 하나씩 1:1 로 짝짓고 남는 지우기는 지운 것이다. 빈 내용은 서로 구별되지 않아 짝짓지 않는다(지운 빈 노트가 숨으면 안 된다). 앱 밖 변경은 원래 기록에 없던 새 경로를 남기지 않으므로, scan 이 **같은 검사에서 사라진 노트와 같은 내용인 새 파일만** `A` 로 기록한다.
- **들어가는 길**: 명령 팔레트 「휴지통」(단축키 기본값 없음), 홈 화면의 작은 링크 「휴지통」(최근 노트 아래). 화면은 도구 모달 틀(17번, `size="md"`). **레일에는 단추를 두지 않았다**: 레일의 도구(데일리·그래프·자료 가져오기·변경 검토·정리 점검)는 자주 쓰거나 기다리는 일이 있는 것이고, 휴지통은 드물게 찾는 곳이라 팔레트·홈으로 충분하다고 봤다.
- **API**: `GET /api/trash?folder=&cursor=` → `{items: TrashItem[], next}`, `GET /api/trash/preview?id=&path=` → `{path, content}`, `POST /api/trash/restore {id, paths?}` → `{restored: [from, to][], lost, rev}`. 화면은 `VaultApi.trash`·`trashPreview`·`restoreTrash`(REST·로컬 볼트 둘 다).

**한계**:
- **앱에서 한 이동·이름 바꾸기는 동기화 뒤 서버 휴지통에 옛 경로가 보인다.** 동기화는 경로마다 따로 보내므로(`sync.ts` 의 `remote.remove`·`remote.write`) 서버에는 지우기 커밋과 만들기 커밋이 따로 남고, 트레일러도 `-M` 도 둘을 짝짓지 못한다. 되살려도 사본이 생길 뿐 데이터 손실은 아니다. 앱 휴지통에는 없다.
- **앱에서 지운 노드는 동기화 뒤 서버 휴지통에 파일마다 한 줄로 쪼개진다**(같은 이유). 서버에서 되살리려면 줄마다 따로 한다.
- 앱: 동기화로 받은 이동·앱 밖 이름 바꾸기 중 **내용도 함께 바뀐 것**(서버에서 노드를 옮기며 링크를 고친 하위 노트 등)과 **빈 노트**는 이동으로 짝짓지 못해 옛 경로가 보인다.
- 서버: 서버 밖(Finder 등)에서 이름을 바꾸며 내용이 절반 넘게 바뀐 노트는 git 이 짝짓지 못해 옛 경로가 보인다(트레일러가 없는 흡수 커밋).
- 서버 밖에서 지운 파일을 서버가 아직 흡수하지 않은 채 그 경로로 노트를 옮겨 이동 커밋이 삭제로만 남는 경우(첫 회차 시험 중 겪음)는 이제 트레일러의 옛 경로로 빠질 것이나, 다시 재현해 보지는 않았다.
- 휴지통은 경로를 `-z` 로 읽어 큰따옴표·역슬래시가 든 경로도 맞게 읽는다. 이력 화면 쪽(`logWithFiles`)은 전과 같이 따옴표로 감싼 경로를 받는다.
- 이력 조회(`log`·`logWithChanges`·`logWithFiles`)는 아직 `%x1e`·`%x1f` 로 가른다. 새 커밋은 메시지를 거르고 작성자 이름도 제어 문자를 못 가지므로(에이전트 이름 규칙, 기기 이름 검사) 깨지지 않지만, 거르기 전에 만든 커밋의 제목 줄에 그 글자가 있으면 그 이력 줄이 어긋나게 보인다.
- 앱에서 첨부만 든 노드(마크다운 없음)를 지운 것은 기록이 없어 휴지통에 나오지 않는다.
- 앱: 한 번의 검사·동기화 안에서 지운 노트와 같은 내용(비지 않음)의 새 파일이 생기면(템플릿 사본 등) 이동으로 짝지어 지운 노트가 휴지통에 보이지 않는다. 내용은 새 파일에 남는다.
- 앱이 꺼져 있는 동안 다른 프로그램에서 지운 노트는 기록되지 않아 앱 휴지통에 나오지 않는다(열 때 사라진 파일을 기록과 대 보지 않는다).
- 대소문자만 다른 새 노트가 생기면 대소문자를 가리는 저장소(Linux 서버, `?local` 의 IndexedDB)에서도 지운 노트가 숨는다(설계 선택 — 리뷰 F10).

**남은 것**: 동기화가 한 번에 지운·옮긴 경로를 한 `batch`(move·delete 연산 여럿)로 보내기 — 위 한계 앞의 둘(앱발 이동의 서버 휴지통 누출, 앱발 노드 삭제의 쪼개짐)을 함께 푼다. 동기화 프로토콜을 바꾸는 별도 작업이다.

**확인한 것**: 시험 서버(임시 `KEYRING_DATA`, 8871)와 `?local` 에서 헤드리스 Chromium(Playwright)으로 홈 링크 → 빈 휴지통(「삭제된 노트 없음」), 빈 노트 이름 바꾸기 뒤 휴지통에 없음, 노트 삭제 → 목록 → 미리보기(굵은 글씨까지 렌더링) → 되살리기 → 토스트 「열기」로 열림, 노드(하위 2 + 첨부 1) 삭제 → 「하위 2개 · 첨부 1개」(앱은 「첨부 1개는 되살릴 수 없음」) → 하위 노트 골라 미리보기 → 되살리기(서버는 첨부 바이트까지 같음), 목록을 연 채 다른 창(서버 API·앱 IndexedDB)에서 같은 이름을 만든 뒤 되살리기 → 「겹침 2」, 390px·어두운 테마(가로 넘침 없음). 데스크톱 앱(Tauri) 창, S3 를 켠 서버의 화면, 실제 마우스 조작은 보지 못했다(S3 첨부는 시험에서만).

**확인한 것(리뷰 반영 회차)**: 시험 서버에서 짧은 링크 노트 셋(`[[W/b]]` 등)이 든 워크스페이스를 설정 → 워크스페이스 → 「이름 바꾸기」로 `W → R` 바꿈 → 링크가 `see [[R/a]]` 로 고쳐지고 휴지통 첫 쪽(가장 최근 커밋이 맨 위)에 옛 경로 없음, 이력 화면 글은 제목 줄 「노드 이동: W → R」 뿐. 지운 커밋 121개에서 「더 보기」 단추를 한 틱에 다섯 번 눌러 요청 1번·100줄·중복 0, 쪽 사이에 다른 창에서 하나 더 지운 뒤 「더 보기」 → 121줄·중복 0·끝. 390px·어두운 테마 가로 넘침 없음. 이번 회차에 `?local` 화면은 다시 보지 않았다(앱 쪽은 시험으로).

**재리뷰 반영(2026-10-20)**: R1(메시지 제어 문자로 휴지통 위조)·R3(백업 복원 뒤 낡은 cursor)를 고치고 시험으로 실증했다(둘 다 되돌리면 새 시험이 떨어진다). R4(서버 전체 실행에서 `devices.test.ts` 가 가끔 5초 초과): `main` 에서 서버 전체를 4번 돌리면 4번 다 180/180 통과라, 이 브랜치가 더한 휴지통 시험의 커밋 부하로 봤다. 휴지통 시험의 시드를 한 커밋으로 묶은 뒤 이 브랜치에서 서버 전체 4번 연속 198/198 통과. 기계 부하에 따라 휴지통 시험 파일 단독 시간이 9~27초로 흔들려 시간 비교는 약하다.

## 홈 고정 (2026-10-21)

### 13. 홈 — 고정(즐겨찾기)

사용자는 「진행해줘」라고만 했다. 그래서 아래 「정함」은 **코디네이터가 정한 기본값이고 사용자와 합의한 값이 아니다.** 바꿀 때는 이 절과 사용자 문서(`docs/manual/*/how-to/organize-notes.md` 「Pin notes」)를 함께 고친다.

**정함(코디네이터 기본값)·구현**:
- **무엇을 고정하나**: 노드(노트이자 디렉터리, 23번). 노트 없는 폴더 노드도 고정할 수 있다. **워크스페이스 노드는 고정하지 않는다** — 워크스페이스는 레일의 전환 목록과 홈 제목이 이미 맡고, 워크스페이스를 고정해도 그 범위 안에서 갈 곳이 늘지 않는다.
- **어디에 두나 — 이 기기(`localStorage` 의 `keyring:pins`)**. 읽고 쓰는 곳은 `web/src/pins.ts` 하나뿐이다(옮기게 되면 이 파일만 바꾼다). 값은 노드 경로(`.md` 없이)를 고정한 순서대로 둔 목록 하나이고, 경로의 첫 마디가 워크스페이스라 워크스페이스마다 따로 보이며 「모든 워크스페이스」면 다 보인다. 고칠 때는 창이 들고 있는 값이 아니라 저장소의 지금 값에서 고치고, 다른 창·탭의 변경은 `storage` 이벤트로 따라간다.
  - **처음 기본값은 공통 설정 파일(`keyring-settings.md` 의 워크스페이스별 묶음)이었으나 버렸다**(구현 중 워커가 찾아 코디네이터가 판정). 공통 설정 파일은 에이전트에게 규칙대로 읽힌다(`ScopedVault.level` 은 쓰기만 `read` 로 깎는다). 볼트 전체 읽기에 `개인/일기 none` 같은 거부 예외를 둔 에이전트는 `read_document`·`read_section`·`list_frontmatter`·`GET /api/revision`(과거 판)으로 숨김 노드의 고정 경로를 볼 수 있다. 내용은 안 새도 이름이 새므로 권한 약속을 깬다 — 「한계로 적고 그대로」(A안)는 탈락. 에이전트에게 줄 때 그 줄을 걸러 내는 B안은 현재 판·과거 판·섹션·프런트매터·백업 등 표면이 넓어 하나만 빠져도 조용히 새는 종류라 이번 범위로 받지 않았다.
- **경로를 따라간다**: 이 기기에서 한 이동·이름 바꾸기 뒤 탭·최근 목록을 고치는 자리(`Workspace.tsx` `afterMove`)에서 노트 파일 하나(하위 폴더는 그 자리에 둔다), 노드 옮기기(`moveNodeTo` — 트리 끌기·F2·「다른 노트로 옮기기」·되돌리기)와 워크스페이스 이름 바꾸기에서 노드째(하위·노트 없는 하위 노드 포함)로 고친다. 서버·`?local` 모두 웹 화면이 같은 길로 고친다. 옮긴 자리에 이미 고정이 있으면 하나만 남긴다.
- **지운 노트**: 목록에서 **걷지 않고 화면에서만 숨긴다**(지금 있는 노드만 보인다). 삭제 알림의 되돌리기·휴지통 되살리기로 같은 경로에 돌아오면 다시 보인다. 다른 기기에서 옮겨 와 경로가 없어진 고정도 같은 길로 숨는다. 대가는 아래 한계.
- **워크스페이스 삭제**: 그 워크스페이스의 고정을 걷고(24번 「같이 걷는 것」과 같은 자리), 알림의 되돌리기면 원래 자리에 다시 넣는다(`dropWorkspacePins`·`restoreWorkspacePins`).
- **들어가는 길**: 트리 오른쪽 클릭 메뉴 「고정」/「고정 해제」(워크스페이스 노드에는 없음), 노트 메뉴(⋯)와 명령 팔레트 「고정」/「고정 해제」(지금 노트, 단축키 기본값 없음).
- **홈**: 「고정」 묶음을 최근 노트 위에 둔다(이름 + 흐린 상위 경로, 탭에 열려 있으면 「탭」). 비어 있으면 묶음째 숨긴다(빈 상태 문구 없음 — 29번).
- **왼쪽 패널**: 노트 보기의 트리 위에 접을 수 있는 「고정 N」 묶음(고정이 있을 때만). 줄은 트리처럼 아이콘·이름이고 「모든 워크스페이스」면 상위 경로를 흐리게 붙인다. 누르면 새 탭에 연다(트리와 같다). 줄 오른쪽 단추(마우스를 올리면, 터치 기기는 늘)로 고정 해제. 길어지면 패널 높이의 40% 안에서 스크롤한다. 접힘은 이 기기(`keyring:prefs` 의 `pinsOpen`). 레일 단추는 두지 않았다 — 제안의 「레일에서도 쓴다」는 이 묶음으로 본다.
- **순서**: 고정한 순서(새것이 끝). 손으로 순서 바꾸기는 하지 않는다.
- **에이전트**: MCP 도구 없음. 고정은 볼트에 쓰지 않으므로 에이전트는 볼 수 없다.

**한계**:
- **기기 간 공유가 없다.** 브라우저·앱마다 목록이 따로다.
- **다른 기기·동기화로 들어온 이동·이름 바꾸기는 따라가지 못한다.** 그 경로가 없어지면 목록에서 숨을 뿐이고, 새 경로에서 다시 고정해야 한다. 앱 밖(Finder 등)에서 바꾼 이름도 같다.
- 숨긴 고정은 저장소에 남는다. 지운 노트와 같은 경로에 새 노트를 만들면 그 노트가 고정된 채로 보인다.
- 휴지통에서 이름이 겹쳐 「 2」 로 되살린 노트는 고정이 따라가지 않는다.
- 있는지는 **대소문자를 가려** 본다(`pinExists`, 최근 목록과 같다). 다른 기기에서 대소문자만 바꾼 노드의 고정은 숨고, 새 대소문자로 다시 고정해야 한다 — 옛 대소문자로 열면 대소문자를 가리는 서버에서 빈 노드가 열려 따로 파일이 생길 수 있어서다.
- 저장소에 쓰기가 실패하면(할당량 초과·사생활 모드) 바꾼 값은 이 창에만 남고, 다음 변경은 저장소의 옛 값에서 고치므로 연달아 바꾼 앞의 것이 사라진다.
- 다른 탭은 트리를 새로 받기 전까지 그 탭이 모르는 경로로 옮긴 고정을 숨긴다(저장값은 바로 받는다). 다른 탭의 트리가 낡아 있는 기존 동작과 같은 모양이다.
- 브라우저에서 같은 주소(같은 출처)로 서버 모드와 `?local` 을 오가면 두 볼트가 목록 하나를 같이 쓴다(최근 노트 `keyring:recent` 와 같다). 다른 볼트의 경로는 그 볼트에 없으면 숨는다.

**남은 것**: 에이전트가 읽지 못하는 볼트 안 저장소(또는 에이전트 응답에서 그 값을 안전하게 걸러 내는 길)가 생기면 고정을 그리로 옮겨 기기 간에 공유한다. 손으로 순서 바꾸기는 노드 손 정렬과 함께.

**확인한 것**: 단위 시험 `web/src/pins.test.ts`(23개 — 넣기·빼기, 노트·노드·워크스페이스 이름 바꾸기와 다른 워크스페이스로 옮기기, 앞부분만 같은 형제, 노트 파일만 옮긴 것, 겹침, 파일마다 정확히 옮긴 뒤 노드째 옮겨도 한 번 옮긴 것과 같음(하위·앞부분 같은 형제 포함), 워크스페이스 삭제·되돌리기, 지운 노드 숨김, 범위, 있는지 판정(대소문자·앞부분 같은 형제), 저장소 읽기·다른 창 값 위에서 고치기·깨진 값). 시험 서버(임시 `KEYRING_DATA`, 8893, `pin.localhost`)에서 헤드리스 Chromium(Playwright)으로 트리 메뉴 고정 → 왼쪽 패널·홈에 보임 → 팔레트로 하위 노트 고정 → 노트 이름 바꾸기·노드 이름 바꾸기(하위 고정 따라감) → 삭제하면 숨고 되돌리면 다시 보임 → 줄 단추로 고정 해제 → 접기 → 다른 워크스페이스(묶음 없음) → 모든 워크스페이스 → 설정에서 워크스페이스 이름 바꾸기(고정 경로가 새 이름으로) → 워크스페이스 삭제(그 고정 걷힘) → 되돌리기(원래 자리로), 390px·어두운 테마(가로 넘침 없음). `?local` 에서 워크스페이스·노트를 화면으로 만들고 트리 메뉴·팔레트 고정, 노드 이름 바꾸기, 트리 끌어 옮기기(하위 고정 따라감), 삭제·되돌리기, 홈, 팔레트 고정 해제, 다른 워크스페이스, 390px·어두운 테마. 데스크톱 앱(Tauri) 창·여러 창 사이의 `storage` 이벤트·실제 터치 기기는 보지 못했다.

## 아이콘 고르기 창 (2026-10-21)

### 10. 아이콘 고르기 창 — 더 많은 이모지·묶음, 최근 줄 잘림

사용자 요청: 「더 다양한 아이콘 + 종류별로 그룹핑」, 「아이콘 선택 시 최근 아이콘 잘려서 보이는 중」. 아래 「정함」은 **코디네이터가 정한 기본값이고 사용자와 합의한 값이 아니다.** 바꿀 때는 이 절과 사용자 문서(`docs/manual/*/how-to/organize-notes.md` 「Give a note an icon」)를 함께 고친다.

**잘림의 원인(관찰한 값)**: 창(`.icon-picker`)은 높이 상한 420px 의 세로 flex 이고 `overflow: hidden` 이었다. 그 안의 최근·전체 두 `.icon-grid` 가 각자 `overflow: auto; min-height: 0` 이라, 넘친 높이를 두 그리드가 내용 크기 비율로 나눠 깎았다. 최근 16개(두 줄, 내용 66px)가 **21px** 로, 전체(내용 984px)가 307px 로 줄어 최근은 첫 줄도 다 보이지 않았다(1280×800, 헤드리스 Chromium).

**정함(코디네이터 기본값)·구현**:
- **스크롤은 한 곳**: 최근과 모든 묶음을 스크롤 영역 하나(`.icon-picker-body`)에 넣고 그리드에는 스크롤을 두지 않는다. 그리드끼리 높이를 나누는 구조가 없어 잘림이 다시 생기지 않는다. 창 높이는 `min(420px, 70vh)` 로 고정한다 — 목록을 늦게 받아도 창 크기가 그대로라 처음 정한 자리(화면 안)를 벗어나지 않는다.
- **목록**: 유니코드 이모지를 **Emoji 14.0 판까지** 싣는다(1,849개, `MAX_EMOJI_VERSION`). 14.0(2021)은 macOS 12.3·iOS 15.4·Windows 11(2022년 업데이트)·Android 12L 부터 그린다. 15.0 이상(65개)은 2023년 이후 OS 에만 있어 그보다 오래된 기기에서 두부(□)로 보인다(OS 별 지원 판은 알려진 지원 표 기준이고 기기로 재지 않았다). 피부색 변형(2,030개)·component(피부색 견본·머리 조각)·지역 지표 글자 단독은 뺀다.
- **데이터**: `emojibase-data` 17.0.0(MIT)의 `ko`·`en` `data.json`. 손으로 늘리지 않는다. 18.0.0 이 아니라 17.0.0 인 이유: 18.0.0 은 고를 때 배포 5일째(2026-10-16)였고, 14.0 판까지만 쓰므로 17 로 충분하다. 빌드 때 `virtual:emoji-data`(`web/vite.config.ts` 의 `emojiData`)가 `buildCatalog`(`web/src/emojiCatalog.ts`)로 쓰는 칸(이모지·한영 이름·검색 낱말)만 골라 싣는다 — 원본 두 벌은 약 1.6MB.
- **FE0F**: emojibase 는 `⭐`·`👍` 처럼 원래 이모지로 그려지는 한 글자에도 FE0F 를 붙여 둔다(152개). 떼어 유니코드 정식 형태로 맞춘다(`canonicalEmoji`) — 안 떼면 예전에 고른 아이콘(`icon: ⭐`)이 창에서 「지금 아이콘」으로 켜지지 않고, 같은 이모지가 두 글로 저장된다. 🗓️ 처럼 글자로 그려지는 것에는 FE0F 가 있어야 하므로 둔다. 검색칸에 붙여 넣고 Enter 로 고른 것도 정식 형태로 저장한다(`pastedEmoji` — `⭐️` 를 붙여 넣으면 `⭐`). 「지금 아이콘」 켜짐·최근 목록 중복·이모지로 찾기는 FE0F 를 가리지 않고 비교한다(`sameEmoji`). 이미 저장된 프런트매터 값은 바꾸지 않고 그대로 보인다. 최근 목록에 `⭐️`·`⭐` 가 함께 저장돼 있으면 읽을 때 앞의 것 하나만 남긴다(`recentIcons`).
- **지연 로드**: 창을 처음 열 때 `import("virtual:emoji-data")`. 청크 332KB(gzip 86KB). 서비스 워커의 지연 자산 목록에 저절로 들어가 웹도 오프라인에서 열리고, 앱(Tauri)은 번들 안에 있다. 첫 로드 JS 는 예전 손 목록(228개)이 빠져 1,358,496 → 1,354,628 B(gzip 443,923 → 441,113 B)로 줄었다. CSS 는 78,132 → 78,649 B. 받다가 실패하면 「이모지 목록을 불러오지 못함 · 페이지를 새로 고친 뒤 다시 열거나, 이모지를 붙여 넣고 Enter」. 실패해도 붙여 넣기 Enter 와 「지우기」는 된다.
- **묶음**: 표정과 감정·사람과 몸·동물과 자연·음식·여행과 장소·활동·사물·기호·깃발(emojibase 의 group 순서), 맨 위 「최근」(있을 때만). 창 위 묶음 단추 줄(대표 이모지 🕒 😀 👋 🐻 🍔 🚗 ⚽ 💡 🔣 🚩, 툴팁·`aria-label` 은 화면 글 `icon.group.*`). 누르면 그 묶음 머리로 스크롤하고, 스크롤하면 머리가 맨 위를 지난 마지막 묶음 단추가 켜진다(`aria-current`). 묶음 이름 줄은 스크롤해도 위에 붙어 있다(sticky). 단추는 Tab 으로 닿는다(검색칸 → 지우기 → 묶음 단추 → 이모지).
- **검색**: 한국어·영어 이름과 검색 낱말, 예전 손 목록의 낱말(`web/src/emojiWords.ts`, 228개 — 「데일리」「일기」 등)을 덧붙인다. 낱말이 여럿이면 모두 맞아야 한다. 검색 중에는 묶음 단추를 숨기고 묶음 없이 평평하게, 이름(또는 그 조각)과 같은 것 → 검색 낱말과 같은 것 → 부분 일치 순서(같은 정도 안에서는 목록 순서). 그래서 「star」 Enter 는 ⭐, 「데일리」는 📅, 「책」은 📕. Enter·붙여 넣은 이모지·Esc 는 예전과 같다.
- **이모지 단추 이름**(`aria-label`): 화면 언어가 한국어면 한국어 이름, 그 밖은 영어 이름(예전에는 이모지 글자 그대로).
- **바꾸지 않은 것**: 프런트매터 `icon` 값 형식, `DocIcon`, 「지우기」, 최근 저장 키 `keyring:recent-icons`(16개).
- **성능**: 버튼 1,865개(최근 16 + 1,849)를 한 번에 그린다. 빌드본 시험 서버에서 누른 뒤 목록이 다 그려질 때까지(이중 rAF) 처음 열기 28~42ms(청크 받기 포함, 5회), 다시 열기 13~19ms(헤드리스 Chromium, Apple Silicon). 묶음별 지연 그리기는 하지 않았다.

**한계**:
- **Windows 10** 의 기본 글꼴은 Emoji 13.0 이후를 갖추지 못해(알려진 지원 범위), 목록의 13.0~14.0 이모지 111개가 두부나 겹친 글자로 보일 수 있다. Android 12 이하·macOS 12.3 이전도 그 판의 일부가 같다. 기기에서 실제로 그려지는지는 재지 않는다(판 기준만).
- 피부색 변형과 15.0 이후 이모지는 목록에 없다 — 검색칸에 붙여 넣고 Enter 로만 고른다.
- 검색 낱말은 한국어·영어뿐이다. 비공식 언어팩 화면에서도 한·영 낱말로 찾고, 이모지 단추 이름은 영어다.
- 묶음 단추 사이를 화살표 키로 옮기지 않는다(Tab 으로 10개를 지난다).
- 새 패키지의 라이선스 고지: 저장소에 제3자 라이선스 고지 관례가 없어(다른 MIT 의존성도 같다) 따로 두지 않았다. 빌드는 `/*! */` 주석도 지운다.
- `emojibase-data` 의 peer `emojibase`(18.0.0)는 pnpm 이 자동으로 깔았다. 타입만 가리키고 번들에는 들어가지 않는다.
- 최근 줄 잘림은 단위 시험이 아니라 화면 측정으로 고정했다(시험 환경에 레이아웃이 없다).
- **목록 받기에 한 번 실패하면 새로 고쳐야 다시 받는다.** 브라우저(Chromium 에서 확인)가 실패한 동적 import 를 모듈 맵에 기억해, 같은 페이지에서 창을 다시 열어도 같은 청크를 다시 요청하지 않는다. 웹에서 서비스 워커가 청크를 캐시하기 전에 끊겼을 때만 생기고, 앱(Tauri)은 번들 안이라 거의 없다(WKWebView 동작은 보지 않았다). JSON 자산 + `fetch` 로 바꾸면 다시 시도되지만 서비스 워커 목록·오프라인 경로가 함께 바뀌어 하지 않았다 — 실패 문구로 새로 고침을 안내한다.

## 검색 필터 (2026-10-21)

### 15. 검색 — 폴더·태그 필터와 결과마다 여러 줄

사용자는 「15번 진행」이라고만 했다. 그래서 아래 「정함」은 **코디네이터가 정한 기본값이고 사용자와 합의한 값이 아니다.** 바꿀 때는 이 절과 사용자 문서(`docs/manual/*/how-to/find-notes.md` 「Search」·「Narrow by folder and tag」)를 함께 고친다.

**정함(코디네이터 기본값)·구현**:
- **폴더 필터**: 검색 칸 아래 「모든 폴더」 칩을 누르면 팔레트(옮길 곳 고르기와 같은 틀)로 폴더를 고른다. 후보는 화면의 노드 트리에서 지금 범위(워크스페이스, 「모든 워크스페이스」면 전부) 안의 **하위 폴더가 있는 노드**다(`folderChoices` — 하위가 없는 노드는 노트 하나라 고를 것이 없다). 트리는 서버가 볼 수 있는 것만 주므로 목록도 그 범위다. 고르면 `search(q, {folder})` 로 그 노드의 노트와 하위만 찾는다(앞부분만 같은 형제는 빼고). 칩에는 범위 안의 경로로 보인다.
- **태그 필터**: 「태그 추가」(지금 범위, 폴더를 골랐으면 그 안의 태그와 문서 수)에서 고르면 칩이 된다. 여럿이면 **모두 가진 문서**(AND), 하위 태그도 맞는다(`#a` 는 `a/b` 도). 검색어의 `#태그` 문법은 그대로이고, 문법과 칩은 한 조건 목록으로 합쳐 모두 만족해야 한다(core `parseSearchQuery`·`hasAllTags`). 칩만 있고 글이 없어도 찾는다(그 태그를 가진 문서 목록). 폴더만으로는 찾지 않는다.
- **결과마다 여러 줄**: 서버·앱이 결과마다 일치 줄을 앞에서부터 `lines` 만큼(상한 **50줄**, `SEARCH_LINES_MAX` — REST·MCP 용)과 전체 개수(`matchCount`)를 준다(core `searchHit`). 화면은 **10줄**만 받고(`SEARCH_LINES_FETCH`), 앞의 **3줄**(`SEARCH_LINES_SHOWN`)을 줄 번호와 함께 보이고, 나머지는 「N줄 더」로 펴고(최대 10줄) 같은 단추 「접기」로 접는다. 10줄을 넘는 문서는 펼친 뒤 「나머지 N줄은 노트에서 찾으세요」(`matchCount` 로 센다). 검색어·폴더·태그가 바뀌면 펼친 결과는 다시 접힌다(`searchKey`). 줄은 검색어 단어 중 하나라도 든 줄이다(대소문자 무시). 제목·경로·태그로만 맞은 문서는 줄 없이 문서 머리만 보인다. 의미 검색 결과는 예전처럼 요약 한 줄이다.
- **줄 누르기**: 그 줄로 가서 고른다 — 검색어 글 단어를 띄어 이은 것이 그 줄에 있으면 그것, 아니면 그 줄에 든 첫 단어(`selectionFor`, `#태그` 단어는 뺀다. 예전에는 검색어 통째를 넘겨 여러 단어·`#태그` 가 섞이면 고르지 못했다). 문서 머리를 누르면 첫 일치 줄. 이동은 예전과 같은 길(`gotoLine`·`setPendingAnchor`)이다.
- **필터 상태**: 앱이 떠 있는 동안 `Workspace` 의 상태로 들고 저장하지 않는다(패널을 바꿔도 남는다). 켜진 필터는 칩(테두리·배경 강조)으로 보이고 칩마다 ×, 「필터 지우기」로 한 번에 지운다. 굵은 포인터(`pointer: coarse`)·좁은 화면(800px 이하)에서는 칩 × 의 누르는 자리가 32×32px 다(보이는 크기 20px 는 그대로). 워크스페이스를 바꿔 고른 폴더가 범위 밖이 되면 **폴더만** 걷는다(태그는 칩으로 보이니 둔다).
- **키보드**: 「N줄 더」와 「접기」는 같은 단추 하나이고 `aria-expanded` 만 바뀐다 — 눌러도 포커스가 그 단추에 남는다. 칩 × ·「필터 지우기」를 키보드(Enter·Space)로 누르면 포커스가 다음 태그 칩의 × 로(없으면 검색 칸으로) 간다. 포인터로 누르면 포커스를 옮기지 않는다 — 터치 화면에서 검색 칸에 포커스를 주면 화면 키보드가 올라온다.
- **의미 검색**: 의미 칸에서는 필터 줄이 숨고 필터를 쓰지 않는다(범위 밖 — 아래 「남은 것」).
- **API**: `GET /api/search?q=&folder=&tag=&tag=&lines=&limit=`. `ScopedVault.search`·`LocalVault.search` 의 옵션 `{folder, tags, limit, lines}`. `lines` 는 0 이상의 정수만 받고(`1e3`·`2.9`·음수·글자는 400 `bad_request`·`integer_required`, 빈 값은 안 준 것) 50 을 넘으면 50 이다. `lines` 를 주지 않으면 응답은 예전 모양(`path, title, line, snippet`)이라 MCP `search` 도구의 응답은 바뀌지 않았다. 웹은 `api.search(q, {folder, tags, lines})`(REST·로컬 볼트 둘 다).
- **권한**: 폴더·태그 조건은 `ScopedVault` 에서 권한 판정(`canRead`) **뒤에** 거른다. 숨긴 폴더·태그를 필터로 주면 없는 폴더·태그와 **글자 하나 다르지 않은 응답**(빈 결과)이고 오류에 이름을 되돌려 주지 않는다. 일치 줄도 읽을 수 있는 문서에서만 나온다. 서버는 요청 경로를 로그에 남기지 않는다(`app.ts` 에 요청 로거가 없고, `onError` 는 예상하지 못한 오류만 찍는데 필터는 오류를 내지 않는다).

**한계**:
- 폴더 고르기는 하위 폴더가 있는 노드만 보인다. 노트 하나만 찾으려면 그 노트를 열고 찾기 막대(`Ctrl/Cmd+F`)를 쓴다.
- 일치 줄은 본문(프런트매터 포함)에서 검색어 단어 중 하나가 **글자 그대로** 든 줄이다. 제목·경로로만 맞은 문서는 줄이 없다(예전 `line: 1` 과 같다).
- 줄 글은 앞뒤 공백을 걷은 앞 200자다. 고를 글이 200자 뒤에 있으면 그 줄로만 가고 고르지 않는다.
- 결과 수 상한은 그대로다(화면 50문서, REST `limit` 최대 100). 한 요청에 일치 줄까지 실으므로 응답이 커질 수 있다 — 줄 글만 셀 때 **화면 최악 50문서 × 10줄 × 200자 = 10만 자**, **REST 최악 100문서 × 50줄 × 200자 = 100만 자**(`limit=100&lines=50`. 리뷰가 합성 볼트에서 잰 응답 2.52MB, UTF-8). 화면이 50줄을 받던 때는 같은 합성 볼트에서 1.26MB 였다(리뷰 측정).
- 좁은 화면(800px 이하)은 노트가 미리보기로 열리는 기존 기본값(`Workspace.tsx` `lastMode`)이라 줄 이동 뒤 고른 글이 보이지 않는다(이번에 바꾸지 않음).

**남은 것**: 정렬 바꾸기(관련도·이름·수정 시각), 의미 검색에도 폴더·태그 필터, 일치 글자 강조(줄 안의 검색어 표시), 트리 메뉴의 「이 폴더에서 찾기」.

## 오픈 소스 라이선스 고지 (2026-10-22)

### 설정 「일반」 — 오픈 소스 라이선스

사용자가 고른 길은 「빌드 때 자동으로 모으고 앱 안에서 보여 준다」 하나다. 아래 「정함」의 범위·자리·형식은 **메인 세션이 정한 기본값이고 사용자와 합의한 값이 아니다.** 라이선스 판단 셋(아래 「정함」 의 dompurify·MPL-2.0·라이선스 파일 없는 패키지)은 메인 세션이 판정했다. 바꿀 때는 이 절, `docs/guides/development.md` 「의존성과 라이선스 고지」 절, 사용자 문서(`docs/manual/*/how-to/customize-settings.md` 「Open Settings」 의 General 행), README 「License」 를 함께 고친다.

**정함(메인 세션 기본값)·구현**:
- **자리**: 설정 「일반」 의 맨 끝 줄 「오픈 소스 라이선스」 와 「열기」 단추. 설정 검색에 걸린다. 누르면 모달(크게 보기 단추 있음)에 `licenses.txt` 전문을 고정폭 글로 보인다. 본문이 처음 포커스를 받아 바로 PageDown·↓·End 로 스크롤된다. 새 창 대신 모달인 것은 앱(Tauri)에 새 탭이 없어서다. 모달은 Esc 로 고지 창만 닫히고 설정은 남는다.
- **파일**: 빌드가 `licenses.txt` 하나를 낸다 — 패키지마다 「이름 판 — 라이선스 [조각]」 한 줄, 전문이 같은 패키지는 묶어 전문을 한 번만. 서버는 `/licenses.txt`(`text/plain; charset=utf-8`), 앱은 번들에 든 것을 연다. 웹은 서비스 워커가 지연 자산 목록으로 받아 두어 **한 번도 열지 않았어도** 오프라인에서 열린다(데이터 절약 모드면 받지 않고 열 때 받은 것만 남는다). 첫 로드 번들에는 들어가지 않는다(따로 받는 파일).
- **범위**: 서버·웹 빌드는 web 번들 + 서버 실행 의존성, 앱 빌드는 web 번들 + Rust 크레이트. 손 목록으로 `emojibase-data` 와 Unicode CLDR(이모지 이름·낱말의 출처, Unicode License V3), 다른 패키지 안에 묶여 실린 것(「bundled in <패키지> <판>」 — `@mermaid-js/parser` 안의 langium·chevrotain 류, `mermaid` 안의 js-yaml, `pdfjs-dist` 안의 core-js, `roughjs` 안의 하위 패키지 넷, 서버의 Skia·pdf.js).
- **라이선스 판단**: `dompurify` 는 `(MPL-2.0 OR Apache-2.0)` 중 Apache-2.0 을 고른 것으로 적는다. MPL-2.0 크레이트(cssparser·cssparser-macros·dtoa-short·selectors·option-ext, Tauri 내부 의존)는 MPL 전문과 크레이트별 소스 주소를 싣는다. 라이선스 파일을 싣지 않은 패키지는 SPDX 표준 전문에 메타데이터의 저작권자를 넣어 붙인다. 그중 objc2 계열 `Zlib OR Apache-2.0 OR MIT` 7개는 Apache-2.0 을 고른 것으로 적고, MIT 단독 `objc2-foundation` 은 원저장소 LICENSE 의 저작권자를 손으로 넣는다.
- **글**: 고지 파일은 영어다(라이선스 전문이 영어이고 화면 언어를 따르지 않는다). 설정 줄·모달 제목은 화면 글(`settings.licenses`·`settings.licensesHint`·`licenses.failed`).

**한계**:

## 설치한 웹 앱의 오프라인 보기 (2026-10-29)

### 설치한 PWA 는 로컬 모드로, 저장소 보존, 오프라인 검색 문구

사용자는 PWA 와 안드로이드 앱 중 PWA 를 먼저 하기로 했다(「pwa 먼저 진행해줘」, 질문 없이 진행). 아래 값·동작은 **코디네이터·워커가 정한 기본값이고 사용자가 고른 값이 아니다.**

**문제(코디네이터가 안드로이드 17 에뮬레이터 Chrome 에서 서버를 끄고 콜드 스타트로 잰 것)**: 서버 모드는 한 번 연 노트만 오프라인에서 열리고 안 연 노트는 「서버에 연결할 수 없습니다」, 검색은 연 노트의 낱말로도 「결과 없음」. `?local` 은 동기화로 볼트 전체가 내려와 안 연 노트도 열렸다. `navigator.storage.persisted()` 는 false 이고 `persist()` 를 부르는 곳이 없었다.

**정함·구현**:
- **모드 판정**(`web/src/local/mode.ts` `startsLocal`, 읽기는 `boot.ts` `wantsLocal`): 앱(Tauri)은 늘 로컬. 고른 것(주소 `?local`·`?local=0` > 기억 `keyring:mode`)이 설치 여부와 상관없이 이긴다. 고른 적 없고 `matchMedia("(display-mode: standalone)")` 가 맞으면 로컬. 단 서버 모드 대기열(`keyring-offline` 의 `outbox`)에 남은 것이 있으면(못 읽어도) 이번 실행은 서버 모드 — 로컬 볼트는 그 대기열을 보내지 않는다. 비면 다음 실행부터 로컬. 자동으로 정한 것은 기억하지 않는다(브라우저 탭으로 열면 그대로 서버 모드).
- **「서버 모드 선택」 기억**: `?local=0` 은 기억을 지우던 것을 `keyring:mode=server` 로 남기게 바꿨다. 그래야 설치한 앱의 자동 로컬 시작이 그 선택을 덮지 않는다. 모르는 값은 고르지 않은 것으로 본다.
- **동기화 연결을 바로 보이기**: 브라우저 로컬 볼트가 동기화 없이(`keyring:sync` 없음) 열리면, 렌더 전에 주소를 `#/:settings/device` 로 바꿔(`main.tsx`, 판정은 `mode.ts` `needsSyncSetup`) 기존의 「주소로 설정 열기」 길(`Workspace.tsx` `settingsFromLocation`)을 탄다. 새 모달·새 상태를 만들지 않았다. 서버 주소 칸은 `location.origin`, 기기 이름은 기본값(`defaultDeviceName`)으로 채운다 — 비밀번호만 넣으면 된다. 연결할 때까지 **실행마다** 연다(`?local` 로 직접 고른 사람도). 노트 하나만 띄운 창(`?solo`)은 열지 않는다. **주소가 노트여도 연다**(2회차, 코디네이터 판단) — 연결 전의 빈 볼트에서 그 노트는 「없음」으로 열리고, 설치 아이콘이 설치 때 주소(노트)로 시작하기도 한다. 원래 노트는 바꾼 주소의 `history.state`(`{ back }`, `mode.ts` `syncSetupState`)에 남기고, 설정을 닫을 때 연 노트가 없으면 그 노트를 연다(`Workspace.tsx` `closeSettings`, `settingsBack`). 설정 안에서 묶음을 바꿔도(`openSettings`·`SettingsModal` 의 `onSection`) state 는 그대로 둔다. 연결하지 않고 닫으면 그 노트가 아직 없어 「노트 없음」 알림과 함께 홈으로 간다.
- **저장소 보존**(`web/src/persist.ts`): 브라우저 로컬 모드 시작(`startLocal`)과 서버 모드 대기열에 넣을 때(`offline.queue`) `navigator.storage.persist()` 를 부른다. 페이지 로드마다 많아야 한 번, 이미 `persisted()` 면 부르지 않는다, API 가 없거나 실패하면 null 로 조용히 넘긴다. 설정 「이 기기·동기화」 의 「이 기기의 볼트」 아래에 보존되면 한 줄(`sync.persisted`), 아니면 경고 색 한 줄(`sync.notPersisted`). 모르면(API 없음) 보이지 않는다.
- **서버 모드 오프라인 검색**: 검색이 `isNetworkError` 로 실패하면 결과 칸에 「결과 없음」 대신 `search.offline`(「서버에 연결되어 있지 않아 검색할 수 없습니다」) 을 보이고 오류 알림은 띄우지 않는다. 로컬 모드는 해당 없다.
